История коммитов — это летопись проекта, содержащая все изменения с момента создания репозитория. Git предоставляет мощные инструменты для просмотра истории и навигации между состояниями проекта.

### Просмотр истории — git log

Команда `git log` отображает список коммитов в обратном хронологическом порядке — от новых к старым.

```sql
$ git log
commit a5f3b8c7d9e2f1a4b6c8d0e3f5a7b9c1d3e5f7a9
Author: Ivan Petrov <ivan@example.com>
Date:   Mon Mar 15 10:30:00 2024 +0300

    Add user authentication feature

commit b7d9e2a1c4f6b8d0e3a5c7f9b1d3e5a7c9f1b3d5
Author: Anna Smirnova <anna@example.com>
Date:   Sun Mar 14 15:45:00 2024 +0300

    Initial project structure
```

Каждая запись содержит:

- SHA-1 хеш коммита — уникальный идентификатор
- Автора и email
- Дату и время создания
- Сообщение коммита

#### Форматы вывода

Git предоставляет множество опций для настройки вывода истории:

```sql
# Компактный вывод — одна строка на коммит
$ git log --oneline
a5f3b8c Add user authentication feature
b7d9e2a Initial project structure

# Показать граф веток
$ git log --graph --oneline
* a5f3b8c Add user authentication feature
* b7d9e2a Initial project structure

# Подробная статистика изменений
$ git log --stat
commit a5f3b8c7d9e2f1a4b6c8d0e3f5a7b9c1d3e5f7a9
Author: Ivan Petrov <ivan@example.com>
Date:   Mon Mar 15 10:30:00 2024 +0300

    Add user authentication feature

 src/auth.js      | 45 +++++++++++++++++++++++++++++++++
 src/auth.test.js | 23 +++++++++++++++++
 2 files changed, 68 insertions(+)

# Показать изменения в каждом коммите
$ git log -p
```

#### Фильтрация истории

Для работы с большими проектами важна возможность фильтровать историю:

```shell
# Последние N коммитов
$ git log -3

# Коммиты за период времени
$ git log --since="2 weeks ago"
$ git log --since="2024-03-01" --until="2024-03-15"

# Коммиты конкретного автора
$ git log --author="Ivan"

# Коммиты с поиском в сообщении
$ git log --grep="fix"

# Коммиты, изменившие конкретный файл
$ git log -- README.md

# Коммиты, изменившие конкретную функцию
$ git log -L :functionName:filename.js
```

#### Настройка формата вывода

Формат вывода можно настроить под конкретные задачи:

```perl
# Пользовательский формат
$ git log --pretty=format:"%h - %an, %ar : %s"
a5f3b8c - Ivan Petrov, 2 hours ago : Add user authentication feature
b7d9e2a - Anna Smirnova, 1 day ago : Initial project structure

# Полезные плейсхолдеры:
# %h - сокращённый хеш
# %H - полный хеш
# %an - имя автора
# %ae - email автора
# %ad - дата (формат зависит от --date=)
# %ar - относительная дата
# %s - тема (первая строка сообщения)
# %b - тело сообщения
```

### Навигация по истории

Git использует систему ссылок для навигации по коммитам. Понимание этой системы критически важно для эффективной работы.

#### Ссылки на коммиты

Существует несколько способов сослаться на коммит:

- **SHA-1 хеш** — полный (40 символов) или сокращённый (минимум 4)
- **Имя ветки** — указывает на последний коммит ветки
- **HEAD** — указывает на текущий коммит
- **Тег** — именованная ссылка на коммит

#### Относительные ссылки

Git поддерживает относительную навигацию от любой ссылки:

```bash
# Родительские коммиты
HEAD~   или HEAD~1   # Один коммит назад
HEAD~2               # Два коммита назад
HEAD~3               # Три коммита назад

# Для коммитов слияния
HEAD^   или HEAD^1   # Первый родитель
HEAD^2               # Второй родитель (при слиянии)

# Комбинирование
HEAD~2^2            # Второй родитель коммита два шага назад
master~3            # Три коммита назад от master
```

Схема навигации:

```css
A ← B ← C ← D ← E (HEAD)
            ↑   ↑
         HEAD~2 HEAD~1
```

### Просмотр конкретного коммита — git show

Команда `git show` отображает подробную информацию о конкретном коммите:

```diff
$ git show a5f3b8c
commit a5f3b8c7d9e2f1a4b6c8d0e3f5a7b9c1d3e5f7a9
Author: Ivan Petrov <ivan@example.com>
Date:   Mon Mar 15 10:30:00 2024 +0300

    Add user authentication feature

diff --git a/src/auth.js b/src/auth.js
new file mode 100644
index 0000000..45f3c2a
--- /dev/null
+++ b/src/auth.js
@@ -0,0 +1,15 @@
+function authenticate(username, password) {
+    // Authentication logic
+    return true;
+}
```

Варианты использования:

```shell
# Показать последний коммит
$ git show

# Показать конкретный коммит
$ git show a5f3b8c

# Показать коммит три шага назад
$ git show HEAD~3

# Показать только статистику без изменений
$ git show --stat

# Показать только имена изменённых файлов
$ git show --name-only
```

### Поиск в истории

Git предоставляет инструменты для поиска конкретных изменений в истории:

```shell
# Найти коммит, добавивший или удаливший строку
$ git log -S "function authenticate"

# Найти коммит с изменением количества вхождений
$ git log -G "authenticate.*password"

# Показать кто и когда изменял каждую строку файла
$ git blame filename.js
```

### Визуализация истории

Для сложных историй с множеством веток полезна визуализация:

```sql
# Простой граф
$ git log --graph --oneline --all
* a5f3b8c (HEAD -> main) Add user authentication
| * d3e4f5a (feature) Add experimental feature
|/
* b7d9e2a Initial project structure

# Расширенный граф с датами
$ git log --graph --pretty=format:'%h -%d %s (%cr) <%an>' --all
* a5f3b8c - (HEAD -> main) Add user authentication (2 hours ago) <Ivan Petrov>
| * d3e4f5a - (feature) Add experimental feature (1 hour ago) <Anna Smirnova>
|/
* b7d9e2a - Initial project structure (1 day ago) <Anna Smirnova>
```

### Сравнение коммитов

Для анализа изменений между коммитами используется уже знакомая команда `git diff`:

```ruby
# Изменения между двумя коммитами
$ git diff HEAD~2 HEAD

# Изменения между коммитом и текущим состоянием
$ git diff a5f3b8c

# Только имена изменённых файлов
$ git diff --name-only HEAD~5 HEAD
```

### Практические сценарии

Типичные задачи при работе с историей:

**Поиск причины ошибки** — просмотр истории изменений конкретного файла или функции помогает найти коммит, внёсший проблему.

**Анализ развития проекта** — статистика по авторам, частоте коммитов и изменённым файлам даёт представление о динамике разработки.

**Подготовка релиза** — просмотр изменений с последнего релиза помогает составить список нововведений.

```shell
# Что изменилось с последнего тега
$ git log v1.0..HEAD --oneline

# Кто больше всего вносил изменений
$ git shortlog -sn

# Активность по дням недели
$ git log --format="%ad" --date=format:"%A" | sort | uniq -c
```

## Итог

Просмотр истории и навигация по коммитам — фундаментальные операции в Git. Команда `git log` с её многочисленными опциями позволяет анализировать историю проекта под разными углами. Система относительных ссылок обеспечивает удобную навигацию по коммитам. `git show` предоставляет детальную информацию о конкретных изменениях. Владение этими инструментами превращает историю из набора коммитов в мощный инструмент анализа и понимания эволюции проекта.
