## Работа с Git начинается с создания репозитория. 

### Два способа получить репозиторий

Существует два основных подхода к созданию Git-репозитория, выбор зависит от ситуации.

#### Инициализация нового репозитория

Когда начинается новый проект или нужно добавить контроль версий к существующему проекту, используется инициализация. Команда `git init` создаёт в текущей директории служебную папку `.git`, которая содержит всю инфраструктуру для работы Git.

После инициализации создаётся следующая структура:

```cmake
project/
├── .git/          # Служебная директория Git
│   ├── HEAD       # Указатель на текущую ветку
│   ├── config     # Конфигурация репозитория
│   ├── objects/   # База данных объектов
│   └── refs/      # Ссылки на коммиты
└── ... файлы проекта ...
```

Важно понимать: инициализация создаёт пустой репозиторий. Файлы проекта ещё не находятся под контролем версий, их нужно будет явно добавить.

#### Клонирование существующего репозитория

Когда нужно получить копию существующего проекта (например, с GitHub), используется клонирование. Команда `git clone` загружает полную историю проекта и создаёт рабочую копию.

При клонировании происходит следующее:

- Создаётся новая директория с именем проекта
- Инициализируется Git-репозиторий внутри неё
- Загружается вся история коммитов
- Создаётся рабочая копия последней версии файлов

Git поддерживает различные протоколы для клонирования: HTTPS (самый распространённый), SSH (требует настройки ключей), Git-протокол и локальные пути.

### Базовая конфигурация

Перед началом работы Git необходимо сообщить, кто является автором изменений. Устанавливаются имя и email:

```csharp
git config --global user.name "Имя Фамилия"
git config --global user.email "email@example.com"
```

Эта информация будет включена в каждый коммит. Параметр `--global` устанавливает настройки для всех репозиториев пользователя в системе.

### Концепция рабочего процесса

Работа с Git следует определённому циклу, который повторяется при каждом изменении проекта. Понимание этого цикла критически важно для эффективной работы.

#### Три состояния

Git оперирует тремя основными областями, через которые проходят изменения:

- **Рабочая директория** — здесь происходит непосредственная работа с файлами
- **Область подготовки (индекс)** — промежуточная область для формирования коммита
- **Репозиторий** — постоянное хранилище зафиксированных изменений

Изменения перемещаются между этими областями с помощью команд Git.

#### Жизненный цикл файлов

Каждый файл в рабочей директории может находиться в одном из состояний:

- **Неотслеживаемый (Untracked)** — Git не знает об этом файле
- **Отслеживаемый неизменённый (Unmodified)** — файл под контролем версий, не изменялся с последнего коммита
- **Изменённый (Modified)** — файл был изменён после последнего коммита
- **Подготовленный (Staged)** — изменения подготовлены для включения в следующий коммит

```1c
Жизненный цикл файла:

Неотслеживаемый → Добавление → Подготовленный
                                      ↓
Неизменённый ← Фиксация (коммит) ←────┘
      ↓
Изменённый → Подготовка → Подготовленный
```

#### Типичный рабочий процесс

Стандартный цикл работы выглядит следующим образом:

1. **Внесение изменений** — редактирование файлов в рабочей директории
2. **Просмотр состояния** — проверка, какие файлы изменены
3. **Подготовка изменений** — выбор файлов для включения в коммит
4. **Фиксация изменений** — создание коммита с описанием
5. **Повторение цикла** — возврат к пункту 1

Этот процесс позволяет создавать логически связанные коммиты, группируя связанные изменения вместе.

### Структура Git-репозитория

После создания репозитория полезно понимать его внутреннюю структуру. Основные компоненты директории `.git`:

- **objects/** — база данных всех объектов (файлов, коммитов, деревьев)
- **refs/** — ссылки на объекты коммитов (ветки, теги)
- **HEAD** — указатель на текущую ветку
- **index** — информация об области подготовки
- **config** — конфигурация репозитория
- **hooks/** — скрипты для автоматизации

Прямое редактирование файлов в `.git` не рекомендуется — Git предоставляет команды для всех необходимых операций.

### Первые шаги после создания репозитория

После создания репозитория типичные первые действия включают:

- Создание файла README с описанием проекта
- Добавление файла .gitignore для исключения ненужных файлов
- Создание первого коммита с начальной структурой проекта
- Настройка удалённого репозитория (при необходимости)

Эти действия формируют основу для дальнейшей работы над проектом.

## Итог

Создание репозитория — отправная точка работы с Git. Новый репозиторий создаётся через инициализацию, существующий получается через клонирование. Понимание рабочего процесса Git — движения изменений через три области и жизненного цикла файлов — формирует основу для эффективной работы. В следующих уроках будут детально рассмотрены команды для реализации этого процесса.
