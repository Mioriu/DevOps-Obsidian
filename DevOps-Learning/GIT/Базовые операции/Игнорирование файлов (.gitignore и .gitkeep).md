В любом проекте существуют файлы, которые не должны попадать в систему контроля версий: временные файлы, результаты компиляции, локальные настройки, секретные данные. Git предоставляет механизм для исключения таких файлов из отслеживания.

### Зачем игнорировать файлы

Существует несколько категорий файлов, которые не следует включать в репозиторий:

- **Результаты сборки и компиляции** — файлы, генерируемые из исходного кода (бинарные файлы, минифицированный код)
- **Зависимости** — внешние библиотеки, устанавливаемые менеджерами пакетов (node_modules, vendor)
- **Временные файлы** — кэш, логи, файлы редакторов (.swp, .tmp)
- **Локальная конфигурация** — настройки среды разработки, специфичные для каждого разработчика
- **Конфиденциальные данные** — пароли, ключи API, сертификаты

Включение таких файлов в репозиторий приводит к раздуванию размера, конфликтам при слиянии и потенциальным проблемам безопасности.

### Файл .gitignore

Файл `.gitignore` содержит шаблоны имён файлов и директорий, которые Git должен игнорировать. Этот файл обычно размещается в корне репозитория, но может находиться в любой поддиректории.

```applescript
# Пример .gitignore для Node.js проекта
# Зависимости
node_modules/
npm-debug.log*

# Результаты сборки
dist/
build/
*.min.js
*.min.css

# Временные файлы
*.tmp
*.swp
.DS_Store

# Локальные настройки
.env
.env.local
config/local.json

# IDE
.vscode/
.idea/
*.sublime-workspace
```

#### Синтаксис шаблонов

Git использует упрощённый синтаксис glob-шаблонов для определения игнорируемых файлов:

```1c
# Комментарий - строки, начинающиеся с #, игнорируются

# Игнорировать все файлы с расширением .log
*.log

# Игнорировать все файлы в директории build
build/

# Игнорировать файл TODO в корне репозитория, но не subdir/TODO
/TODO

# Игнорировать все файлы в любой директории temp
**/temp

# Игнорировать doc/notes.txt, но не doc/server/notes.txt
doc/*.txt

# Игнорировать все .pdf файлы в директории doc/ и её поддиректориях
doc/**/*.pdf

# НЕ игнорировать файл important.log, даже если *.log игнорируется
!important.log
```

Основные правила синтаксиса:

- `*` — соответствует любому количеству символов (кроме /)
- `?` — соответствует одному символу
- `[abc]` — соответствует любому символу из набора
- `**` — соответствует вложенным директориям
- `/` в начале — привязка к корню репозитория
- `/` в конце — указание на директорию
- `!` в начале — отмена игнорирования

### Работа с .gitignore

#### Создание и применение

Файл `.gitignore` создаётся как обычный текстовый файл и должен быть добавлен в репозиторий:

```shell
$ echo "node_modules/" > .gitignore
$ echo "*.log" >> .gitignore
$ git add .gitignore
$ git commit -m "Add .gitignore"
```

После создания `.gitignore` новые файлы, соответствующие шаблонам, не будут отображаться в `git status` как неотслеживаемые.

#### Важное замечание

Файл `.gitignore` влияет только на неотслеживаемые файлы. Если файл уже добавлен в репозиторий, добавление его в `.gitignore` не приведёт к его удалению из Git. Необходимо явно удалить файл из индекса:

```shell
# Удалить файл из репозитория, но оставить в рабочей директории
$ git rm --cached filename.log
$ git commit -m "Remove accidentally committed log file"

# Для директории
$ git rm -r --cached node_modules/
$ git commit -m "Remove node_modules from tracking"
```

### Множественные файлы .gitignore

В проекте может быть несколько файлов `.gitignore`:

```1c
project/
├── .gitignore          # Глобальные правила проекта
├── src/
│   └── .gitignore      # Правила для src/
└── tests/
    └── .gitignore      # Правила для tests/
```

Правила применяются к директории, содержащей `.gitignore`, и всем её поддиректориям. Более специфичные правила имеют приоритет над общими.

### Глобальный .gitignore

Для файлов, которые следует игнорировать во всех проектах (например, файлы операционной системы или IDE), используется глобальный `.gitignore`:

```shell
# Настройка глобального .gitignore
$ git config --global core.excludesfile ~/.gitignore_global

# Создание файла
$ echo ".DS_Store" > ~/.gitignore_global
$ echo "Thumbs.db" >> ~/.gitignore_global
$ echo "*.swp" >> ~/.gitignore_global
```

Глобальные правила применяются ко всем репозиториям пользователя, но не влияют на других разработчиков проекта.

### Сохранение пустых директорий — .gitkeep

Git не отслеживает пустые директории. Если структура директорий важна для проекта, используется соглашение о создании пустого файла `.gitkeep`:

```cmake
project/
├── src/
├── logs/
│   └── .gitkeep    # Сохраняет директорию logs/ в репозитории
├── temp/
│   └── .gitkeep    # Сохраняет директорию temp/
└── uploads/
    └── .gitkeep    # Сохраняет директорию uploads/
```

Создание структуры с пустыми директориями:

```shell
$ mkdir -p logs temp uploads
$ touch logs/.gitkeep temp/.gitkeep uploads/.gitkeep
$ git add .
$ git commit -m "Add directory structure"
```

Имя `.gitkeep` — это соглашение, не специальный файл Git. Можно использовать любое имя (`.keep`, `README.md`), но `.gitkeep` стал стандартом де-факто.

### Проверка игнорируемых файлов

Git предоставляет команды для проверки, какие файлы игнорируются:

```applescript
# Проверить, игнорируется ли конкретный файл
$ git check-ignore -v filename.log
.gitignore:3:*.log    filename.log

# Показать все игнорируемые файлы в директории
$ git status --ignored

# Показать все игнорируемые файлы с деталями
$ git status --ignored -v
```

### Лучшие практики

При работе с игнорированием файлов рекомендуется следовать нескольким принципам:

**Добавлять .gitignore в начале проекта** — это предотвратит случайное добавление нежелательных файлов.

**Использовать шаблоны из gitignore.io** — сервис предоставляет готовые шаблоны для различных языков и сред разработки.

**Документировать нестандартные правила** — если правило неочевидно, добавить комментарий с объяснением.

**Не игнорировать важные файлы** — файлы, необходимые для сборки проекта, должны быть в репозитории.

## Итог

Механизм игнорирования файлов — важная часть работы с Git. Файл `.gitignore` определяет, какие файлы и директории не должны попадать под контроль версий. Правильная настройка игнорирования сохраняет репозиторий чистым, уменьшает его размер и предотвращает утечку конфиденциальной информации. Соглашение `.gitkeep` позволяет сохранять важную структуру директорий. Понимание синтаксиса шаблонов и лучших практик обеспечивает эффективное управление содержимым репозитория.
