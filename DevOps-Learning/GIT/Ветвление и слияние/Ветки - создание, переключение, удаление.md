Ветвление — одна из ключевых возможностей Git, позволяющая вести параллельную разработку различных функций. Механизм веток в Git отличается от других систем контроля версий своей простотой и эффективностью.

### Концепция веток в Git

Ветка в Git — это подвижный указатель на определённый коммит. Это принципиально отличается от подхода других систем, где создание ветки означает копирование файлов проекта. В Git создание ветки — это создание файла размером 41 байт, содержащего SHA-1 хеш коммита.

При работе в ветке и создании новых коммитов указатель ветки автоматически перемещается вперёд, всегда указывая на последний коммит. Это обеспечивает естественное развитие независимых линий разработки.

Важное следствие такой архитектуры — операции с ветками выполняются мгновенно независимо от размера проекта. Создание, переключение и удаление веток занимает доли секунды даже в репозиториях с миллионами строк кода и десятилетней историей.

### Создание веток

Git предоставляет несколько способов создания веток. Базовая команда `git branch` создаёт новую ветку, но не переключается на неё:

```ruby
$ git branch feature-login
```

После выполнения этой команды создаётся новый указатель на текущий коммит. HEAD остаётся на прежней ветке, рабочая директория не изменяется. Такой подход полезен, когда нужно создать ветку для будущей работы, но продолжить текущую задачу.

Чаще требуется создать ветку и сразу переключиться на неё. Современный Git (версии 2.23 и выше) предлагает интуитивную команду `git switch` с флагом создания:

```r
$ git switch -c feature-login
```

Классический способ, который встречается в большинстве документации и до сих пор широко используется — команда `git checkout` с флагом `-b`. Эта команда выполняет те же действия: создаёт ветку и переключается на неё.

При именовании веток важно следовать принятым в команде соглашениям. Распространённая практика — использование префиксов, указывающих на тип работы: feature/ для новой функциональности, bugfix/ для исправлений, hotfix/ для срочных правок, release/ для подготовки релизов. Такая система именования упрощает навигацию в проекте с десятками активных веток.

### Переключение между ветками

Переключение веток — фундаментальная операция, изменяющая состояние рабочей директории. При переключении Git выполняет три действия: перемещает HEAD на новую ветку, обновляет индекс и изменяет файлы в рабочей директории в соответствии с выбранной веткой.

Команда `git switch` — современный способ переключения, введённый для разделения функциональности перегруженной команды `git checkout`:

```cpp
$ git switch main
```

Важный момент — Git защищает от потери несохранённых изменений. При попытке переключиться на другую ветку с незафиксированными изменениями, которые конфликтуют с целевой веткой, Git выдаст предупреждение и откажется выполнять операцию. Это предотвращает случайную потерю работы.

В такой ситуации есть несколько вариантов действий. Можно зафиксировать изменения коммитом, временно сохранить их командой `git stash`, или отменить изменения, если они больше не нужны. Каждый подход имеет свои сценарии применения.

Полезная возможность — переключение на предыдущую ветку с помощью дефиса. Команда `git switch -` вернёт на ветку, в которой происходила работа до текущей. Это удобно при частом переключении между двумя ветками.

### Просмотр информации о ветках

Команда `git branch` без параметров показывает список локальных веток с выделением текущей звёздочкой. Для более детальной информации используются различные флаги.

```sql
$ git branch -v
  develop       a5f3b8c Add API endpoints
  feature-login b7d9e2a Implement login form
* main          c1d2e3f Update documentation
```

Флаг `-v` добавляет к списку веток последний коммит каждой ветки. Это помогает понять актуальное состояние работы в разных направлениях разработки.

Особенно полезны флаги `--merged` и `--no-merged`, показывающие ветки относительно их статуса слияния с текущей веткой. Это критически важно при очистке репозитория от устаревших веток — безопасно удалять можно только слитые ветки, иначе есть риск потерять несохранённую работу.

Для просмотра удалённых веток используется флаг `-a`, показывающий как локальные, так и удалённые ветки. Удалённые ветки отображаются с префиксом remotes/ и представляют состояние веток в удалённом репозитории на момент последней синхронизации.

### Удаление веток

После завершения работы над функциональностью и успешного слияния изменений, ветка становится ненужной. Поддержание чистоты репозитория требует регулярного удаления отработавших веток.

Git предоставляет защиту от случайного удаления важных данных. Команда `git branch -d` удаляет ветку только если она полностью слита с текущей веткой или upstream-веткой:

```erlang
$ git branch -d feature-login
Deleted branch feature-login (was a5f3b8c).
```

Если ветка содержит уникальные коммиты, Git откажется её удалять, предупреждая о возможной потере данных. В случаях, когда удаление действительно необходимо (например, отказ от экспериментальной функциональности), используется флаг принудительного удаления `-D`.

Удаление веток в удалённом репозитории выполняется через команду push со специальным синтаксисом. После удаления удалённой ветки полезно выполнить очистку локальных ссылок командой `git remote prune`, которая удалит устаревшие ссылки на несуществующие удалённые ветки.

### Практические аспекты работы с ветками

Эффективная работа с ветками основывается на понимании нескольких ключевых принципов. Ветки должны создаваться для логически обособленных задач — новой функциональности, исправления конкретного бага, подготовки релиза. Это упрощает code review и потенциальный откат изменений.

Важно поддерживать актуальность веток относительно основной линии разработки. Долгоживущие ветки накапливают конфликты и усложняют интеграцию. Регулярная синхронизация с основной веткой через merge или rebase минимизирует проблемы при финальном слиянии.

Визуализация структуры веток помогает понимать текущее состояние проекта. Команда `git log` с флагами `--graph` и `--oneline` создаёт наглядное представление истории веток, показывая точки расхождения и слияния.

При работе в команде критически важна связь локальных веток с удалёнными. Установка upstream-связи позволяет Git отслеживать расхождения между локальной и удалённой версиями ветки, упрощая синхронизацию изменений.

## Итог

Механизм веток в Git обеспечивает гибкую и эффективную модель параллельной разработки. Простота создания и переключения веток поощряет экспериментирование и изоляцию изменений. Правильное использование веток — с осмысленными именами, регулярной очисткой и поддержанием актуальности — формирует основу продуктивного рабочего процесса. В следующих уроках будет рассмотрено слияние веток и разрешение неизбежно возникающих конфликтов.
