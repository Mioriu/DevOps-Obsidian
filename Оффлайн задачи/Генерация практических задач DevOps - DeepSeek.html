1. Docker-образы

Все образы нужно скачать командой docker pull:

bash
# Базовые образы
docker pull alpine:latest
docker pull alpine:3.19
docker pull busybox:latest
docker pull ubuntu:22.04

# Веб-серверы и базы данных
docker pull nginx:alpine
docker pull redis:alpine
docker pull mysql:8
docker pull postgres:15

# Для сборки (Задачи 10, 19)
docker pull python:3.10-slim
docker pull gcc:alpine

# Для стресс-тестов (Задача 22)
docker pull polinux/stress

Одной командой:

bash
for img in alpine:latest alpine:3.19 busybox:latest ubuntu:22.04 nginx:alpine redis:alpine mysql:8 postgres:15 python:3.10-slim gcc:alpine polinux/stress; do
    docker pull $img
done

4. Утилиты внутри Docker-контейнеров

Некоторые задачи требуют установки пакетов внутри контейнеров. Так как интернета не будет, нужно либо скачать эти пакеты заранее и пробросить в контейнер, либо использовать образы, где они уже есть.

Для Alpine-контейнеров (apk)

В задачах используются:

  • redis (клиент) — Задача 6

  • tcpdump — Задача 17

  • curl — разные задачи

Решение: Создай свой кастомный образ на основе alpine со всем необходимым:

dockerfile
# Dockerfile.custom-alpine
FROM alpine:latest
RUN apk add --no-cache \
    redis \
    tcpdump \
    curl \
    bash \
    vim \
    net-tools

Собери заранее:

bash
docker build -t my-alpine:latest -f Dockerfile.custom-alpine .

И используй my-alpine:latest вместо alpine:latest в задачах 6, 17 и других.

Для BusyBox

BusyBox — минималистичный образ, пакетов там практически нет. Для задачи 22 (стресс-тест) лучше использовать polinux/stress (уже есть в списке образов) или alpine с установленным stress.

7. Рекомендации для полностью офлайн-работы

  1. Скачай все образы и сохрани их в tar-архивы (если будешь переносить на другую машину):

    bash
    docker save alpine:latest nginx:alpine redis:alpine mysql:8 postgres:15 python:3.10-slim gcc:alpine polinux/stress busybox:latest -o ~/docker-images.tar

    Потом загрузить:

    bash
    docker load -i ~/docker-images.tar

  2. Для APT-пакетов можно скачать .deb-файлы с зависимостями:

    bash
    apt download nginx redis-tools tcpdump iotop sysstat lsof
# Установка:
sudo dpkg -i *.deb

  3. Проверь всё до отключения от сети:

    bash
    docker run --rm alpine:latest echo "OK"
docker run --rm nginx:alpine nginx -v
sudo nginx -t
which redis-cli tcpdump iostat iotop lsof

Быстрая проверка готовности

Запусти этот скрипт перед уходом в офлайн — он проверит, всё ли доступно:

bash
#!/bin/bash
echo "=== Проверка Docker-образов ==="
IMAGES=("alpine:latest" "busybox:latest" "nginx:alpine" "redis:alpine" "mysql:8" "postgres:15" "python:3.10-slim" "gcc:alpine" "polinux/stress")
for img in "${IMAGES[@]}"; do
    if docker image inspect "$img" &>/dev/null; then
        echo "✓ $img"
    else
        echo "✗ $img — НЕ НАЙДЕН!"
    fi
done

echo -e "\n=== Проверка системных утилит ==="
CMDS=("nginx" "redis-cli" "tcpdump" "iostat" "iotop" "lsof" "gcc" "python3" "ss" "find" "awk" "sort" "tar")
for cmd in "${CMDS[@]}"; do
    if command -v "$cmd" &>/dev/null; then
        echo "✓ $cmd"
    else
        echo "✗ $cmd — НЕ НАЙДЕН!"
    fi
done

Сохрани как check_env.sh, выполни chmod +x check_env.sh && ./check_env.sh. Если все галочки — ты полностью готов к офлайн-практике.

Всё ок кроме docker pull gcc:alpine Error response from daemon: manifest for gcc:alpine not found: manifest unknown: manifest unknown

Верно, официального образа gcc:alpine не существует. Вот несколько вариантов замены для задачи 19 (сборка статического бинарника из C-кода).

Варианты замены

Вариант 1: Использовать gcc:latest (самый простой)

Образ основан на Debian, статическая компиляция работает из коробки:

bash
docker pull gcc:latest

В Dockerfile заменить:

dockerfile
FROM gcc:latest AS builder

Минус: образ большой (~1.2 ГБ), но для офлайн-работы это некритично.

Вариант 2: Использовать alpine и установить gcc вручную (компактнее)

Создай свой образ для компиляции на основе Alpine:

bash
docker pull alpine:latest

Dockerfile.gcc-alpine:

dockerfile
FROM alpine:latest
RUN apk add --no-cache gcc musl-dev

Собери:

bash
docker build -t my-gcc-alpine -f Dockerfile.gcc-alpine .

В основной задаче Dockerfile будет:

dockerfile
FROM my-gcc-alpine AS builder

Вариант 3: Использовать python:3.10-slim (раз уж он всё равно скачан)

В python:3.10-slim (основан на Debian) можно доустановить gcc. Но проще использовать варианты выше.

Вариант 4: Изменить задачу — использовать Go вместо C

Go умеет компилировать статические бинарники, и для него есть Alpine-образ:

bash
docker pull golang:alpine

Но это меняет суть задачи.

Исправленный список образов для загрузки

Замени строку docker pull gcc:alpine на одну из этих:

bash
# Вариант 1 — самый простой
docker pull gcc:latest

# ИЛИ Вариант 2 — компактный (нужно будет собрать my-gcc-alpine)
docker pull alpine:latest
# Потом собрать Dockerfile.gcc-alpine (см. выше)

Обновлённый Dockerfile для задачи 19 (с gcc:latest)

dockerfile
# Этап 1: Компиляция
FROM gcc:latest AS builder
COPY hello.c /src/
WORKDIR /src
RUN gcc -static -o hello hello.c

# Этап 2: Финальный образ
FROM scratch
COPY --from=builder /src/hello /hello
CMD ["/hello"]

Собирается точно так же:

bash
docker build -t hello-scratch .
docker run --rm hello-scratch
