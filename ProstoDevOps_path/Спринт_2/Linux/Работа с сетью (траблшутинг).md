## 1. Основные команды для диагностики

### `ss` - посмотреть открытые порты и подключения

Команда `**ss**` — основной инструмент для анализа сетевых подключений.  
**Все слушающие TCP порты:**

ss -tlnp

**Объяснение:**

- `-t` — только TCP
- `-u` — только UDP
- `-l` — только слушающие
- `-n` — показывать номера портов (не резолвить имена)
- `-p` — показывать процессы
- `0.0.0.0:80` — nginx слушает на всех интерфейсах
- `127.0.0.1:8080` — приложение только на localhost

**Все активные подключения:**

ss -tnp

**Полезные комбинации:**

codecopy

```
# UDP портыss -ulnp # Все TCP подключения (listening + established)ss -tanp # Подключения к конкретному портуss -tnp | grep :80
```

### `netstat` - классика

codecopy

```
# Аналог ss -tlnpnetstat -tlnp # Статистика по протоколамnetstat -s # Таблица маршрутизацииnetstat -rn
```

### `lsof`

Команда `**lsof**` — показывает какой процесс использует порт.

codecopy

```
# Что слушает на порту 8080sudo lsof -i :8080
```

**Все сетевые подключения процесса:**

sudo lsof -i -p 9012

### `ping`

Команда `**ping**` — отправляет `ICMP` пакеты и проверяет доступен ли хост.

**Полезные опции:**

codecopy

### Найти процесс который занял порт

**Задача:** Приложение не может запуститься - порт уже занят.

Error: Address already in use: 8080

**Решение:**

codecopy

```
# Найти процессsudo lsof -i :8080
```

**Вывод:**

codecopy

```
COMMAND  PID  USER   FD   TYPE  NODE NAMEjava    5678  user   42u  IPv4  TCP *:8080 (LISTEN)
```

Видишь что процесс `java` с `PID 5678` занял порт.  
**Убить процесс:**

codecopy

```
sudo kill 5678 # Если не помогло - жёсткоsudo kill -9 5678
```

**Или через fuser:**

codecopy

```
# Показать PIDsudo fuser 8080/tcp # Убить сразуsudo fuser -k 8080/tcp
```

## 3. Файрволлы в Linux

### `iptables` - низкоуровневый файрволл

`**iptables**` — система фильтрации пакетов на уровне ядра.  
**Основные цепочки:**

- `INPUT` — входящий трафик
- `OUTPUT` — исходящий трафик
- `FORWARD` — транзитный трафик

**Посмотреть правила:**

sudo iptables -L -n -v

**Базовые правила:**

codecopy

```
# Разрешить SSHsudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT # Разрешить HTTP и HTTPSsudo iptables -A INPUT -p tcp --dport 80 -j ACCEPTsudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT # Разрешить established соединенияsudo iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT # Разрешить loopbacksudo iptables -A INPUT -i lo -j ACCEPT # Заблокировать IPsudo iptables -A INPUT -s 192.168.1.50 -j DROP # Дефолт политика - запретить всё входящееsudo iptables -P INPUT DROP
```

**Удалить правило:**

codecopy

```
# Посмотреть с номерамиsudo iptables -L INPUT --line-numbers # Удалить правило номер 5sudo iptables -D INPUT 5
```

**Сохранить правила:**

codecopy

```
# Ubuntu/Debiansudo apt install iptables-persistentsudo netfilter-persistent save # RHEL/CentOSsudo service iptables save
```

## **Важно:** Без сохранения правила слетят после перезагрузки.

### `firewalld`

`**firewalld**` — высокоуровневая надстройка над `iptables`.  
**Основные концепции:**

- **Зоны** — наборы правил (public, internal, trusted)
- **Сервисы** — предопределённые правила (http, ssh, mysql)

**Посмотреть статус:**

codecopy

```
sudo systemctl status firewalldsudo firewall-cmd --state
```

**Работа с портами:**

codecopy

```
# Открыть портsudo firewall-cmd --add-port=8080/tcp --permanent # Открыть диапазонsudo firewall-cmd --add-port=8000-9000/tcp --permanent # Применить измененияsudo firewall-cmd --reload # Посмотреть открытые портыsudo firewall-cmd --list-ports
```

**Работа с сервисами:**

codecopy

```
# Открыть HTTP и HTTPSsudo firewall-cmd --add-service=http --permanentsudo firewall-cmd --add-service=https --permanent # Посмотреть доступные сервисыsudo firewall-cmd --get-services # Посмотреть открытые сервисыsudo firewall-cmd --list-services
```

**Блокировка IP:**

codecopy

```
# Заблокировать IPsudo firewall-cmd --add-rich-rule='rule family="ipv4" source address="192.168.1.50" reject' --permanent # Разблокироватьsudo firewall-cmd --remove-rich-rule='rule family="ipv4" source address="192.168.1.50" reject' --permanent # Применитьsudo firewall-cmd --reload
```

**Работа с зонами:**

codecopy

```
# Посмотреть активную зонуsudo firewall-cmd --get-active-zones # Посмотреть правила зоныsudo firewall-cmd --zone=public --list-all # Сменить зону интерфейсаsudo firewall-cmd --zone=internal --change-interface=eth1 --permanent
```

### `ufw`

`**ufw**` — самый простой файрволл для Ubuntu.  
**Включить:**

sudo ufw enable

**Базовые правила:**

codecopy

```
# Разрешить SSHsudo ufw allow 22/tcp # Разрешить HTTP и HTTPSsudo ufw allow 80/tcpsudo ufw allow 443/tcp # Разрешить конкретному IP доступ к портуsudo ufw allow from 192.168.1.100 to any port 3306 # Запретить портsudo ufw deny 3306/tcp # Удалить правилоsudo ufw delete allow 80/tcp
```

**Посмотреть правила:**

sudo ufw status numbered

**Вывод:**

codecopy

```
Status: active      To                         Action      From     --                         ------      ----[ 1] 22/tcp                     ALLOW IN    Anywhere[ 2] 80/tcp                     ALLOW IN    Anywhere[ 3] 443/tcp                    ALLOW IN    Anywhere
```

**Удалить правило по номеру:**

sudo ufw delete 2

## 4. Траблшутинг `HTTP` ошибок

### Диагностика `502 Bad Gateway`

**Симптомы:**

curl http://example.com

HTTP/1.1 502 Bad Gateway

**Что означает:** Nginx (или другой прокси) не может подключиться к бэкенду.  
**Проверка:**  
**Шаг 1: Проверить что бэкенд запущен**

codecopy

```
# Проверить процессps aux | grep java# илиsystemctl status myapp # Проверить что слушает на портуss -tlnp | grep :8080
```

**Шаг 2: Проверить доступность порта**

codecopy

```
# С сервера nginxnc -zv localhost 8080
```

Если connection refused — бэкенд не слушает.  
**Шаг 3: Посмотреть логи nginx**

sudo tail -f /var/log/nginx/error.log

Типичная ошибка:

connect() failed (111: Connection refused) while connecting to upstream

**Шаг 4: Проверить firewall**

codecopy

```
# Если nginx на другом сервереsudo firewall-cmd --list-ports
```

Порт `8080` должен быть открыт.  
**Решение:**

1. Запустить бэкенд: `sudo systemctl start myapp`
2. Проверить конфиг nginx - правильный ли upstream
3. Открыть порт в файрволле

### Диагностика `500 Internal Server Error`

**Симптомы:**

curl http://example.com/api/users

HTTP/1.1 500 Internal Server Error

**Что означает:** Ошибка в приложении (код упал).  
**Проверка:**  
**Шаг 1: Посмотреть логи приложения**

codecopy

```
# Логи приложенияsudo tail -f /var/log/myapp/application.log # Если через systemdsudo journalctl -u myapp -f # Логи nginx (там может быть что-то полезное)sudo tail -f /var/log/nginx/error.log
```

**Шаг 2: Проверить подключение к БД**

codecopy

```
# Проверить что БД доступнаnc -zv db-server 5432 # Попробовать подключитьсяpsql -h db-server -U myuser -d mydb
```

**Шаг 3: Проверить ресурсы**

codecopy

```
# CPU и памятьtop # Место на дискеdf -h # Логи не забили диск?du -sh /var/log/*
```

**Типичные причины 500:**

- База данных недоступна
- Закончилось место на диске
- Ошибка в коде (null pointer, и т.д.)
- Закончилась память (OOM killer убил процесс)

### Диагностика `504 Gateway Timeout`

**Симптомы:**  
Запрос висит и возвращает:

HTTP/1.1 504 Gateway Timeout

**Что означает:** Бэкенд не ответил за отведённое время.  
**Проверка:**  
**Шаг 1: Проверить что бэкенд медленный**

codecopy

```
# Прямой запрос к бэкендуtime curl http://localhost:8080/api/slow-endpoint
```

Если висит больше 60 секунд — проблема в приложении.  
**Шаг 2: Посмотреть timeout в nginx**

sudo cat /etc/nginx/nginx.conf | grep timeout

codecopy

```
proxy_read_timeout 60s;proxy_connect_timeout 60s;
```

**Шаг 3: Проверить медленные запросы**

codecopy

```
# Активные подключения к БДsudo -u postgres psql -c "SELECT pid, now() - pg_stat_activity.query_start AS duration, query FROM pg_stat_activity WHERE state = 'active';"
```

**Решение:**

1. Увеличить timeout в nginx если запрос реально долгий
2. Оптимизировать медленный запрос в приложении
3. Добавить индексы в БД

## 5. `SSH` - настройка и безопасность

### Базовая настройка SSH

**Файл конфигурации:** `/etc/ssh/sshd\_config`  
**Важные параметры:**

codecopy

```
# Запретить root логинPermitRootLogin no # Использовать только ключи (запретить пароли)PasswordAuthentication noPubkeyAuthentication yes # Сменить порт (security through obscurity)Port 2222 # Ограничить пользователейAllowUsers deployer admin # Таймаут неактивностиClientAliveInterval 300ClientAliveCountMax 2
```

**Применить изменения:**

sudo systemctl restart sshd

### `SSH` ключи для деплоя

**Создание пользователя для деплоя:**

codecopy

```
# Создать пользователяsudo useradd -m -s /bin/bash deployer # Добавить в группу для sudo (опционально)sudo usermod -aG sudo deployer # Переключиться на пользователяsudo su - deployer
```

**Генерация SSH ключа (на локальной машине):**

ssh-keygen -t ed25519 -C "deploy@myapp"

**Вывод:**

codecopy

```
Generating public/private ed25519 key pair.Enter file in which to save the key (/home/user/.ssh/id_ed25519):Enter passphrase (empty for no passphrase):
```

Создаются два файла:

- `~/.ssh/id\_ed25519` — приватный ключ (никому не показывать)
- `~/.ssh/id\_ed25519.pub` — публичный ключ

**Добавить ключ на сервер:**

codecopy

```
# Способ 1: ssh-copy-idssh-copy-id deployer@server.com # Способ 2: вручнуюcat ~/.ssh/id_ed25519.pub | ssh deployer@server.com "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```

**На сервере проверить права:**

codecopy

```
chmod 700 ~/.sshchmod 600 ~/.ssh/authorized_keys
```

**Теперь можно подключаться без пароля:**

ssh deployer@server.com

## Практический пример

### Настройка `SSH` для `CI/CD`

**Задача:** Настроить деплой через `SSH` без пароля для GitLab CI.  
**Решение:**  
**На сервере:**

codecopy

```
# Создать пользователяsudo useradd -m -s /bin/bash deployer # Создать директорию для ключейsudo mkdir -p /home/deployer/.sshsudo chmod 700 /home/deployer/.ssh
```

**Локально (или в CI):**

codecopy

```
# Генерировать ключ без passphrasessh-keygen -t ed25519 -f deploy_key -N "" # Скопировать публичный ключ на серверcat deploy_key.pub | ssh root@server "cat >> /home/deployer/.ssh/authorized_keys"
```

**На сервере:**

codecopy

```
# Установить праваsudo chmod 600 /home/deployer/.ssh/authorized_keyssudo chown -R deployer:deployer /home/deployer/.ssh # Разрешить deployer рестартить сервисы без пароляsudo visudo
```

Добавить:

deployer ALL=(ALL) NOPASSWD: /bin/systemctl restart myapp, /bin/systemctl status myapp

В GitLab CI ( **`.gitlab-ci.yml`):**

codecopy

```
deploy:  stage: deploy  script:    - eval $(ssh-agent -s)    - echo "$SSH_PRIVATE_KEY" | ssh-add -    - ssh deployer@server "cd /opt/myapp && git pull && sudo systemctl restart myapp"
```

## Troubleshooting

### Проблема 1: `Connection refused`

**Симптомы:**

curl http://example.com:8080

curl: (7) Failed to connect to example.com port 8080: Connection refused

**Причины и решения:**  
**Причина 1: Приложение не запущено**

systemctl status myapp

Если `inactive` или `failed`:

codecopy

```
sudo systemctl start myappjournalctl -u myapp -n 50
```

**Причина 2: Приложение слушает на другом порту**

ss -tlnp | grep java

Видишь что слушает на :8081 вместо :8080? Исправь конфиг приложения.  
**Причина 3: Приложение слушает только на localhost**

ss -tlnp | grep :8080

LISTEN 0 128 127.0.0.1:8080 0.0.0.0:*

## Приложение доступно только локально. Измени конфиг чтобы слушало на `0.0.0.0:8080`.

### Проблема 2: `Connection timeout`

**Симптомы:**

curl http://example.com:8080

Команда висит ~30 секунд и возвращает:

curl: (28) Failed to connect to example.com port 8080: Connection timed out

**Причины и решения:**  
**Причина 1: Файрволл блокирует**

codecopy

```
# На целевом сервереsudo firewall-cmd --list-ports
```

Если порта нет:

codecopy

```
sudo firewall-cmd --add-port=8080/tcp --permanentsudo firewall-cmd --reload
```

**Причина 2: Проблемы с роутингом**

traceroute example.com

Смотришь где пакеты застревают.  
**Причина 3: Неправильный IP/hostname**

codecopy

```
# Проверить резолвингnslookup example.comdig example.com # Пинговатьping example.com
```

### Проблема 3: `SSH` Permission denied (publickey)

**Симптомы:**

ssh deployer@server.com

Permission denied (publickey).

**Причины и решения:**  
**Причина 1: Ключ не добавлен на сервер**  
Проверить:

codecopy

```
# На локальной машинеcat ~/.ssh/id_ed25519.pub # На сервереcat ~/.ssh/authorized_keys
```

Если ключа нет - добавить:

ssh-copy-id deployer@server.com

**Причина 2: Неправильные права на файлы**  
На сервере:

codecopy

```
# Права на директориюchmod 700 ~/.ssh # Права на authorized_keyschmod 600 ~/.ssh/authorized_keys # Владелецls -la ~/.ssh/
```

**Причина 3: Использует неправильный ключ**

codecopy

```
# Явно указать ключssh -i ~/.ssh/specific_key deployer@server.com # Или добавить в ~/.ssh/configHost server    HostName server.com    User deployer    IdentityFile ~/.ssh/specific_key
```

**Причина 4: SELinux блокирует**

codecopy

```
# Проверитьsudo ausearch -m avc -ts recent # Восстановить контекстsudo restorecon -R -v /home/deployer/.ssh
```

### Проблема 4: Too many open files

**Симптомы:**  
В логах приложения:

java.io.IOException: Too many open files

ss -tanp | wc -l

Видишь огромное количество подключений.  
**Причины и решения:**  
**Причина: Достигнут лимит открытых файлов**

codecopy

```
# Проверить текущий лимитulimit -n # Посмотреть лимиты процессаcat /proc/$(pgrep java)/limits | grep "open files"
```

**Решение:**  
Увеличить лимит:

codecopy

```
# Временноulimit -n 65536 # Постоянно - добавить в /etc/security/limits.confsudo nano /etc/security/limits.conf
```

codecopy

```
*    soft nofile 65536*    hard nofile 65536
```

Для systemd сервиса:

sudo systemctl edit myapp

codecopy

```
[Service]LimitNOFILE=65536
```

codecopy

```
sudo systemctl daemon-reloadsudo systemctl restart myapp
```

**Частые ошибки на собеседованиях:**

- Путают "connection refused" и "connection timeout" (refused = порт закрыт, timeout = файрволл)
- Думают что ufw, firewalld и iptables это три разных файрволла (firewalld и ufw это обёртки над iptables)

**Что запомнить:**

- Диагностика: процесс → порт → файрволл → логи
- `ss -tlnp` для проверки открытых портов (с sudo)
- `nc -zv` для быстрой проверки доступности порта
- Connection refused = приложение не слушает, timeout = файрволл блокирует
- SSH ключи требуют правильных прав (700 для .ssh, 600 для ключей)
