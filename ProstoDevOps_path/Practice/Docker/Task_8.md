- **Билдим образ**  
  `docker build -t log-app .`
- **Запускаем контейнер**  
  `docker run -d --name logtest -p "8080:8080" log-app:lates`
- **Проверяем работу приложения**  
  `curl http://localhost:8080`
- **Проверяем логи**  
  `docker logs logtst`  
  Видим огромное количество логов — 800+ при трёх запросах.

**Проблема** — приложение генерирует чрезвычайно много логов, очень быстро забивается диск. При большой или даже средней нагрузке это быстро съест диск, приложение упадёт, а что ещё хуже — может препятствовать работе всего сервера.

**Анализ проблемы**  
Поскольку у нас есть только Dockerfile и `app.py`, начинаем анализ с них. В коде приложения видно, что генерация логов зависит от переменной окружения `LOG_LEVEL`. При значении `DEBUG` генерируется огромное количество логов — это и есть причина проблемы.
В логах видим сообщение:  
`"Starting app with LOG_LEVEL=DEBUG WARNING: DEBUG mode generates INSANE amount of logs!"`  
что подтверждает: установлена переменная `LOG_LEVEL=DEBUG`.
Смотрим Dockerfile — там передаётся это значение: `ENV LOG_LEVEL=DEBUG`.  
Анализ кода показывает: можно уменьшить генерацию логов, установив `LOG_LEVEL == 'INFO'` или `LOG_LEVEL == 'PROD'` (для наименьшего количества логов).

**Решение**  
Варианта два:  
1. Изменить в Dockerfile переменную на `PROD`, пересобрать образ и поднять контейнер.  
2. Передать переменную окружения сразу при запуске контейнера, перезаписав значение из образа.
Выбираю второй вариант:  
```bash
docker rm -f logtest
docker run -d --name logtest -p "8080:8080" -e LOG_LEVEL=PROD log-app:latest
```
Делаем пару запросов:
```
curl http://localhost:8080
curl http://localhost:8080
```

Проверяем логи:  
`docker logs logtest`  
Проблема исправлена — логи больше не генерируются в таком количестве.
