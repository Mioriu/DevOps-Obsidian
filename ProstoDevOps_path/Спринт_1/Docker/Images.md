## Docker Image: Неизменяемый фундамент

Если контейнер — это **процесс** (действие), то образ — это **файл** (данные). Технически, **Docker Image** — это упакованный пакет, в котором есть абсолютно всё, чтобы запустить приложение:

1. Код вашего приложения.
2. Среда выполнения (например, Node.js или Python).
3. Системные библиотеки и инструменты.
4. Настройки (переменные окружения).

## 1. Главный принцип: Слои (Layers)

Это самая важная техническая особенность. Образ — это не один огромный файл (как `.iso` или `.zip`), а **набор слоев**, наложенных друг на друга.

Представьте, что вы рисуете картину на прозрачных пленках:

1. **Слой 1 (Base Image):** Берем пленку и закрашиваем её белым цветом (Это операционная система, например, `Ubuntu`).
2. **Слой 2 (Dependencies):** Кладем сверху вторую пленку и рисуем на ней дерево (Устанавливаем `Python`).
3. **Слой 3 (App Code):** Кладем третью пленку и рисуем яблоки на дереве (Копируем ваш код).

В итоге, смотря сверху, вы видите цельную картину.

### Зачем это нужно? (Кэширование)

Docker ленив и эффективен. Если вы решите обновить код (перерисовать яблоки), Docker не будет заново рисовать фон и дерево. Он просто выбросит верхнюю пленку и положит новую.

Когда вы делаете `docker pull`, скачиваются только те слои, которых у вас еще нет. Если у вас уже есть 5 образов на базе `Ubuntu`, то слой с самой Ubuntu будет храниться на диске в единственном экземпляре.

## 2. Неизменяемость (Immutability)

Образы — **Read-Only**. Как только образ собран, его нельзя изменить. Если вы хотите исправить баг в коде или обновить версию библиотеки, вы не редактируете образ. Вы собираете **новый** образ.

Это гарантирует предсказуемость:

- Образ `myapp:v1`, запущенный сегодня на вашем ноутбуке, будет работать **абсолютно так же**, как тот же самый образ, запущенный через год на другом сервере.

## 3. Dockerfile

Откуда берутся образы? Их собирают из текстовой инструкции, которая называется `Dockerfile`. Это простой список команд: «возьми это», «добавь то», «запусти это».

Давайте посмотрим на `Dockerfile` для простого Python-приложения:

dockerfilecopy

```dockerfile
# 1. FROM: Базовый слой. С чего начинаем?# Берем официальный образ Python версии 3.11 (он уже содержит Linux и Python)FROM python:3.11-slim # 2. WORKDIR: Создаем рабочую папку внутри будущего образаWORKDIR /app # 3. COPY: Копируем файл зависимостей с вашего компьютера внутрь образаCOPY requirements.txt . # 4. RUN: Выполняем команду ВНУТРИ образа (устанавливаем библиотеки)# Этот шаг создаст новый слойRUN pip install -r requirements.txt # 5. COPY: Копируем остальной код приложенияCOPY . . # 6. CMD: Команда, которая сработает ТОЛЬКО при старте контейнераCMD ["python", "main.py"]
```

Чтобы превратить этот текст в образ, вы выполняете команду сборки: `docker build -t my-app:v1 .`

## 4. Теги и версии (Versioning)

У одного образа может быть много версий. Для этого используются **Теги (Tags)**. Тег пишется после двоеточия: `image_name:tag`.

Примеры на основе официального образа `python`:

- `python:3.11` — конкретная версия 3.11.
- `python:3.11.18-slim` — версия 3.11.18, урезанная (облегченная) сборка.
- `python:latest` — метка, указывающая на самую последнюю версию.

**Важно про `latest`:** В продакшене (на боевых серверах) **никогда** не используйте тег `latest`. Сегодня `latest` — это Python 3.11, а завтра разработчики обновят его до Python 4.0, и ваш код сломается при следующем перезапуске. Всегда фиксируйте версии (например, `node:16-alpine`).

## 5. Размер имеет значение (Alpine vs Debian)

Одна из главных битв в мире Docker — это борьба за размер образа. Чем меньше образ:

- Тем быстрее он скачивается по сети (deploy).
- Тем меньше места занимает на диске.
- Тем меньше в нем уязвимостей (меньше лишних программ — меньше дыр).

Поэтому часто используют **Alpine Linux**. Это экстремально легкий дистрибутив Linux.

Например:

- Образ `postgres:latest` (на базе Debian) весит около **350 МБ**.
- Образ `postgres:alpine` весит около **70 МБ**.

## Итог: Что такое образ?

1. **Это слепок.** Замороженное состояние файловой системы и зависимостей.
2. **Это слои.** Он состоит из кирпичиков, которые переиспользуются между разными образами.
3. **Это неизменяемость.** Хотите поменять конфиг? Собирайте новый образ.
4. **Это стандарт.** Вы можете передать образ кому угодно (через Registry), и он запустится гарантированно так же, как у вас.
