## 1. Запуск и управление контейнерами

Самая частая операция — создание и запуск экземпляра приложения.

### `docker run`

Комбинированная команда. Она скачивает образ (если его нет), создает контейнер и запускает его.

**Синтаксис:**

docker run [FLAGS] IMAGE_NAME [COMMAND]

**Ключевые флаги:**

- `-d` (**Detached**): Запуск в фоновом режиме. Контейнер работает, но не блокирует вашу консоль.
    
- `-p` (**Port**): Проброс портов. Формат `HOST_PORT:CONTAINER_PORT`.
    
- Пример: `-p 8080:80` означает, что запросы на порт 8080 вашего компьютера улетят на порт 80 внутри контейнера.
    
- `--name`: Присвоить контейнеру понятное имя вместо случайного ID.
    
- `-v` (**Volume**): Монтирование томов. Прокидывание папки с хоста внутрь контейнера.
    
- `--rm`: Автоматически удалить контейнер после его остановки (полезно для временных задач).
    

**Пример:**

bashcopy

```bash
# Запустить Nginx в фоне, пробросив порт 8080 и назвав его "web-server"docker run -d -p 8080:80 --name web-server nginx
```

### `docker ps`

Показывает список **запущенных** контейнеров.

- `docker ps -a` (All): Показывает **все** контейнеры, включая остановленные. Полезно, чтобы понять, почему контейнер упал сразу после старта.

### `docker stop` / `docker start`

- `docker stop <name_or_id>`: Штатная остановка. Отправляет сигнал `SIGTERM`, давая процессу время (обычно 10 сек) на корректное завершение.
- `docker kill <name_or_id>`: Мгновенная остановка (`SIGKILL`).

## 2. Диагностика и взаимодействие

Как понять, что происходит внутри контейнера, если он запущен в фоне (`-d`)?

### `docker logs`

Выводит поток вывода (`STDOUT` и `STDERR`) главного процесса контейнера.

- `docker logs <name>`: Показать логи с момента старта.
- `docker logs -f <name>` (**Follow**): Читать логи в реальном времени (как `tail -f`).

### `docker exec`

Выполнение команды внутри **уже запущенного** контейнера. Чаще всего используется для входа в консоль контейнера для отладки.

**Пример:**

bashcopy

```bash
# Запустить интерактивный (-i) терминал (t) bash внутри контейнера web-serverdocker exec -it web-server /bin/bash
```

_Если в образе нет bash, используйте `/bin/sh`._

### `docker inspect`

Выводит подробную техническую информацию о контейнере или образе в формате JSON: IP-адрес, пути к вольюмам, переменные окружения и т.д.

docker inspect web-server

## 3. Работа с образами

### `docker images`

Выводит список всех скачанных образов, находящихся локально на диске. Аналог — `docker image ls`.

### `docker pull`

Принудительно скачивает образ из реестра (Docker Hub), не запуская его. Полезно для обновления кэша, если вышла новая версия с тем же тегом.

docker pull postgres:16

### `docker build`

Собирает образ из `Dockerfile`.

**Синтаксис:**

docker build -t NAME:TAG PATH

- `-t`: Тег (имя) будущего образа.
- `.` (точка в конце): Контекст сборки (текущая директория).

**Пример:**

docker build -t my-app:v1 .

## 4. Очистка ресурсов

Docker не удаляет старые контейнеры и образы автоматически. Они копятся и занимают место.

### `docker rm`

Удаляет **остановленный** контейнер.

- `docker rm -f <name>`: Принудительное удаление (даже если запущен).

### `docker rmi`

Удаляет образ (Remove Image). Работает, только если нет контейнеров (даже остановленных), основанных на этом образе.

### `docker system prune`

Команда генеральной уборки. Удаляет:

1. Все остановленные контейнеры.
2. Все неиспользуемые сети.
3. Все висячие (dangling) образы (у которых нет имени, обычно следы неудачных сборок).

|---|---|
|`docker build -t myapp .`|Собрать образ из Dockerfile в текущей папке|
|`docker run -dp 80:80 myapp`|Запустить контейнер в фоне с пробросом порта|
|`docker ps`|Показать работающие контейнеры|
|`docker logs -f <id>`|Смотреть логи контейнера в реальном времени|
|`docker exec -it <id> bash`|Зайти внутрь контейнера через терминал|
|`docker stop <id>`|Остановить контейнер|
|`docker rm <id>`|Удалить контейнер|
|`docker rmi <image>`|Удалить образ|
