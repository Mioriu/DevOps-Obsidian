Переходим к **оркестрации**.

**Docker Compose** — это инструмент для определения и запуска многоконтейнерных приложений Docker.

# Docker Compose: Управление мульти-контейнерной средой

В реальной жизни приложение редко состоит из одного контейнера. Обычно это стек:

- Backend (Python/Go/Node.js)
- Database (PostgreSQL)
- Cache (Redis)
- Frontend (Nginx/React)

Запускать их вручную через `docker run` с кучей флагов (`--network`, `-v`, `-e`, `-p`) — это долго, неудобно и чревато ошибками.

**Docker Compose** решает эту проблему. Он позволяет описать всю архитектуру вашего проекта в **одном файле** (`docker-compose.yml`) и запустить всё одной командой.

## 1. Файл конфигурации: `docker-compose.yml`

Это декларативный файл в формате **YAML**. В нем вы описываете желаемое состояние вашей системы.

Структура файла состоит из трех основных блоков:

1. **Services (Сервисы):** Описание контейнеров, которые нужно запустить.
2. **Volumes (Тома):** Описание хранилищ данных.
3. **Networks (Сети):** Описание сетевого взаимодействия.

### Пример реального файла

Рассмотрим классическую связку: Web-приложение + База данных.

yamlcopy

```yaml
version: '3.8'  # Версия схемы (необязательна в новых версиях Docker Compose v2) services:  # --- Сервис 1: Наше приложение ---  webapp:    build: .              # Собирать образ из Dockerfile в текущей папке    container_name: my-app-prod    ports:      - "8000:8000"       # Проброс портов Хост:Контейнер    environment:      - DB_HOST=postgres_db  # Обращаемся к базе по ИМЕНИ СЕРВИСА      - DB_USER=admin      - DB_PASS=secret    depends_on:      - postgres_db       # Ждать запуска базы данных    networks:      - backend-net       # Подключить к сети   # --- Сервис 2: База данных ---  postgres_db:    image: postgres:14-alpine  # Используем готовый образ с Docker Hub    restart: always            # Перезапускать, если упадет    environment:      POSTGRES_USER: admin      POSTGRES_PASSWORD: secret    volumes:      - db_data:/var/lib/postgresql/data # Именованный том для сохранения данных    networks:      - backend-net # --- Описание томов ---volumes:  db_data: # Docker создаст этот том автоматически # --- Описание сетей ---networks:  backend-net:    driver: bridge
```

## 2. Разбор ключевых директив

### `build` vs `image`

- **`image: postgres`**: Скачать готовый образ из реестра. Используется для баз данных, очередей и стандартного ПО.
- **`build: .`**: Собрать образ из исходного кода (ищет Dockerfile). Используется для вашего собственного кода.

### `depends_on`

Указывает порядок запуска. Docker сначала запустит `postgres_db`, и только потом `webapp`. _Важно:_ Docker ждет только старта _контейнера_, он не проверяет, готова ли база _принимать подключения_ (для этого в коде приложения пишут ретраи или используют скрипты `wait-for-it`).

### `restart`

Политика перезапуска (Restart Policy):

- `no`: Не перезапускать (по умолчанию).
- `always`: Всегда перезапускать, если контейнер остановился (даже если вы перезагрузили сервер).
- `on-failure`: Перезапускать только если приложение упало с ошибкой.

### Магия DNS в Compose

Вам больше не нужны IP-адреса. Внутри сети Docker Compose создает DNS-записи по именам сервисов. Если сервис называется `postgres_db`, то ваше приложение может подключиться к нему по хосту `postgres_db`.

## 3. Основные команды (CLI)

В современном Docker (версии v2 и выше) команда пишется как `docker compose` (с пробелом). Старый вариант `docker-compose` (через дефис) считается устаревшим.

### Запуск и остановка

- **`docker compose up`** Читает файл `docker-compose.yml`, создает сети, тома и запускает контейнеры. Логи выводятся в консоль.
- **`docker compose up -d`** (**Detached**) Самая частая команда. Запускает всё в фоновом режиме и освобождает терминал.
- **`docker compose down`** Останавливает и удаляет контейнеры и сети.
- **`docker compose down -v`** Удаляет контейнеры, сети **И ТОМА (Volumes)**

### Управление

- **`docker compose ps`** Показать статус контейнеров, относящихся к текущему проекту (текущему файлу yml).
- **`docker compose logs -f`** Просмотр логов всех сервисов одновременно.
- **`docker compose logs -f webapp`** Просмотр логов конкретного сервиса.
- **`docker compose exec webapp bash`** Зайти внутрь конкретного контейнера.
- **`docker compose build`** Принудительная пересборка образов (если вы изменили код, но не изменили `docker-compose.yml`).

## 4. Переменные окружения и `.env`

Хардкодить пароли в `docker-compose.yml` — плохая практика, особенно если файл попадает в Git. Docker Compose автоматически ищет файл **`.env`** в той же папке.

**Файл `.env`:**

inicopy

```ini
POSTGRES_USER=adminPOSTGRES_PASSWORD=super_secret_passAPP_PORT=8080
```

**Файл `docker-compose.yml`:**

yamlcopy

```yaml
services:  db:    image: postgres    environment:      POSTGRES_USER: ${POSTGRES_USER}         # Подставит значение из .env      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}    ports:      - "${APP_PORT}:80"
```

Это позволяет иметь разные конфиги для локальной разработки, теста и продакшена, просто меняя `.env` файл.

## 5. Именование проектов

Docker Compose группирует ресурсы по **имени проекта**. По умолчанию имя проекта — это **название папки**, где лежит файл.

Если ваша папка называется `my_project`, то контейнеры получат имена:

- `my_project-webapp-1`
- `my_project-db-1`
- Сеть: `my_project_default`

Это позволяет запускать несколько копий одного и того же окружения в разных папках, и они не будут конфликтовать.
