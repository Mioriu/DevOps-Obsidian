# Основы сетей: что такое сеть, клиент-сервер и протоколы

## Зачем это знать?

- Приложение не может подключиться к базе данных — нужно понять, это проблема сети или самого приложения
- "Cайт не открывается" — надо понять почему
- Настраиваешь новый сервис и он не видит другие сервисы в сети
- И т.д.

## 1. Что такое сеть

Сеть — это когда два или больше компа могут обмениваться данными. Всё.

Не нужно усложнять. Если комп может отправить файл на другой комп — между ними есть сеть. Если сервер приложения может сходить в базу данных — они в одной сети (или в связанных сетях).

### Типы сетей по масштабу

|Тип|Расшифровка|Пример|Размер|
|---|---|---|---|
|LAN|Local Area Network|Офис, дата-центр|Одно здание|
|WAN|Wide Area Network|Связь между офисами|Город, страна|
|Internet|Сеть сетей|Весь мир|Глобально|

В DevOps ты чаще всего работаешь с LAN внутри дата-центра или облака, и с выходом в интернет для внешних пользователей.

### Что запомнить

- Сеть = возможность обмена данными между устройствами
- LAN — локальная сеть (офис, дата-центр)
- WAN — глобальная сеть (интернет и связь между локациями)

## 2. Клиент-серверная модель

Это базовая модель взаимодействия в сетях. Почти всё построено на ней.

### Роли: клиент и сервер

**Клиент** — тот кто запрашивает. Инициирует соединение, отправляет запрос, ждёт ответ.

**Сервер** — тот кто отвечает. Слушает входящие соединения, принимает запросы, отправляет ответы.

**Важно:** это роли, не типы устройств. Один и тот же сервер может быть клиентом для базы данных и сервером для пользователей.

![Схема в материале «Основы 1: Базовая база»: Пользователь (клиент) → Nginx (сервер)](https://offers.prostodevops.ru/diagrams/extras/seti/osnovy-1-bazovaya-baza-3.png)Схема в материале «Основы 1: Базовая база»: Пользователь (клиент) → Nginx (сервер)Nginx одновременно сервер для пользователя и клиент для бэкенда.

### Как это работает пошагово

1. Сервер запускается и начинает слушать на определённом порту (например, nginx на 80)
2. Клиент узнаёт адрес сервера (IP или доменное имя)
3. Клиент устанавливает соединение с сервером
4. Клиент отправляет запрос
5. Сервер обрабатывает запрос
6. Сервер отправляет ответ
7. Соединение закрывается (или остаётся открытым для следующих запросов)

### Проверяем на практике

Смотрим кто слушает порты на сервере:

bashcopy

```bash
# Показать все слушающие портыss -tlnp
```

Вывод:

codecopy

```
State    Recv-Q   Send-Q   Local Address:Port    Peer Address:Port   ProcessLISTEN   0        128      0.0.0.0:22            0.0.0.0:*           users:(("sshd",pid=1234,fd=3))LISTEN   0        511      0.0.0.0:80            0.0.0.0:*           users:(("nginx",pid=5678,fd=6))LISTEN   0        244      127.0.0.1:5432        0.0.0.0:*           users:(("postgres",pid=9012,fd=5))
```

Что мы видим:

- sshd слушает на порту 22 на всех интерфейсах (0.0.0.0) — можно подключиться снаружи
- nginx слушает на 80 на всех интерфейсах — веб-сервер доступен извне
- postgres слушает на 5432 только на localhost (127.0.0.1) — только локальные подключения

Смотрим установленные соединения:

bashcopy

```bash
# Показать активные TCP соединенияss -tnp
```

Вывод:

codecopy

```
State    Recv-Q   Send-Q   Local Address:Port    Peer Address:Port    ProcessESTAB    0        0        10.0.0.5:80           203.0.113.45:52431   users:(("nginx",pid=5678,fd=10))ESTAB    0        0        10.0.0.5:45678        10.0.0.10:5432       users:(("python",pid=3456,fd=8))
```

Здесь видно:

- Кто-то с IP 203.0.113.45 подключён к nginx (клиент → сервер)

### Альтернатива: peer-to-peer (P2P)

В P2P нет выделенного сервера. Каждый участник может быть и клиентом, и сервером одновременно. Примеры: торренты, некоторые блокчейны.

В DevOps P2P встречается редко. Почти всё — клиент-сервер.

### Что запомнить

- Клиент инициирует соединение, сервер ждёт подключений
- Одна машина может быть клиентом и сервером одновременно

## 3. IP-адреса и порты

Чтобы клиент нашёл сервер, нужны два параметра: куда идти (IP-адрес) и в какую дверь стучать (порт).

### IP-адрес

IP-адрес — уникальный идентификатор устройства в сети.

**IPv4** — 4 числа от 0 до 255 (октеты), разделённые точками:

codecopy

```
192.168.1.10010.0.0.58.8.8.8
```

**IPv6** — 8 групп по 4 hex-символа:

2001:0db8:85a3:0000:0000:8a2e:0370:7334

В большинстве инфраструктур пока используется IPv4. IPv6 встречается, но реже.

### Специальные адреса

|Адрес|Назначение|
|---|---|
|127.0.0.1|localhost, сам на себя|
|0.0.0.0|"все интерфейсы" при прослушивании|
|10.x.x.x|Приватная сеть (класс A)|
|172.16.x.x - 172.31.x.x|Приватная сеть (класс B)|
|192.168.x.x|Приватная сеть (класс C)|

Приватные адреса не маршрутизируются в интернете. Их используют внутри локальных сетей.

### Порт

Порт — число от 0 до 65535. Определяет конкретный сервис на машине.

**Стандартные порты:**

|Порт|Сервис|
|---|---|
|22|SSH|
|80|HTTP|
|443|HTTPS|
|3306|MySQL|
|5432|PostgreSQL|
|6379|Redis|
|8080|HTTP (альтернативный)|
|9090|Prometheus|
|3000|Grafana|

### Сокет = IP + порт

Комбинация IP-адреса и порта называется сокетом:

codecopy

```
192.168.1.100:543210.0.0.5:80
```

Полное соединение описывается парой сокетов:

клиент 10.0.0.5:45678 → сервер 10.0.0.10:5432

Клиентский порт (45678) выбирается случайно из диапазона эфемерных портов (обычно 32768-60999).

### Проверяем адреса на практике

bashcopy

```bash
# Показать IP-адреса на интерфейсахip addr show
```

Вывод:

codecopy

```
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536    inet 127.0.0.1/8 scope host lo2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500    inet 10.0.0.5/24 brd 10.0.0.255 scope global eth0
```

Видим:

- lo — loopback интерфейс с адресом 127.0.0.1
- eth0 — сетевой интерфейс с адресом 10.0.0.5, маска /24 (255.255.255.0)

### Что запомнить

- IP-адрес — адрес машины в сети
- Порт — номер сервиса на машине
- Приватные сети: 10.x.x.x, 172.16-31.x.x, 192.168.x.x
- Знай стандартные порты: 22 (SSH), 80 (HTTP), 443 (HTTPS), 5432 (PostgreSQL)

## 4. Что такое протокол

Протокол — это набор правил, по которым общаются клиент и сервер. Договорённость о формате сообщений и порядке действий.

### Зачем нужны протоколы

Без протокола клиент и сервер не поймут друг друга:

- В каком формате отправлять данные?
- Как понять что сообщение закончилось?
- Что делать если часть данных потерялась?
- Как сообщить об ошибке?

Протокол отвечает на все эти вопросы.

### Уровни протоколов (модель TCP/IP)

Протоколы работают на разных уровнях. Каждый уровень решает свою задачу:

|Уровень|Название|Протоколы|Задача|
|---|---|---|---|
|4|Прикладной|HTTP, SSH, DNS, SMTP|Логика приложения|
|3|Транспортный|TCP, UDP|Доставка данных между процессами|
|2|Сетевой|IP, ICMP|Маршрутизация между сетями|
|1|Канальный|Ethernet, Wi-Fi|Передача по физическому каналу|

Когда ты отправляешь HTTP-запрос:

1. HTTP формирует запрос (GET /index.html)
2. TCP разбивает на сегменты, нумерует, гарантирует доставку
3. IP добавляет адреса источника и назначения, маршрутизирует
4. Ethernet упаковывает в кадры и отправляет по проводу/Wi-Fi

На принимающей стороне всё распаковывается в обратном порядке.

## 5. Как всё работает вместе: путь HTTP-запроса (забегая чуть вперёд)

Разберём полный путь запроса когда ты открываешь сайт в браузере.

### Шаг за шагом

**1. Ты вводишь в браузере:** `http://example.com/page`

**2. DNS-резолвинг:**![Схема в материале «Основы 1: Базовая база»: Браузер → DNS-сервер: "Какой IP у example.com?"](https://offers.prostodevops.ru/diagrams/extras/seti/osnovy-1-bazovaya-baza-4.png)Схема в материале «Основы 1: Базовая база»: Браузер → DNS-сервер: "Какой IP у example.com?"

**3. TCP-соединение:**![Схема в материале «Основы 1: Базовая база»: Браузер → Сервер: SYN](https://offers.prostodevops.ru/diagrams/extras/seti/osnovy-1-bazovaya-baza-1.png)Схема в материале «Основы 1: Базовая база»: Браузер → Сервер: SYN

**4. HTTP-запрос:**

codecopy

```
GET /page HTTP/1.1Host: example.comUser-Agent: Mozilla/5.0Accept: text/html
```

**5. Сервер обрабатывает:**

- Nginx принимает запрос
- Смотрит конфиг, находит нужный location
- Отдаёт статику или проксирует на бэкенд

**6. HTTP-ответ:**

codecopy

```
HTTP/1.1 200 OKContent-Type: text/htmlContent-Length: 1234 <!DOCTYPE html><html>...
```

**7. Закрытие соединения** (или keep-alive для следующих запросов)
