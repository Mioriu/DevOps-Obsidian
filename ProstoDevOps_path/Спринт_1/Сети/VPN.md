# VPN: WireGuard, OpenVPN, IPSec

VPN (Virtual Private Network) — это зашифрованный туннель между точками через недоверенную сеть (интернет). Снаружи виден только шифрованный трафик, внутри — обычная сетевая связность.

## 1. Как работает VPN

Базовая идея: взять пакеты, зашифровать их, обернуть в другие пакеты и отправить через интернет. На другой стороне — развернуть и расшифровать.

![Схема в материале «Сети расширенные 4: VPN (WireGuard, OpenVPN, IPSec)»: Исходный пакет: [IP: 10.0.1.5 → 10.0.2.10] [Data: ...]](https://offers.prostodevops.ru/diagrams/extras/seti/seti-rasshirennye-4-vpn-wireguard-openvpn-ipsec-1.png)Схема в материале «Сети расширенные 4: VPN (WireGuard, OpenVPN, IPSec)»: Исходный пакет: [IP: 10.0.1.5 → 10.0.2.10] [Data: ...]

Внешние IP — публичные адреса VPN-серверов. Внутренние IP — приватные адреса, которые "не видны" в интернете.

## 2. WireGuard

Современный VPN-протокол. Простой, быстрый, минимум кода (4000 строк vs 100000+ у OpenVPN).

### Принципы

- Работает на уровне ядра Linux (есть userspace-реализации для других ОС)
- UDP-based (один порт, обычно 51820)
- Криптография без выбора — фиксированный набор современных алгоритмов
- Нет понятия "соединение" — есть только пиры с публичными ключами

### Как работает

Каждый участник имеет пару ключей (приватный + публичный). Конфигурация описывает: мой приватный ключ, публичные ключи пиров, какие IP-адреса за каким пиром.

codecopy

```
[Interface]PrivateKey = <мой приватный ключ>Address = 10.0.0.1/24ListenPort = 51820 [Peer]PublicKey = <публичный ключ пира>AllowedIPs = 10.0.0.2/32Endpoint = 203.0.113.5:51820
```

**AllowedIPs** — ключевая концепция. Это одновременно:

- Какие IP принимать от этого пира (входящий фильтр)
- На какие IP отправлять через этого пира (роутинг)

### Плюсы и минусы

Плюсы:

- Очень быстрый (работает в ядре)
- Простая конфигурация
- Минимальная поверхность атаки (мало кода)
- Роуминг — клиент может менять IP, соединение сохраняется
- Встроен в ядро Linux с версии 5.6

Минусы:

- Нет встроенного управления пользователями (нужны внешние инструменты)
- Только UDP (может блокироваться)
- Нельзя выбрать криптографию (для некоторых compliance-требований это проблема)

## 3. OpenVPN

Зрелый, проверенный временем.

### Принципы

- Работает в userspace (не в ядре)
- Может работать поверх TCP или UDP
- Гибкая настройка криптографии
- PKI (сертификаты) или pre-shared keys
- Поддержка username/password аутентификации

### Архитектура

Два режима:

- **TUN** — L3, IP-пакеты (чаще используется)
- **TAP** — L2, Ethernet-фреймы (для bridging)

Обычно используется клиент-серверная модель с PKI:![VPN PKI: CA подписывает Server и Clients сертификаты](https://offers.prostodevops.ru/diagrams/network/vpn-pki.png)VPN PKI: CA подписывает Server и Clients сертификаты

### Плюсы и минусы

Плюсы:

- Работает везде (Windows, Mac, Linux, мобильные)
- TCP-режим проходит через большинство файрволов
- Гибкая конфигурация
- Зрелая экосистема, много документации
- Интеграция с LDAP, RADIUS

Минусы:

- Медленнее WireGuard
- Сложная настройка PKI
- Много конфигурационных опций (легко ошибиться)

## 4. IPSec

Набор протоколов для шифрования на сетевом уровне. Стандарт для site-to-site VPN, особенно в энтерпрайзе.

### Компоненты

**IKE (Internet Key Exchange)** — протокол согласования ключей:

- IKEv1 — старый, сложный
- IKEv2 — современный, проще, лучше для мобильных клиентов

**ESP (Encapsulating Security Payload)** — собственно шифрование и аутентификация данных

**AH (Authentication Header)** — только аутентификация, без шифрования (редко используется)

### Режимы работы

**Transport mode** — шифруется только полезная нагрузка, IP-заголовок остаётся:

[Оригинальный IP-заголовок][Заголовок ESP][Зашифрованная полезная нагрузка][Трейлер ESP]

Используется для host-to-host.

**Tunnel mode** — шифруется весь пакет, добавляется новый IP-заголовок:

[Новый IP-заголовок][Заголовок ESP][Зашифрованный: оригинальный IP-заголовок + полезная нагрузка][Трейлер ESP]

Используется для site-to-site VPN.

### Реализации

**strongSwan** — основная open-source реализация для Linux:

**Libreswan** — форк, популярен в RHEL/CentOS.

### IKEv2 для мобильных клиентов

IKEv2 хорошо работает с мобильными устройствами — поддерживает MOBIKE (смена IP без переподключения).

Встроенная поддержка:

- iOS/macOS — нативно
- Windows 10+ — нативно
- Android — через strongSwan app

### Плюсы и минусы

Плюсы:

- Стандарт, поддерживается всеми вендорами (Cisco, Juniper, облака)
- Нативная поддержка в ОС (не нужен отдельный клиент для IKEv2)
- Работает на L3, прозрачен для приложений
- Хорошо интегрируется с сетевым оборудованием

Минусы:

- Сложная настройка и отладка
- Много вариантов конфигурации (легко получить несовместимость)
- NAT traversal может быть проблемой

## 5. Сравнение

|Характеристика|WireGuard|OpenVPN|IPSec/IKEv2|
|---|---|---|---|
|Скорость|Очень высокая|Средняя|Высокая|
|Сложность настройки|Низкая|Средняя|Высокая|
|Протокол|UDP|UDP/TCP|UDP (ESP+IKE)|
|Криптография|Фиксированная|Настраиваемая|Настраиваемая|
|Поддержка ОС|Linux (ядро), другие (userspace)|Все|Все (нативно)|
|NAT traversal|Да|Да|Да (NAT-T)|
|Мобильные клиенты|Приложения|Приложения|Нативно|
|Enterprise интеграция|Слабая|LDAP, RADIUS|LDAP, RADIUS, PKI|
|Аудит кода|Простой (мало кода)|Сложный|Сложный|

### Когда что использовать

**WireGuard:**

- Новые проекты без legacy-требований
- Максимальная производительность
- Простота важнее гибкости
- Mesh-сети между серверами

**OpenVPN:**

- Нужна поддержка TCP (строгие файрволы)
- Интеграция с существующей PKI
- Нужны разные профили доступа для пользователей
- Клиенты на разных ОС

**IPSec/IKEv2:**

- Site-to-site с сетевым оборудованием (Cisco, Juniper)
- Нативные клиенты без установки софта
- Enterprise-требования, compliance
- Интеграция с облачными VPN (AWS VPN, Azure VPN Gateway)

## 6. Практические сценарии

### Remote Access для команды

Рекомендация: WireGuard или OpenVPN.

WireGuard проще, но нужен UI для управления (можно использовать wg-easy, Firezone, Netmaker).

OpenVPN сложнее в настройке, но есть готовые решения типа Pritunl с веб-интерфейсом.

### Site-to-Site между облаками

Для облаков лучше брать IPSec, если оба облака имеют managed VPN gateways с поддержкой IPSec.

Для своих серверов WireGuard проще и быстрее.

### Mesh между серверами

WireGuard + инструменты:

- **Tailscale** — managed WireGuard, очень просто
- **Netmaker** — self-hosted mesh
- **Nebula** — не WireGuard, но похожая концепция от Slack

## Что запомнить

1. **VPN — зашифрованный туннель** через недоверенную сеть. Внутри — обычная сетевая связность
    
2. **WireGuard** — быстрый, простой, современный. Первый выбор для новых проектов
    
3. **OpenVPN** — гибкий, зрелый. Когда нужен TCP или сложная аутентификация
    
4. **IPSec/IKEv2** — стандарт для enterprise и интеграции с сетевым оборудованием. Нативные клиенты в ОС
    
5. **AllowedIPs в WireGuard** — и фильтр входящего, и таблица маршрутизации
    
6. **OpenVPN требует PKI** — CA, серверный сертификат, клиентские сертификаты
    
7. **IKEv2 лучше для мобильных** — поддерживает смену сети без разрыва (MOBIKE)
    
8. **Для managed решений**: Tailscale (WireGuard), облачные VPN Gateway (IPSec)
