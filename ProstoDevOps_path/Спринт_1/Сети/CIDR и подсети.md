## 1. IP-адрес: Из чего он состоит

Прежде чем разбираться с подсетями, нужно понять, что такое IP-адрес на уровне битов.

IP-адрес (IPv4) — это 32-битное число. Мы записываем его в виде четырёх десятичных чисел через точку для удобства, но компьютер видит только нули и единицы.

codecopy

```
Человеческая запись:   192.168.1.10Двоичная запись:       11000000.10101000.00000001.00001010
```

Каждое из четырёх чисел (октет) — это 8 бит. Диапазон значений одного октета: от 0 (`00000000`) до 255 (`11111111`).

Любой IP-адрес делится на две части:

- **Сетевая часть (Network)** — идентификатор сети, к которой принадлежит устройство. Как название улицы.
- **Хостовая часть (Host)** — идентификатор конкретного устройства внутри этой сети. Как номер дома.

Вопрос в том, где проходит граница между этими частями. Именно это определяет маска подсети.

## 2. Маска подсети (Subnet Mask)

Маска подсети — это 32-битное число, которое показывает, какие биты IP-адреса относятся к сети, а какие — к хосту.

Правило простое: единицы в маске — это сетевая часть, нули — хостовая.

codecopy

```
IP-адрес:       192.168.1.10                11000000.10101000.00000001.00001010 Маска:          255.255.255.0                11111111.11111111.11111111.00000000                |------сеть---------|----хост----| Сетевая часть:  192.168.1Хостовая часть:             .10
```

В этом примере первые 24 бита — сеть, последние 8 бит — хост. Это значит, что все устройства с адресами `192.168.1.X` находятся в одной сети.

### Как маска работает технически

Чтобы определить адрес сети, выполняется побитовая операция AND между IP-адресом и маской:

![Схема в материале «Основы 2: CIDR и Подсети»: IP:     11000000.10101000.00000001.00001010  (192.168.1.10)](https://offers.prostodevops.ru/diagrams/extras/seti/osnovy-2-cidr-i-podseti-3.png)Схема в материале «Основы 2: CIDR и Подсети»: IP: 11000000.10101000.00000001.00001010 (192.168.1.10)

Результат — адрес сети `192.168.1.0`. Любое устройство, у которого операция AND с той же маской даёт тот же результат, находится в той же сети.

## 3. CIDR-нотация

Записывать маску как `255.255.255.0` длинно и неудобно. Поэтому в 1993 году появилась нотация **CIDR (Classless Inter-Domain Routing)**.

Вместо полной маски указывается количество единичных битов через слеш после IP-адреса:

![Схема в материале «Основы 2: CIDR и Подсети»: 192.168.1.0/24   →   маска 255.255.255.0   (24 единицы, 8 нулей)](https://offers.prostodevops.ru/diagrams/extras/seti/osnovy-2-cidr-i-podseti-1.png)Схема в материале «Основы 2: CIDR и Подсети»: 192.168.1.0/24 → маска 255.255.255.0 (24 единицы, 8 нулей)

Число после слеша называется **префиксом**. `/24` означает, что первые 24 бита — это сеть, оставшиеся 8 — хосты.

### Таблица соответствия

|CIDR|Маска подсети|Бит под хосты|Кол-во адресов|Доступно хостам|
|---|---|---|---|---|
|/8|255.0.0.0|24|16 777 216|16 777 214|
|/16|255.255.0.0|16|65 536|65 534|
|/24|255.255.255.0|8|256|254|
|/25|255.255.255.128|7|128|126|
|/26|255.255.255.192|6|64|62|
|/27|255.255.255.224|5|32|30|
|/28|255.255.255.240|4|16|14|
|/30|255.255.255.252|2|4|2|
|/32|255.255.255.255|0|1|1|

Почему «доступно хостам» всегда на 2 меньше, чем «кол-во адресов»? Потому что в каждой подсети два адреса зарезервированы:

- **Первый адрес** — адрес самой сети (например, `192.168.1.0`). Нельзя назначить устройству.
- **Последний адрес** — широковещательный (broadcast) адрес (например, `192.168.1.255`). Пакет на этот адрес получат все устройства в сети.

## 4. Зачем нужно деление на подсети (Subnetting)

Представьте, что у вас есть сеть `10.0.0.0/8` — это больше 16 миллионов адресов. Если все устройства компании окажутся в одной такой сети, возникнут проблемы:

**Широковещательный шторм.** Многие сетевые протоколы (ARP, DHCP) отправляют пакеты всем устройствам в сети. Если в сети 10 000 машин, каждая из них будет обрабатывать широковещательные пакеты от всех остальных. Сеть захлебнётся.

**Отсутствие изоляции.** Бухгалтерия, разработка и продакшен-серверы оказываются в одном сегменте. Любой компьютер может напрямую обратиться к любому другому.

**Невозможность гранулярного управления.** Нельзя применить правила файрвола к отделу, если весь отдел не выделен в отдельный сегмент.

Subnetting решает это: вы берёте большую сеть и нарезаете её на подсети поменьше, каждая из которых изолирована на сетевом уровне.

## 5. Как делить сети: Практика

### Пример 1: Разделить /24 на две равные подсети

Исходная сеть: `192.168.1.0/24` — 256 адресов, 254 хоста.

Чтобы разделить пополам, увеличиваем префикс на 1: `/24` → `/25`. Один бит из хостовой части уходит в сетевую.

codecopy

```
Было:   192.168.1.0/24        сеть: 192.168.1   хост: 8 бит (256 адресов) Стало:  две подсети /25, хост: 7 бит (128 адресов каждая)
```

|Подсеть|Диапазон хостов|Broadcast|
|---|---|---|
|192.168.1.0/25|192.168.1.1 – 192.168.1.126|192.168.1.127|
|192.168.1.128/25|192.168.1.129 – 192.168.1.254|192.168.1.255|

Каждая подсеть вмещает 126 хостов.

### Пример 2: Разделить /24 на четыре подсети

Увеличиваем префикс на 2: `/24` → `/26`. Два бита уходят из хостовой части в сетевую.

/26 = 64 адреса на подсеть, 62 хоста

|Подсеть|Диапазон хостов|Broadcast|
|---|---|---|
|192.168.1.0/26|192.168.1.1 – 192.168.1.62|192.168.1.63|
|192.168.1.64/26|192.168.1.65 – 192.168.1.126|192.168.1.127|
|192.168.1.128/26|192.168.1.129 – 192.168.1.190|192.168.1.191|
|192.168.1.192/26|192.168.1.193 – 192.168.1.254|192.168.1.255|

### Формула

Количество подсетей при увеличении префикса на N бит:

codecopy

```
Подсетей = 2^NХостов в каждой = 2^(оставшиеся биты) - 2
```

Например, разбиваем `/24` на подсети `/27`:

- Увеличили префикс на 3 бита → `2^3 = 8` подсетей.
- В хостовой части осталось 5 бит → `2^5 - 2 = 30` хостов в каждой.

## 6. Быстрый счёт: Шаг подсети

Есть способ быстро определить границы подсетей без перевода в двоичную систему.

**Шаг подсети** — это размер блока адресов, который занимает одна подсеть. Он равен количеству адресов в подсети.

![Схема в материале «Основы 2: CIDR и Подсети»: /25 → 128 адресов → шаг 128 → подсети начинаются с 0, 128](https://offers.prostodevops.ru/diagrams/extras/seti/osnovy-2-cidr-i-podseti-2.png)Схема в материале «Основы 2: CIDR и Подсети»: /25 → 128 адресов → шаг 128 → подсети начинаются с 0, 128

Зная шаг, вы мгновенно определяете, к какой подсети принадлежит адрес.

**Вопрос:** К какой подсети `/26` принадлежит адрес `192.168.1.200`?

Шаг `/26` = 64. Подсети: 0, 64, 128, **192**, 256. Адрес 200 попадает в блок, начинающийся с 192. Ответ: `192.168.1.192/26`.

## 7. Частные (Private) IP-адреса

Не все IP-адреса маршрутизируются в Интернете. Три диапазона зарезервированы для внутренних сетей (RFC 1918):

|Диапазон|CIDR|Количество адресов|
|---|---|---|
|10.0.0.0 – 10.255.255.255|10.0.0.0/8|16 777 216|
|172.16.0.0 – 172.31.255.255|172.16.0.0/12|1 048 576|
|192.168.0.0 – 192.168.255.255|192.168.0.0/16|65 536|

Эти адреса можно свободно использовать внутри любой локальной сети. В Интернет они не попадают — для выхода наружу используется NAT (Network Address Translation), который заменяет приватный адрес на публичный.

Именно из этих диапазонов выделяются подсети в облачных VPC (Virtual Private Cloud). Когда вы создаёте сеть в Yandex Cloud или AWS, вы выбираете, например, `10.0.0.0/16` и дальше нарезаете её на подсети `/24` для разных сервисов.

## 8. CIDR в реальной жизни: Примеры

### Облачная инфраструктура

Типичная схема VPC:

![VPC + подсети (public/app/db/monitoring)](https://offers.prostodevops.ru/diagrams/network/cidr-subnets.png)VPC + подсети (public/app/db/monitoring)

Каждая подсеть изолирована. Между ними трафик проходит через маршрутизатор, где можно применить правила безопасности: например, разрешить подсети `app` подключаться к подсети `db` по порту 5432, но запретить всё остальное.

### Docker-сети

Docker по умолчанию создаёт bridge-сеть `172.17.0.0/16`. Каждый контейнер в этой сети получает адрес из этого диапазона. Когда вы создаёте пользовательские сети через `docker network create`, вы можете указать свой CIDR:

docker network create --subnet=10.10.0.0/24 my-network

### Правила файрвола / Security Groups

CIDR используется для задания правил доступа:

diagramcopy

```
Разрешить SSH (порт 22) с адреса 203.0.113.50/32    ← один конкретный IP
Разрешить HTTP (порт 80) с 0.0.0.0/0                ← весь Интернет
Разрешить PostgreSQL (5432) с 10.0.2.0/24            ← только подсеть app
```

`/32` — это маска для одного единственного адреса. `0.0.0.0/0` — это все возможные адреса (ноль бит под сеть, все 32 бита — хосты).
