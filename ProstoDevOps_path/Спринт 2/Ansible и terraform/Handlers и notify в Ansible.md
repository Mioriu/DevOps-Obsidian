## Проблема, которую решают handlers

Типичная ситуация. Вы меняете конфиг nginx через template и после этого хотите сделать reload, чтобы nginx подхватил новый конфиг. Самый очевидный подход:

yamlcopy

```yaml
  tasks:    - name: Сгенерировать конфиг nginx      template:        src: nginx.conf.j2        dest: /etc/nginx/nginx.conf     - name: Перезагрузить nginx      service:        name: nginx        state: reloaded
```

И это работает. Но вот проблема — nginx будет перезагружаться каждый раз, когда вы запускаете плейбук. Даже если конфиг не изменился. Первый запуск — конфиг обновился, reload. Второй запуск — конфиг тот же, но reload всё равно. Третий — то же самое. А reload — это хоть и мягкая перезагрузка, но всё равно операция, которую не хочется делать просто так.

Handlers решают это красиво. Handler — это задача, которая выполняется только если ее позвали. А позвать ее может только задача, которая реально что-то изменила (статус `changed`).

## Как это работает

yamlcopy

```yaml
---- name: Настройка nginx  hosts: webservers  become: true   tasks:    - name: Сгенерировать основной конфиг nginx      template:        src: nginx.conf.j2        dest: /etc/nginx/nginx.conf      notify: Перезагрузить nginx     - name: Скопировать конфиг сайта      template:        src: site.conf.j2        dest: /etc/nginx/conf.d/site.conf      notify: Перезагрузить nginx     - name: Установить htop (не связано с nginx)      apt:        name: htop        state: present   handlers:    - name: Перезагрузить nginx      service:        name: nginx        state: reloaded
```

Что тут происходит:

1. Ansible генерирует основной конфиг nginx. Если файл изменился — задача получает статус `changed`, и handler "Перезагрузить nginx" помечается как "нужно выполнить".
2. Ansible копирует конфиг сайта. Если и он изменился — тот же handler помечается.
3. Ansible ставит htop. Это к nginx отношения не имеет, handler не трогается.
4. Все таски выполнены. Теперь Ansible смотрит: есть ли помеченные handlers? Если да — выполняет их.

Если ни один конфиг не изменился — обе задачи будут в статусе `ok`, handler не вызовется, nginx не перезагрузится.

Ещё один важный момент — handler выполняется только один раз, даже если его позвали несколько задач. Не будет двух reload'ов, будет один.

## Порядок выполнения handlers

Handlers выполняются не сразу после задачи, которая их позвала, а в конце плея, после всех тасок. Это по умолчанию.

То есть, вот такой порядок:

![Схема в материале «Плейбуки: Handlers»: TASK [Сгенерировать конфиг nginx]   → changed → handler помечен](https://offers.prostodevops.ru/diagrams/extras/ansible/pleybuki-handlers-1.png)Схема в материале «Плейбуки: Handlers»: TASK [Сгенерировать конфиг nginx] → changed → handler помечен

Почему так сделано? Потому что если у вас несколько задач меняют конфиги одного сервиса, вы хотите перезагрузить его один раз в конце, а не после каждого изменённого файла.

Если handlers несколько, они выполняются в том порядке, в котором описаны в секции `handlers`, а не в порядке вызова через `notify`.
