### Тезисно: Управление разделами дисков в Linux

**1. Зачем нужны разделы? (Логическое разделение)**

- **Изоляция:** Система (/) и данные (/home) в разных разделах. Если пользователь заполнит /home, система продолжит работать.
    
- **Мультизагрузка:** Несколько ОС на одном диске.
    
- **Безопасность:** Разные права доступа для разных разделов.
    
- **Удобство бэкапов:** Можно копировать только нужный раздел.
    

**2. Таблицы разделов: MBR vs GPT (Фундамент)**

- **MBR (Master Boot Record):** Старый стандарт.
    
    - Максимум 4 основных раздела.
        
    - Максимальный размер диска 2 ТБ.
        
    - Подходит для старых систем и BIOS.
        
- **GPT (GUID Partition Table):** Современный стандарт.
    
    - До 128 разделов (в Linux).
        
    - Диски размером до 9,4 ЗБ.
        
    - Требует UEFI для загрузки (но можно использовать и с BIOS через специальный загрузчик).
        
    - **Проверка:** `sudo fdisk -l /dev/sda` (смотрим строку `Disklabel type`).
        

**3. Основные инструменты: fdisk и parted**

- **fdisk:** Классическая утилита с интерактивным меню. Изменения применяются только после команды `w` (защита от ошибок).
    
    - **Основные команды внутри fdisk:**
        
        - `g` — создать новую GPT таблицу.
            
        - `n` — новый раздел.
            
        - `d` — удалить раздел.
            
        - `t` — изменить тип раздела (например, на swap).
            
        - `p` — показать текущую таблицу.
            
        - `w` — записать изменения и выйти.
            
        - `q` — выйти без сохранения.
            
- **parted:** Более современная утилита, поддерживает изменение размера разделов. Может работать как в интерактивном, так и в командном режиме.
    
    - `sudo parted /dev/sdb mklabel gpt` (создать GPT)
        
    - `sudo parted /dev/sdb mkpart primary ext4 0% 20GB` (создать раздел)
        

**4. Создание разделов (Практика)**

- **Процесс в fdisk:**
    
    1. Запуск: `sudo fdisk /dev/sdb`
        
    2. `g` — создаем новую GPT таблицу (если диск новый).
        
    3. `n` — создаем новый раздел.
        
    4. Указываем размер: `+20G` (20 ГБ), `+500M`, `+50%` (половина свободного места).
        
    5. При необходимости меняем тип (`t`), например, для swap (код 19).
        
    6. `p` — проверяем.
        
    7. `w` — записываем.
        
- **Формула размера:** `+размер` (`+10G`, `+500M`, `+2T`).
    

**5. Удаление и изменение разделов (Осторожно!)**

- **Удаление:** Внутри fdisk: `d` -> выбрать номер раздела -> `w`.
    
- **Изменение размера:** Сложная операция. **Обязательно делать резервную копию!**
    
    - **Увеличение раздела ext4:**
        
        1. Размонтировать: `umount /dev/sdb1`
            
        2. Проверить ФС: `e2fsck -f /dev/sdb1`
            
        3. Увеличить раздел в parted: `sudo parted /dev/sdb resizepart 1 40GB`
            
        4. Увеличить ФС: `resize2fs /dev/sdb1`
            
    - **Уменьшение:** Сначала уменьшаем файловую систему (`resize2fs /dev/sdb1 20G`), потом раздел.
        

**6. Полезные команды и советы**

- **Выравнивание (alignment):** Современные утилиты автоматически выравнивают разделы для оптимальной производительности SSD (начинают с сектора 2048). Проверка: `sudo parted /dev/sda align-check optimal 1`.
    
- **Типы разделов:** Коды в fdisk (19 — Linux swap, 20 — Linux filesystem).
    
- **Применить изменения без перезагрузки:** `sudo partprobe /dev/sdb`.
    
- **Бэкап таблицы разделов:** `sudo sfdisk -d /dev/sda > backup.txt`.
    
- **Восстановление:** `sudo sfdisk /dev/sda < backup.txt`.
