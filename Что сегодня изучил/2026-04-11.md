### Саммари 1: Git Reset vs Git Revert — отмена изменений

**Фундаментальное различие:**

||`git reset`|`git revert`|
|---|---|---|
|**Что делает**|Перемещает указатель ветки назад (удаляет коммиты из истории)|Создаёт новый коммит, отменяющий изменения старого|
|**Изменяет историю?**|Да|Нет|
|**Безопасен для публичных веток?**|Нет|Да|
|**Результат**|Коммиты исчезают из истории ветки|История сохраняется + новый "отменяющий" коммит|

bash

# reset — перемотка истории
A---B---C---D     # было
A---B             # после reset --hard HEAD~2
# revert — создание отменяющего коммита
A---B---C---D---C'   # C' отменяет изменения коммита C

**Три режима `git reset`:**

|Режим|Указатель ветки|Индекс (staging)|Рабочая директория|
|---|---|---|---|
|`--soft`|перемещается|сохраняется|не меняется|
|`--mixed` (по умолчанию)|перемещается|очищается|не меняется|
|`--hard`|перемещается|очищается|очищается|

bash

git reset --soft HEAD~1    # отменить коммит, изменения в индексе
git reset HEAD~1           # отменить коммит, изменения в рабочей директории
git reset --hard HEAD~1    # ПОЛНОСТЬЮ удалить коммит и изменения

**Базовое использование `git revert`:**

bash

git revert HEAD            # отменить последний коммит
git revert abc123def       # отменить конкретный коммит
git revert HEAD~3..HEAD    # отменить диапазон коммитов

**Revert merge-коммитов (важно!):**

bash

# merge-коммит имеет двух родителей
git revert -m 1 M    # отменить merge, сохранить изменения из main
git revert -m 2 M    # отменить merge, сохранить изменения из feature

**Когда что использовать:**

|Ситуация|Решение|
|---|---|
|Коммит только локальный, не опубликован|`reset`|
|Нужно реорганизовать последние коммиты|`reset --soft` + новый коммит|
|Синхронизация с удалённой веткой|`reset --hard origin/main`|
|Коммит уже в общей ветке (main, develop)|`revert`|
|Отмена в середине публичной истории|`revert`|
|Нужно сохранить полную историю изменений|`revert`|

**Восстановление после ошибочного reset:**

bash

git reflog                 # найти коммит до reset
git reset --hard HEAD@{1}  # вернуться

**Правила безопасности:**

1. **Никогда не используйте `reset` для опубликованных коммитов**
    
2. Всегда проверяйте `git status` перед `reset --hard`
    
3. Делайте backup-ветку перед опасными операциями
    
4. Для общих веток используйте только `revert`
    

**Итог:** `reset` переписывает историю (опасно для публичных веток), `revert` сохраняет историю (безопасно). Если сомневаетесь — используйте `revert`.

### Саммари 2: Git Stash — временное хранилище изменений

**Что такое stash:**  
Механизм, который сохраняет текущие незакоммиченные изменения в специальное временное хранилище, позволяя вернуть рабочую директорию к чистому состоянию (как последний коммит). Затем изменения можно восстановить.

bash

git stash                    # сохранить изменения
git stash pop                # восстановить и удалить из stash
git stash apply              # восстановить, оставив в stash

**Что сохраняется по умолчанию:**

- Изменения в отслеживаемых файлах (modified)
    
- Изменения в индексе (staged)
    

**Что НЕ сохраняется:**

- Неотслеживаемые файлы (untracked) — требуют флага `-u`
    
- Игнорируемые файлы — требуют флага `-a`
    

**Основные команды:**

|Команда|Действие|
|---|---|
|`git stash push -m "описание"`|Сохранить с понятным описанием|
|`git stash list`|Показать все сохранённые stash|
|`git stash show stash@{1}`|Показать содержимое stash|
|`git stash show -p stash@{1}`|Детальный diff|
|`git stash apply stash@{2}`|Применить конкретный stash|
|`git stash drop stash@{1}`|Удалить конкретный stash|
|`git stash clear`|Удалить все stash|
|`git stash branch <имя> stash@{1}`|Создать ветку из stash|

**Продвинутые возможности:**

- `git stash push -p` — интерактивный выбор изменений для stash
    
- `git stash push -u` — включить неотслеживаемые файлы
    
- `git stash push src/file.js` — сохранить только указанные файлы
    
- `git stash push --keep-index` — сохранить всё, кроме уже добавленных в индекс
    

**Типичные сценарии:**

1. **Срочное переключение задач** — сохранить WIP, исправить баг, вернуться
    
2. **Перенос изменений между ветками** — stash → переключиться → pop
    
3. **Эксперименты без коммитов** — сохранить состояние перед экспериментом
    

**Разрешение конфликтов при pop/apply:**

bash

# Если возник конфликт
git stash drop               # stash не удаляется автоматически
# разрешить конфликт вручную
git add <файлы>
git stash drop               # удалить stash вручную

**Восстановление потерянного stash:**

bash

git fsck --unreachable | grep commit | xargs git log --merges --no-walk --grep=WIP
git stash store -m "Recovered" <commit-hash>

**Практические советы:**

- Всегда добавляйте описание (`-m "..."`)
    
- Используйте `apply` вместо `pop` при неуверенности
    
- Регулярно чистите список старых stash
    
- Для долгосрочного хранения создавайте ветку, а не stash
