## Основные инструкции Dockerfile

|Инструкция|Назначение|Пример|
|---|---|---|
|`FROM`|Базовый образ (первая строка)|`FROM python:3.11-slim`|
|`WORKDIR`|Рабочая директория (аналог `cd`)|`WORKDIR /app`|
|`COPY`|Копирование файлов с хоста|`COPY . .`|
|`ADD`|COPY + распаковка `.tar.gz` + URL|`ADD archive.tar.gz /` (редко)|
|`RUN`|Команда **на этапе сборки** (создаёт слой)|`RUN pip install -r requirements.txt`|
|`ENV`|Переменные окружения (сборка + runtime)|`ENV APP_ENV=production`|
|`EXPOSE`|Декларация порта (документация, не публикует!)|`EXPOSE 8080`|
|`CMD`|Команда по умолчанию (легко переопределить)|`CMD ["python", "app.py"]`|
|`ENTRYPOINT`|Точка входа (сложно переопределить)|`ENTRYPOINT ["python"]`|

---

## CMD vs ENTRYPOINT — ключевое различие

||`CMD`|`ENTRYPOINT`|
|---|---|---|
|Переопределить при `docker run`|Да (полностью)|Нет (только добавить аргументы)|
|Типичное использование|Аргументы по умолчанию|Исполняемый файл|

**Пример совместного использования:**

dockerfile

ENTRYPOINT ["python", "app.py"]
CMD ["--port", "8080"]

Запуск: `docker run my-image --port 9090` → выполнится `python app.py --port 9090`

## Shell Form vs Exec Form (очень важно!)

|Формат|Синтаксис|Что запускается|PID 1|Приём сигналов|
|---|---|---|---|---|
|**Shell** (плохо)|`CMD python app.py`|`/bin/sh -c "python app.py"`|`sh`|Нет (не доходит до приложения)|
|**Exec** (хорошо)|`CMD ["python", "app.py"]`|`python app.py` напрямую|ваше приложение|Да|

**⚠️ Всегда используйте Exec form (квадратные скобки) для `CMD` и `ENTRYPOINT`!**

## Контекст сборки и `.dockerignore`

При `docker build .` Docker CLI архивирует **ВСЕ** файлы в папке и отправляет демону.

**`.dockerignore`** — исключает ненужное (работает как `.gitignore`):

text

.git
node_modules
*.log
tmp/
.env

## Оптимизация кэширования — порядок инструкций

**Плохо (кэш не работает):**

dockerfile

COPY . .                       # копируем всё (меняется часто)
RUN pip install -r requirements.txt   # переустанавливается при любом изменении кода

**Хорошо (кэш работает):**

dockerfile

COPY requirements.txt .        # копируем только зависимости
RUN pip install -r requirements.txt   # пока requirements.txt не изменился — кэш!
COPY . .                       # код копируем в последнюю очередь

**Правило:** самое редко меняющееся — выше, часто меняющееся — ниже.

## Multi-Stage Builds — многоэтапная сборка

**Проблема:** Для компиляции Go/C++ нужны компиляторы (сотни МБ), для запуска готового бинарника — нет.

**Решение:** Разделяем на этапы.

dockerfile

# ЭТАП 1: Сборка (большой образ с компиляторами)
FROM golang:1.19 AS builder
WORKDIR /app
COPY . .
RUN go build -o myapp main.go
# ЭТАП 2: Продакшн (маленький образ)
FROM alpine:latest
WORKDIR /root/
COPY --from=builder /app/myapp .
CMD ["./myapp"]

**Результат:** 800 МБ → 10 МБ

## Безопасность: не работайте от root

dockerfile

RUN adduser -D myuser   # Alpine
# или RUN useradd -m myuser (Debian/Ubuntu)
USER myuser

## Минимизация слоёв: объединяйте команды

**Плохо (3 слоя + мусор остаётся):**

dockerfile

RUN apt-get update
RUN apt-get install -y curl
RUN rm -rf /var/lib/apt/lists/*

**Хорошо (1 слой + мусор удалён):**

dockerfile

RUN apt-get update && apt-get install -y curl && rm -rf /var/lib/apt/lists/*

## Итог: чеклист хорошего Dockerfile

|✅|Правило|
|---|---|
||Конкретная версия в `FROM` (не `latest`)|
||`WORKDIR` задан|
||Сначала копируются зависимости, потом код|
||Тяжёлые операции (`RUN pip install`) — после копирования зависимостей|
||`RUN` команды объединены (`&&`)|
||`CMD` / `ENTRYPOINT` в **Exec form** (`["cmd", "arg"]`)|
||Есть `.dockerignore`|
||Multi-stage для компилируемых языков|
||Пользователь non-root (`USER`)|
