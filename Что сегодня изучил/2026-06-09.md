# Саммари статей по сетевым основам: OSI, TCP/UDP, DNS, TTL, HTTP

## Статья 1: OSI и TCP/IP — модели сетевого взаимодействия

### OSI — 7 уровней (теоретическая модель)

| Уровень | Название                     | Что делает                      | Примеры                     |
| ------- | ---------------------------- | ------------------------------- | --------------------------- |
| 7       | Application (Прикладной)     | Интерфейс для приложений        | HTTP, HTTPS, SSH, DNS, SMTP |
| 6       | Presentation (Представления) | Кодирование, шифрование, сжатие | SSL/TLS, JPEG, JSON         |
| 5       | Session (Сеансовый)          | Управление сессиями             | NetBIOS, RPC                |
| 4       | Transport (Транспортный)     | Доставка между приложениями     | **TCP, UDP**                |
| 3       | Network (Сетевой)            | Маршрутизация между сетями      | **IP, ICMP**                |
| 2       | Data Link (Канальный)        | Передача между соседними узлами | Ethernet, Wi-Fi, MAC        |
| 1       | Physical (Физический)        | Биты по проводам/радио          | Кабели, разъёмы, частоты    |

### TCP/IP — 4 уровня (реальная модель)

| Уровень TCP/IP | Что делает               | Соответствие OSI |
| -------------- | ------------------------ | ---------------- |
| Application    | Всё, что выше транспорта | 5, 6, 7          |
| Transport      | TCP, UDP                 | 4                |
| Internet       | IP, ICMP, маршрутизация  | 3                |
| Network Access | Ethernet, Wi-Fi, ARP     | 1, 2             |

### Инкапсуляция

Каждый уровень добавляет свой заголовок: данные → сегмент (TCP) → пакет (IP) → фрейм (Ethernet) → биты

### Траблшутинг по уровням (снизу вверх)

- **L1-2:** `ip link show`, кабель подключён?
    
- **L3:** `ping 8.8.8.8`, `ip route`
    
- **L4:** `ss -tln`, `telnet host port`
    
- **L7:** `curl -v`, логи приложения

## Статья 2: TCP и UDP — транспортный уровень

### Сравнение

| Характеристика    | TCP                    | UDP                    |
| ----------------- | ---------------------- | ---------------------- |
| Соединение        | Есть (3-way handshake) | Нет                    |
| Гарантия доставки | Да                     | Нет                    |
| Порядок пакетов   | Гарантирован           | Не гарантирован        |
| Скорость          | Медленнее              | Быстрее                |
| Заголовок         | 20-60 байт             | 8 байт                 |
| Использование     | HTTP, SSH, базы данных | DNS, видео, игры, VoIP |

### TCP: трёхстороннее рукопожатие

text

Клиент → Сервер: SYN (seq=100)
Сервер → Клиент: SYN-ACK (seq=300, ack=101)
Клиент → Сервер: ACK (seq=101, ack=301)

### Состояния TCP (важные)

- **LISTEN** — сервер ждёт соединения
    
- **ESTABLISHED** — активное соединение
    
- **TIME_WAIT** — закрыто, ждёт таймаут (нормально при высокой нагрузке)
    
- **CLOSE_WAIT** — другая сторона закрыла, наше приложение не закрыло сокет (**баг!**)
    

### Диагностика: `ss`

bash

ss -tlnp        # слушающие TCP-порты с процессами
ss -t state established   # соединения в ESTABLISHED
ss -t state time-wait     # соединения в TIME_WAIT

### Типичные проблемы

- **Connection refused** → сервис не запущен или порт закрыт
    
- **Connection timed out** → файрвол или сеть
    
- **Много CLOSE_WAIT** → баг в приложении (не закрывает сокеты)

## Статья 3: DNS — Domain Name System

### Что такое DNS

Распределённая база данных, превращающая доменные имена в IP-адреса. Иерархическая система: корень → TLD → домен → поддомен.

### Типы DNS-записей

| Тип       | Назначение                                                    | Пример                                                |
| --------- | ------------------------------------------------------------- | ----------------------------------------------------- |
| **A**     | IPv4 адрес                                                    | `example.com. IN A 93.184.216.34`                     |
| **AAAA**  | IPv6 адрес                                                    | `example.com. IN AAAA 2606:2800:...`                  |
| **CNAME** | Алиас на другое имя                                           | `www.example.com. IN CNAME example.com.`              |
| **MX**    | Почтовый сервер                                               | `example.com. IN MX 10 mail.example.com.`             |
| **TXT**   | Текст (SPF, DKIM, верификация)                                | `example.com. IN TXT "v=spf1 ..."`                    |
| **NS**    | DNS-сервер зоны                                               | `example.com. IN NS ns1.example.com.`                 |
| **SOA**   | Метаданные зоны (серийный номер, refresh, retry, expire, TTL) | —                                                     |
| **PTR**   | Reverse DNS (IP → имя)                                        | `34.216.184.93.in-addr.arpa. IN PTR example.com.`     |
| **SRV**   | Местоположение сервиса                                        | `_sip._tcp.example.com. IN SRV 10 60 5060 sipserver.` |
| **CAA**   | Разрешённые CA для сертификатов                               | `example.com. IN CAA 0 issue "letsencrypt.org"`       |

### Диагностика: `dig`

bash

dig example.com                    # A-запись
dig example.com MX                 # MX-записи
dig @8.8.8.8 example.com           # запрос к конкретному DNS
dig +trace example.com             # полный путь резолвинга
dig -x 93.184.216.34               # reverse DNS

### Коды ответов

- `NOERROR` — успех
    
- `NXDOMAIN` — домен не существует
    
- `SERVFAIL` — ошибка сервера

## Статья 4: TTL — Time To Live (два разных понятия)

### IP TTL vs DNS TTL

||IP TTL|DNS TTL|
|---|---|---|
|**Что это**|Счётчик хопов в IP-пакете|Время кэширования DNS-записи|
|**Единица измерения**|Хопы (переходы)|Секунды|
|**Где находится**|Заголовок IP-пакета|DNS-ответ|
|**Что при нуле**|Пакет отбрасывается, ICMP Time Exceeded|Резолвер запрашивает заново|
|**Зачем нужен**|Защита от петель маршрутизации|Баланс между актуальностью и нагрузкой|

### IP TTL

- Начальные значения: Linux=64, Windows=128, macOS=64, Cisco=255
    
- `traceroute` работает благодаря TTL: отправляет пакеты с TTL=1,2,3...
    

### DNS TTL

- Типичные значения: 60 (миграция), 300 (часто меняется), 3600 (стандарт), 86400 (стабильные)
    
- **Перед миграцией снижай TTL заранее!** Иначе часть трафика будет идти на старый IP весь старый TTL.
    

### Посмотреть DNS TTL

bash

dig example.com
# example.com.    3600    IN  A   93.184.216.34
#                 ^^^^ TTL в секундах

## Статья 5: HTTP — протокол веба

### Структура HTTP-запроса

text

GET /api/users?page=1 HTTP/1.1
Host: api.example.com
Content-Type: application/json
Authorization: Bearer token123

### Методы HTTP

| Метод  | Назначение              | Идемпотентный |
| ------ | ----------------------- | ------------- |
| GET    | Получить ресурс         | Да            |
| POST   | Создать ресурс          | Нет           |
| PUT    | Заменить ресурс целиком | Да            |
| PATCH  | Частично обновить       | Нет           |
| DELETE | Удалить ресурс          | Да            |

### Коды ответов (важные)

| Код     | Значение                             |
| ------- | ------------------------------------ |
| **200** | OK                                   |
| **201** | Created                              |
| **204** | No Content                           |
| **301** | Moved Permanently (навсегда)         |
| **302** | Found (временно)                     |
| **400** | Bad Request                          |
| **401** | Unauthorized (кто ты?)               |
| **403** | Forbidden (знаю, но нельзя)          |
| **404** | Not Found                            |
| **429** | Too Many Requests (rate limit)       |
| **500** | Internal Server Error                |
| **502** | Bad Gateway (бэкенд ответил странно) |
| **503** | Service Unavailable                  |
| **504** | Gateway Timeout (бэкенд не ответил)  |

### Версии HTTP

- **HTTP/1.1** — текстовый, keep-alive, но head-of-line blocking
    
- **HTTP/2** — бинарный, мультиплексирование, сжатие заголовков
    
- **HTTP/3** — поверх QUIC (UDP), нет head-of-line blocking
    

### Диагностика: `curl`

bash

curl -v https://example.com          # verbose (заголовки + тело)
curl -I https://example.com          # только заголовки
curl -X POST -d '{"name":"John"}' -H "Content-Type: application/json" URL
curl -H "Authorization: Bearer token" URL
curl -L URL                          # следовать редиректам
curl -k https://self-signed.com      # игнорировать TLS (только тест!)

### Заголовки (важные)

**Запрос:**

- `Host` — обязателен
    
- `Content-Type` — тип тела (`application/json`)
    
- `Authorization` — токен (`Bearer xxx`)
    
- `Accept` — что клиент принимает
    
- `User-Agent` — информация о клиенте
    

**Ответ:**

- `Content-Type` — тип ответа
    
- `Cache-Control` — кэширование (`max-age=3600`, `no-cache`, `no-store`)
    
- `Location` — URL для редиректа
    
- `Set-Cookie` — установка куки
    

### HTTPS = HTTP + TLS

- Шифрует трафик, обеспечивает конфиденциальность и аутентификацию
    
- Частые проблемы: истёк сертификат, несовпадение домена
