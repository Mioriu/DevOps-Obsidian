## Статья 1: Inventory — описание инфраструктуры

### Что такое Inventory

Файл, в котором перечислены серверы, их адреса и группировка. Ansible использует его, чтобы знать, к каким хостам подключаться.

### INI-формат (простой и популярный)

ini

[webservers]
web1 ansible_host=192.168.1.10
web2 ansible_host=192.168.1.11
[databases]
db1 ansible_host=192.168.1.20
db2 ansible_host=192.168.1.21
[monitoring]
prometheus ansible_host=192.168.1.30

- `[группа]` — название группы
    
- `web1` — алиас (имя внутри Ansible)
    
- `ansible_host` — IP или домен
    

Если хост доступен по DNS, можно просто:

ini

[webservers]
web1.example.com
web2.example.com

### YAML-формат (структурированный)

yaml

all:
  children:
    webservers:
      hosts:
        web1:
          ansible_host: 192.168.1.10
        web2:
          ansible_host: 192.168.1.11
    databases:
      hosts:
        db1:
          ansible_host: 192.168.1.20
        db2:
          ansible_host: 192.168.1.21

**Какой выбрать:** INI — для небольших проектов, YAML — для больших с вложенными группами.

### Группы и дочерние группы

ini

[prod_webservers]
prod-web1 ansible_host=10.0.1.10
prod-web2 ansible_host=10.0.1.11
[prod_databases]
prod-db1 ansible_host=10.0.1.20
[staging_webservers]
staging-web1 ansible_host=10.0.2.10
[staging_databases]
staging-db1 ansible_host=10.0.2.20
[prod:children]
prod_webservers
prod_databases
[staging:children]
staging_webservers
staging_databases
[webservers:children]
prod_webservers
staging_webservers
[databases:children]
prod_databases
staging_databases

Синтаксис `[prod:children]` — группа `prod` состоит из дочерних групп.

**Теперь можно:**

- `prod` — все продакшн-серверы
    
- `webservers` — все веб-серверы (и prod, и staging)
    
- `staging_databases` — только базы данных стейджинга
    

### Встроенные группы

- **`all`** — все хосты из inventory
    
- **`ungrouped`** — хосты, не входящие ни в одну группу
    

### Переменные хостов

ini

[webservers]
web1 ansible_host=192.168.1.10 ansible_port=2222 http_port=8080
web2 ansible_host=192.168.1.11 http_port=80

**Встроенные переменные:**

- `ansible_host` — IP/домен
    
- `ansible_port` — SSH-порт (по умолч. 22)
    
- `ansible_user` — пользователь
    
- `ansible_ssh_private_key_file` — путь к ключу
    
- `ansible_python_interpreter` — путь к Python
    

### Переменные групп

ini

[webservers]
web1 ansible_host=192.168.1.10
web2 ansible_host=192.168.1.11
[webservers:vars]
ansible_user=deploy
http_port=80
nginx_version=1.24

### `host_vars` и `group_vars` — отдельные файлы

Структура:

text

├── ansible.cfg
├── inventory.ini
├── group_vars/
│   ├── all.yml
│   └── webservers.yml
└── host_vars/
    └── web1.yml

**`group_vars/webservers.yml`:**

yaml

ansible_user: deploy
http_port: 80
nginx_version: "1.24"

**`group_vars/all.yml`:**

yaml

ntp_server: ntp.example.com
dns_servers:
  - 8.8.8.8
  - 8.8.4.4

**`host_vars/web1.yml`:**

yaml

http_port: 8080
ssl_enabled: true

**Приоритет переменных:** чем конкретнее, тем выше приоритет.

- `host_vars` → перебивает `group_vars`
    
- `group_vars/группа` → перебивает `group_vars/all`
    

### Визуализация inventory

bash

ansible-inventory --graph

text

@all:
  |--@prod:
  |  |--@prod_webservers:
  |  |  |--prod-web1
  |  |  |--prod-web2
  |  |--@prod_databases:
  |  |  |--prod-db1
  |--@staging:
  |  |--@staging_webservers:
  |  |  |--staging-web1
  |  |--@staging_databases:
  |  |  |--staging-db1
  |--@ungrouped:

bash

ansible-inventory --list      # полный JSON со всеми переменными
ansible-inventory --host web1 # переменные конкретного хоста

## Статья 2: Ad-hoc команды

### Общий синтаксис

bash

ansible <хосты> -m <модуль> -a "<аргументы>"

### Модуль `command` (по умолчанию)

bash

ansible all -a "uptime"
ansible all -a "df -h"
ansible all -a "free -m"

**Ограничение:** не работает с пайпами, перенаправлениями, переменными окружения.

### Модуль `shell` (с шеллом)

bash

ansible all -m shell -a "cat /var/log/syslog | tail -20"
ansible all -m shell -a "echo 'hello' > /tmp/test.txt"
ansible all -m shell -a "echo $HOME"

**Правило:** `command` — если не нужны пайпы/перенаправления; `shell` — если нужны.

### Модуль `copy`

bash

# Копирование файла
ansible all -m copy -a "src=./nginx.conf dest=/etc/nginx/nginx.conf owner=root group=root mode=0644"
# Создание файла с содержимым
ansible all -m copy -a "content='Hello from Ansible\n' dest=/tmp/hello.txt"

**Важно:** `mode=0644` — всегда с нулём в начале!

### Модуль `file`

bash

# Создать директорию
ansible all -m file -a "path=/opt/myapp state=directory owner=root group=root mode=0755"
# Удалить
ansible all -m file -a "path=/tmp/garbage state=absent"
# Создать симлинк
ansible all -m file -a "src=/opt/myapp/current dest=/opt/myapp/latest state=link"

### Модули `apt` и `yum`

bash

# Установка (Ubuntu/Debian)
ansible all -m apt -a "name=nginx state=present update_cache=yes"
# Удаление
ansible all -m apt -a "name=nginx state=absent"
# Конкретная версия
ansible all -m apt -a "name=nginx=1.24.0-1~jammy state=present"
# CentOS/RHEL
ansible all -m yum -a "name=nginx state=present"

### Модуль `service`

bash

# Запустить
ansible all -m service -a "name=nginx state=started"
# Остановить
ansible all -m service -a "name=nginx state=stopped"
# Перезапустить (всегда!)
ansible all -m service -a "name=nginx state=restarted"
# Включить автозагрузку
ansible all -m service -a "name=nginx enabled=yes"
# Комбо
ansible all -m service -a "name=nginx state=started enabled=yes"

**Важно:** `started`/`stopped` — идемпотентны. `restarted` — нет.

### Модуль `user`

bash

# Создать пользователя
ansible all -m user -a "name=deploy shell=/bin/bash createhome=yes"
# Добавить в группы
ansible all -m user -a "name=deploy groups=sudo append=yes"
# Удалить
ansible all -m user -a "name=olduser state=absent remove=yes"

**Важно:** `append=yes` — добавляет в группы, не заменяя существующие.

### Модуль `authorized_key`

bash

ansible all -m authorized_key -a "user=deploy key='ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI... new_guy@company' state=present"

### Параллелизм — `-f`

bash

ansible all -m ping -f 20     # 20 серверов параллельно

По умолчанию — 5. Можно изменить в `ansible.cfg`: `forks = 20`

### Become — выполнение с sudo

bash

ansible all -m apt -a "name=htop state=present" -b
ansible all -m apt -a "name=htop state=present" -b -K   # с паролем

- `-b` (`--become`) — выполнять с правами root
    
- `-K` (`--ask-become-pass`) — спросить пароль sudo
    

### Практические кейсы

bash

# Остановить сервис на всех серверах
ansible webservers -m service -a "name=problematic-service state=stopped" -f 20
# Проверить место на диске
ansible all -m shell -a "df -h / | tail -1"
# Найти большие логи
ansible problem_server -m shell -a "du -sh /var/log/* | sort -rh | head -10"
# Массовое обновление пакета
ansible all -m apt -a "name=openssl state=latest" -b
# Перезагрузка пачками по 5
ansible all -m reboot -a "reboot_timeout=300" -f 5

### Полезные флаги

bash

--limit "server1,server2"   # только указанные хосты
--check                      # dry run (ничего не менять)
-v, -vv, -vvv               # подробный вывод

## Статья 3: Первый playbook

### Структура playbook'а (YAML)

**Правила YAML:**

- **Только пробелы, никогда табы**
    
- **Стандартный отступ — 2 пробела**
    
- Списки — с тире: `- элемент`
    
- Словари — `ключ: значение`
    

### Простейший playbook

yaml

---
- name: Настройка веб-серверов
  hosts: webservers
  become: true
  tasks:
    - name: Установить nginx
      apt:
        name: nginx
        state: present
        update_cache: yes
    - name: Запустить nginx
      service:
        name: nginx
        state: started
        enabled: yes

### Play

yaml

- name: Настройка веб-серверов
  hosts: webservers
  become: true

- `name` — описание play
    
- `hosts` — на каких серверах выполнять
    
- `become: true` — выполнять с правами sudo
    

Можно несколько play'ев в одном файле:

yaml

---
- name: Настройка веб-серверов
  hosts: webservers
  become: true
  tasks: ...
- name: Настройка баз данных
  hosts: databases
  become: true
  tasks: ...

### Tasks

yaml

tasks:
  - name: Установить nginx
    apt:
      name: nginx
      state: present
      update_cache: yes

- `name` — описание задачи (обязательно!)
    
- `apt` — модуль, дальше его параметры
    

Задачи выполняются последовательно. При ошибке — остановка.

### Модуль `debug`

yaml

- name: Вывести приветствие
  debug:
    msg: "Привет! Ansible работает на хосте {{ inventory_hostname }}"
- name: Вывести информацию об ОС
  debug:
    msg: "ОС: {{ ansible_os_family }}, Версия: {{ ansible_distribution_version }}"
- name: Вывести все IP-адреса
  debug:
    var: ansible_all_ipv4_addresses

- `{{ }}` — синтаксис Jinja2 (переменные)
    
- `msg` — произвольный текст
    
- `var` — вывод конкретной переменной
    

### Идемпотентность

Первый запуск — `changed`, второй — `ok` (ничего не меняет).

**Плохо (неидемпотентно):**

yaml

- name: Добавить строку в конфиг
  shell: echo "server_name example.com;" >> /etc/nginx/conf.d/site.conf

**Хорошо:** использовать специальный модуль (`lineinfile`, `copy` и т.д.).

**Правило:** если есть модуль — используйте его, а не `shell`/`command`.

### Запуск playbook'а

bash

ansible-playbook playbook.yml
ansible-playbook -i inventory.ini playbook.yml

### Полезные флаги `ansible-playbook`

bash

--check           # dry run (ничего не менять)
--diff            # показать разницу в файлах
--limit server1   # выполнить только на server1
-v, -vv, -vvv     # подробный вывод

**Лучшая комбинация для ревью:**

bash

ansible-playbook playbook.yml --check --diff

### Полноценный пример

yaml

---
- name: Базовая настройка сервера
  hosts: all
  become: true
  gather_facts: true
  tasks:
    - name: Обновить кэш пакетов
      apt:
        update_cache: yes
        cache_valid_time: 3600
    - name: Установить базовые пакеты
      apt:
        name:
          - htop
          - curl
          - wget
          - git
          - vim
          - net-tools
          - unzip
        state: present
    - name: Создать пользователя deploy
      user:
        name: deploy
        shell: /bin/bash
        groups: sudo
        append: yes
        createhome: yes
    - name: Закинуть SSH-ключ
      authorized_key:
        user: deploy
        key: "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI... ваш_ключ"
        state: present
    - name: Настроить sudo без пароля
      copy:
        content: "deploy ALL=(ALL) NOPASSWD:ALL\n"
        dest: /etc/sudoers.d/deploy
        owner: root
        group: root
        mode: "0440"
    - name: Установить nginx
      apt:
        name: nginx
        state: present
    - name: Запустить и включить nginx
      service:
        name: nginx
        state: started
        enabled: yes
    - name: Вывести IP-адрес
      debug:
        msg: "Сервер {{ inventory_hostname }} настроен. IP: {{ ansible_default_ipv4.address }}"

---

## Итог

1. **Inventory** — описывает серверы и группы (INI или YAML). Поддерживает вложенные группы, переменные хостов/групп, отдельные файлы `host_vars`/`group_vars`.
    
2. **Ad-hoc** — быстрые одноразовые команды. `command` (без шелла) vs `shell` (с шеллом). Модули: `copy`, `file`, `apt/yum`, `service`, `user`, `authorized_key`.
    
3. **Playbooks** — описывают состояние системы (YAML). Идемпотентность — ключевое свойство. `ansible-playbook` с флагами `--check`, `--diff`, `--limit`.
