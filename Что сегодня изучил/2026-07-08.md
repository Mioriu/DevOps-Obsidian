# Саммари по Nginx

## Установка и статус

bash

apt update && apt install nginx -y
systemctl status nginx   # active (running)

## Структура конфигов

text

/etc/nginx/
├── nginx.conf              # главный файл (обычно не трогаем)
├── conf.d/                 # *.conf — всё подключается
├── sites-available/        # все конфиги сайтов
└── sites-enabled/          # симлинки на активные

### `nginx.conf` — основные настройки

nginx

user www-data;
worker_processes auto;
pid /run/nginx.pid;
events {
    worker_connections 1024;
}
http {
    include /etc/nginx/mime.types;
    include /etc/nginx/conf.d/*.conf;
    include /etc/nginx/sites-enabled/*;
}

**Смысл:** `nginx.conf` — каркас, который подключает через `include` все остальные конфиги.

### `conf.d/` vs `sites-available/ + sites-enabled/`

|Подход|Как работает|
|---|---|
|`conf.d/`|Всё, что там лежит — активно. Просто и прямолинейно|
|`sites-available/` + `sites-enabled/`|Конфиги в `available`, симлинки на активные в `enabled`|

**Активация сайта (для Debian/Ubuntu):**

bash

ln -s /etc/nginx/sites-available/mysite.conf /etc/nginx/sites-enabled/

## Блок `server` — виртуальный хост

nginx

server {
    listen 80;
    server_name example.com www.example.com;
    root /var/www/example.com;
    index index.html;
    location / {
        try_files $uri $uri/ =404;
    }
}

### `listen` — порт

nginx

listen 80;              # HTTP
listen 443 ssl;         # HTTPS
listen [::]:80;         # IPv6

### `server_name` — доменное имя

nginx

server_name example.com www.example.com;
server_name *.example.com;        # вайлдкард
server_name _;                     # дефолтный сервер (ловит всё)

`server_name _` — «ловушка» для всех запросов, которые не попали под другие `server_name`.

### `root` и `index`

nginx

root /var/www/example.com;          # корневая директория
index index.html index.htm;         # файл по умолчанию для директорий

### `location` — маршрутизация

nginx

# Префиксный матч
location /static/ {
    expires 30d;
    add_header Cache-Control "public, immutable";
}
# Регулярное выражение (регистронезависимый)
location ~* \.(jpg|jpeg|png|gif|ico|svg)$ {
    expires 7d;
}
# Прокси на бэкенд
location /api/ {
    proxy_pass http://127.0.0.1:8080;
}
# SPA-приложение
location / {
    try_files $uri $uri/ /index.html;
}

**Приоритет location:**

1. Точный `=`
    
2. Приоритетный префикс `^~`
    
3. Регулярные выражения `~`, `~*`
    
4. Обычный префикс
    

### `try_files`

nginx

try_files $uri $uri/ =404;              # пробует файл → директорию → 404
try_files $uri $uri/ /index.html;       # для SPA (если не найден — отдаём index.html)

## Reverse proxy — `proxy_pass`

nginx

server {
    listen 80;
    server_name app.example.com;
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

**Важно:** эти 4 заголовка всегда ставьте при проксировании — без них бэкенд не увидит реальный IP клиента и оригинальный хост.

nginx

# Прокси на другой сервер
proxy_pass http://10.0.1.15:8080;
# Прокси на Unix-сокет (Gunicorn, PHP-FPM)
proxy_pass http://unix:/var/run/app.sock;
# Балансировка
upstream backend {
    server 10.0.1.10:8080;
    server 10.0.1.11:8080;
    server 10.0.1.12:8080;
}
location / {
    proxy_pass http://backend;
}

## reload vs restart

|Команда|Что делает|Когда использовать|
|---|---|---|
|`systemctl reload nginx`|Плавный перезапуск воркеров, без потери соединений|**Всегда** после изменения конфига|
|`systemctl restart nginx`|Убивает все процессы и запускает заново, рвёт соединения|Только если Nginx завис|

**На продакшене всегда `reload`, никогда `restart`.**

## Проверка конфига — `nginx -t`

**Обязательное правило:** перед любым `reload` проверяйте синтаксис.

bash

nginx -t

text

nginx: configuration file /etc/nginx/nginx.conf syntax is ok
nginx: configuration file /etc/nginx/nginx.conf test is successful

Если ошибка — видно файл и строку.

**Правильная последовательность:**

text

edit → nginx -t → systemctl reload nginx

## Логи — `access.log` и `error.log`

### access.log — кто и что запрашивал

`/var/log/nginx/access.log`

text

93.184.216.34 - - [29/Jan/2025:14:22:15 +0000] "GET /api/users HTTP/1.1" 200 1532 "https://example.com/" "Mozilla/5.0..."

**Полезные переменные в формате лога:**

nginx

log_format main '$remote_addr - $remote_user [$time_local] '
                '"$request" $status $body_bytes_sent '
                '"$http_referer" "$http_user_agent" '
                '$request_time $upstream_response_time';

- `$request_time` — общее время обработки запроса Nginx
    
- `$upstream_response_time` — сколько ждал ответ от бэкенда
    

### error.log — ошибки

`/var/log/nginx/error.log`

text

2025/01/29 14:25:03 [error] 1234#1234: *5678 connect() failed (111: Connection refused) while connecting to upstream, client: 93.184.216.34, upstream: "http://127.0.0.1:8080/api/users"

**Это первое место для диагностики.**

Уровни: `debug`, `info`, `notice`, `warn`, `error`, `crit`, `alert`, `emerg`

### Ротация логов

Логи — главный пожиратель места. logrotate настраивается автоматически при установке.

bash

cat /etc/logrotate.d/nginx   # проверить

## Полезные команды

bash

nginx -t                          # проверка синтаксиса
nginx -T                          # весь результирующий конфиг (с include-ами)
systemctl reload nginx            # применить изменения без даунтайма
systemctl status nginx            # статус + последние строки лога
# Живые логи
tail -f /var/log/nginx/access.log
tail -f /var/log/nginx/error.log
# Топ IP по запросам
awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -20
# Топ URL с 500-ми ошибками
awk '$9 == 500 {print $7}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -20

## Шпаргалка

|Что нужно|Команда|
|---|---|
|Установить|`apt install nginx`|
|Проверить синтаксис|`nginx -t`|
|Применить конфиг|`systemctl reload nginx`|
|Статус|`systemctl status nginx`|
|Логи ошибок|`tail -f /var/log/nginx/error.log`|
|Логи доступа|`tail -f /var/log/nginx/access.log`|
|Включить сайт (Debian)|`ln -s /etc/nginx/sites-available/site.conf /etc/nginx/sites-enabled/`|
|Отключить сайт|`rm /etc/nginx/sites-enabled/site.conf`|
