# Саммари статей по Docker: Базовые команды и взаимодействие с контейнерами

## Статья 1: Основные команды Docker

### Базовые команды для повседневной работы

|Команда|Назначение|Пример|
|---|---|---|
|`docker run`|Запуск контейнера|`docker run -d --name mynginx -p 8080:80 nginx`|
|`docker ps`|Список запущенных контейнеров|`docker ps -a` (включая остановленные)|
|`docker stop`|Остановка контейнера|`docker stop mynginx`|
|`docker rm`|Удаление контейнера|`docker rm mynginx`|
|`docker pull`|Скачать образ из реестра|`docker pull node:14`|
|`docker images`|Список локальных образов|`docker images`|
|`docker rmi`|Удалить образ|`docker rmi node:14`|

### Важные флаги `docker run`

|Флаг|Назначение|Пример|
|---|---|---|
|`-d`|Запуск в фоновом режиме (detached)|`docker run -d nginx`|
|`-p хост:контейнер`|Проброс портов|`-p 8080:80` (localhost:8080 → порт 80 контейнера)|
|`--name`|Задать имя контейнеру|`--name mynginx`|
|`-e KEY=VALUE`|Переменные окружения|`-e ENV=prod`|

### Дополнительные команды

|Команда|Назначение|
|---|---|
|`docker kill`|Резко завершить контейнер (SIGKILL, без шанса на корректное закрытие)|
|`docker rename`|Переименовать контейнер|
|`docker port`|Показать проброшенные порты|
|`docker inspect`|Детальная информация о контейнере в JSON|
|`docker logs`|Посмотреть логи контейнера (stdout/stderr)|

### Пример использования `docker logs`

bash

docker logs mynginx          # показать логи
docker logs -f mynginx       # следить за логами в реальном времени (follow)

### Итог

Минимальный набор команд без которых не обойтись:

- `run` → запустить
    
- `ps -a` → посмотреть
    
- `stop`/`rm` → остановить/удалить
    
- `pull`/`images`/`rmi` → управление образами
    
- `logs` → отладка

## Статья 2: Взаимодействие с запущенным контейнером

### `docker exec` — выполнение команд внутри контейнера

bash

docker exec <контейнер> <команда>
# Пример: выполнить ls внутри контейнера
docker exec mynginx ls -l /usr/share/nginx/html

### Интерактивный доступ (попасть внутрь контейнера как в SSH)

bash

docker exec -it mynginx /bin/bash

- `-i` (interactive) — интерактивный режим
    
- `-t` (pseudo-TTY) — эмуляция терминала
    
- `/bin/bash` — оболочка (для Alpine может быть `/bin/sh`)
    

Внутри контейнера можно выполнять команды. Выход — `exit`.

**Важно:** `docker exec` создаёт **новый процесс** в контейнере, не мешая основному.

### `docker attach` vs `docker exec`

|Команда|Что делает|Когда использовать|
|---|---|---|
|`docker attach`|Подключается к **главному процессу** контейнера|Редко (видите stdout главного процесса)|
|`docker exec -it`|Создаёт **новый процесс** (shell)|Всегда для отладки и администрирования|

### `docker cp` — копирование файлов

**Синтаксис:**

bash

# Хост → контейнер
docker cp <локальный_путь> <контейнер>:<путь_в_контейнере>
# Контейнер → хост
docker cp <контейнер>:<путь_в_контейнере> <локальный_путь>

**Примеры:**

bash

# Копируем файл в контейнер
docker cp index.html mynginx:/usr/share/nginx/html/index.html
# Копируем файл из контейнера
docker cp mynginx:/usr/share/nginx/html/index.html ./index_from_container.html

**Ограничение:** если контейнер удалён, скопированные файлы (без томов) исчезают. `docker cp` — для быстрого обмена, не для постоянного хранения.

### Поиск контейнера

Если контейнера нет в `docker ps` (возможно, остановлен):

bash

docker ps -a    # показать все контейнеры (включая остановленные)

### Итог

- `docker exec -it <контейнер> bash` — зайти внутрь контейнера (shell)
    
- `docker cp` — копировать файлы туда/обратно
    
- `docker attach` — используется редко (подключение к главному процессу)
    

Теперь вы можете не только запускать контейнеры, но и заходить внутрь для отладки, а также обмениваться файлами с хостом.
