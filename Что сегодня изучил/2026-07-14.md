## Статья 1: Переменные в Ansible

### Зачем нужны переменные

Чтобы не хардкодить значения в playbook'ах. Один playbook работает на разных окружениях (dev, staging, prod) с разными настройками.

### `vars` — переменные прямо в playbook'е

yaml

---
- name: Настройка веб-сервера
  hosts: webservers
  become: true
  vars:
    http_port: 80
    app_name: myapp
    app_user: deploy
    packages:
      - nginx
      - curl
      - htop
  tasks:
    - name: Установить пакеты
      apt:
        name: "{{ packages }}"
        state: present
    - name: Создать пользователя
      user:
        name: "{{ app_user }}"
        shell: /bin/bash

**Важно:** если значение начинается с `{{ }}`, его нужно брать в кавычки:

yaml

name: "{{ app_user }}"   # ПРАВИЛЬНО
name: {{ app_user }}     # НЕПРАВИЛЬНО

### `vars_files` — переменные в отдельном файле

yaml

---
- name: Настройка веб-сервера
  hosts: webservers
  become: true
  vars_files:
    - vars/main.yml
    - vars/secrets.yml

**`vars/main.yml`:**

yaml

---
http_port: 80
app_name: myapp
app_user: deploy
app_dir: /opt/myapp

### `host_vars` и `group_vars` — переменные для хостов и групп

Структура:

text

├── ansible.cfg
├── inventory.ini
├── group_vars/
│   ├── all.yml
│   └── webservers.yml
└── host_vars/
    └── server1.yml

**`group_vars/webservers.yml`** — для всех хостов группы `webservers`:

yaml

---
http_port: 80
nginx_worker_processes: 4

**`group_vars/all.yml`** — для всех хостов:

yaml

---
ntp_server: ntp.company.local
dns_servers:
  - 8.8.8.8
  - 8.8.4.4

**`host_vars/server1.yml`** — только для `server1`:

yaml

---
http_port: 8080
custom_domain: server1.company.com

### Приоритет переменных (от низкого к высокому)

1. `defaults` роли — самый низкий
    
2. `group_vars/all`
    
3. `group_vars/конкретная_группа`
    
4. `host_vars`
    
5. `vars` в play
    
6. `vars` в task
    
7. **`-e` / `--extra-vars`** — самый высокий (перебивает всё)
    

**Правило:** чем конкретнее место, тем выше приоритет.

### Extra vars — из командной строки

bash

ansible-playbook playbook.yml -e "app_version=2.1.0 deploy_env=production"
ansible-playbook playbook.yml -e "@vars/release.yml"

### Факты — информация о серверах

Ansible автоматически собирает информацию с серверов через модуль `setup`.

**Просмотр фактов:**

bash

ansible server1 -m setup
ansible server1 -m setup -a "filter=ansible_distribution*"
ansible server1 -m setup -a "filter=ansible_mem*"
ansible server1 -m setup -a "filter=ansible_default_ipv4"

**Часто используемые факты:**

- `ansible_hostname` — имя хоста
    
- `ansible_fqdn` — полное доменное имя
    
- `ansible_default_ipv4.address` — основной IPv4
    
- `ansible_distribution` — дистрибутив (Ubuntu, CentOS)
    
- `ansible_distribution_version` — версия ОС
    
- `ansible_os_family` — семейство ОС (Debian, RedHat)
    
- `ansible_memtotal_mb` — общая память в МБ
    
- `ansible_processor_cores` — количество ядер
    
- `ansible_mounts` — смонтированные диски
    

**Использование фактов:**

yaml

- name: Информация о сервере
  debug:
    msg: "ОС: {{ ansible_distribution }} {{ ansible_distribution_version }}, Ядер: {{ ansible_processor_cores }}"
- name: Установить пакет в зависимости от ОС
  apt:
    name: nginx
    state: present
  when: ansible_os_family == "Debian"
- name: Установить на RedHat
  yum:
    name: nginx
    state: present
  when: ansible_os_family == "RedHat"

**Отключение сбора фактов** (ускоряет выполнение):

yaml

- name: Простая задача
  hosts: all
  gather_facts: false
  tasks:
    - name: Пингуем
      ping:

### Кастомные факты

Файлы на целевом сервере в `/etc/ansible/facts.d/`.

**Статический факт (`/etc/ansible/facts.d/app.fact`):**

ini

[general]
app_name = myapp
app_version = 2.1.0
environment = production

**Доступ в playbook'е:** `ansible_local.app.general.app_name`

### Переменные из `register`

Сохраняет результат выполнения задачи в переменную:

yaml

- name: Проверить версию nginx
  command: nginx -v
  register: nginx_result
  changed_when: false
- name: Показать версию
  debug:
    msg: "Nginx: {{ nginx_result.stderr }}"
- name: Показать код возврата
  debug:
    msg: "Код возврата: {{ nginx_result.rc }}"

**Что лежит в зарегистрированной переменной:**

- `stdout` — стандартный вывод
    
- `stderr` — вывод ошибок
    
- `rc` — код возврата
    
- `changed` — изменилось ли что-то

## Статья 2: Шаблоны (Templates)

### Модуль `template`

Работает как `copy`, но перед копированием прогоняет файл через шаблонизатор Jinja2.

yaml

- name: Сгенерировать конфиг nginx
  template:
    src: templates/nginx.conf.j2
    dest: /etc/nginx/nginx.conf
    owner: root
    group: root
    mode: "0644"
  notify: Перезагрузить nginx

### Синтаксис Jinja2

**Переменные — `{{ }}`:**

jinja2

server_name {{ domain }};
listen {{ http_port }};
root {{ app_dir }}/public;

**Условия — `{% if %}`:**

jinja2

{% if ssl_enabled %}
listen 443 ssl;
ssl_certificate {{ ssl_cert_path }};
{% else %}
listen 80;
{% endif %}

**Проверка существования переменной:**

jinja2

{% if custom_error_page is defined %}
error_page 500 502 503 504 {{ custom_error_page }};
{% endif %}

**Циклы — `{% for %}`:**

jinja2

{% for server in upstream_servers %}
    server {{ server.host }}:{{ server.port }} weight={{ server.weight | default(1) }};
{% endfor %}

**Комментарии — `{# #}`** (не попадают в итоговый файл):

jinja2

{# Этот комментарий не попадёт в итоговый файл #}

### Фильтры

|Фильтр|Назначение|Пример|
|---|---|---|
|`default`|Значение по умолчанию|`{{ http_port \| default(80) }}`|
|`join`|Склеить список в строку|`{{ dns_servers \| join(' ') }}`|
|`to_json` / `to_yaml`|Сериализация|`{{ data \| to_json }}`|
|`regex_replace`|Замена по регулярке|`{{ url \| regex_replace('^https?://', '') }}`|
|`int` / `round`|Математика|`{{ (mem / 4) \| int }}`|
|`upper` / `lower`|Регистр|`{{ hostname \| upper }}`|

### Пример шаблона nginx.conf

jinja2

# {{ ansible_managed }}
user www-data;
worker_processes {{ nginx_worker_processes | default(ansible_processor_cores) }};
pid /run/nginx.pid;
events {
    worker_connections {{ nginx_worker_connections | default(1024) }};
}
http {
    sendfile on;
    tcp_nopush on;
    keepalive_timeout 65;
    types_hash_max_size 2048;
    include /etc/nginx/mime.types;
    default_type application/octet-stream;
    access_log /var/log/nginx/access.log;
    error_log /var/log/nginx/error.log;
{% for site in nginx_sites %}
    server {
        listen {{ site.port | default(80) }};
        server_name {{ site.domain }};
{% if site.ssl | default(false) %}
        listen 443 ssl;
        ssl_certificate /etc/ssl/certs/{{ site.domain }}.crt;
        ssl_certificate_key /etc/ssl/private/{{ site.domain }}.key;
{% endif %}
        location / {
            proxy_pass http://{{ site.upstream_host }}:{{ site.upstream_port }};
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
{% if site.websocket | default(false) %}
            proxy_http_version 1.1;
            proxy_set_header Upgrade $http_upgrade;
            proxy_set_header Connection "upgrade";
{% endif %}
        }
    }
{% endfor %}
}

**Переменные (`group_vars/webservers.yml`):**

yaml

nginx_worker_processes: 4
nginx_worker_connections: 2048
nginx_sites:
  - domain: app.company.com
    port: 80
    upstream_host: 127.0.0.1
    upstream_port: 8080
    ssl: false
  - domain: api.company.com
    port: 80
    upstream_host: 127.0.0.1
    upstream_port: 3000
    ssl: true
    websocket: true

## Статья 3: Handlers

### Проблема, которую решают handlers

Если перезагружать сервис после каждого изменения конфига, это происходит даже когда ничего не изменилось. Handlers выполняются **только если их позвала задача, которая реально что-то изменила** (статус `changed`).

### Как это работает

yaml

---
- name: Настройка nginx
  hosts: webservers
  become: true
  tasks:
    - name: Сгенерировать основной конфиг nginx
      template:
        src: nginx.conf.j2
        dest: /etc/nginx/nginx.conf
      notify: Перезагрузить nginx
    - name: Скопировать конфиг сайта
      template:
        src: site.conf.j2
        dest: /etc/nginx/conf.d/site.conf
      notify: Перезагрузить nginx
  handlers:
    - name: Перезагрузить nginx
      service:
        name: nginx
        state: reloaded

**Порядок выполнения:**

1. Задачи выполняются все (независимо от того, изменилось что-то или нет)
    
2. В конце Ansible смотрит, есть ли помеченные handlers
    
3. Если есть — выполняет их **один раз** (даже если notify было из нескольких задач)
    

**Важно:** handlers выполняются в том порядке, в котором описаны в секции `handlers`, а не в порядке вызова через `notify`.
