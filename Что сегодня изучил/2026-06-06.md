[[Task_5]] [[Разбор тестового с пайтон веб-приложенем]] 

## Основная идея

**Multi-arch образы** — один образ, содержащий версии для разных архитектур процессоров (`amd64`, `arm64`, `arm/v7`). Docker автоматически выбирает нужную версию при `pull`.

## Проблема, которую решает Multi-Arch

|Ситуация|Проблема|
|---|---|
|Образ собран на Mac M1 (ARM)|Не запустится на обычном Linux-сервере (amd64)|
|Образ собран на Intel/AMD (x86_64)|Не запустится на Raspberry Pi (ARM)|

**Решение:** Собрать один образ, который работает везде.

## Основные архитектуры

|Архитектура|Альтернативные имена|Где используется|
|---|---|---|
|`linux/amd64`|x86_64, x64|Intel/AMD серверы, обычные ПК|
|`linux/arm64`|aarch64, arm64v8|Mac M1/M2, AWS Graviton|
|`linux/arm/v7`|armhf, armv7l|Raspberry Pi 2/3/4 (32-bit)|
|`linux/arm/v6`|armel, armv6l|Raspberry Pi Zero/1|

**Для продакшена:** `linux/amd64` + `linux/arm64`

## Docker Buildx

**Buildx** — расширение Docker для multi-arch сборки. Включён по умолчанию в Docker Desktop.

bash

docker buildx version          # проверка
docker buildx ls               # список билдеров и поддерживаемых архитектур

## Создание билдера для multi-arch

bash

# Создать билдер с поддержкой эмуляции
docker buildx create --name multiarch-builder --driver docker-container --bootstrap
# Использовать его
docker buildx use multiarch-builder
# Проверить
docker buildx inspect --bootstrap

## Сборка multi-arch образа

### Базовая команда (обязательно с `--push`)

bash

docker buildx build \
  --platform linux/amd64,linux/arm64 \
  -t YOUR_USERNAME/myapp:latest \
  --push \
  .

**⚠️ Важно:** Multi-arch образы нельзя сохранить локально (только с `--load` для одной архитектуры). Нужно пушить в registry.

### Вариант 1: Локальная сборка (одна архитектура, для теста)

bash

docker buildx build \
  --platform linux/amd64 \
  -t myapp:local \
  --load \
  .

### Вариант 2: Multi-arch с пушем в Docker Hub

bash

docker login
docker buildx build \
  --platform linux/amd64,linux/arm64 \
  -t YOUR_USERNAME/multiarch-demo:latest \
  --push \
  .

### Вариант 3: Экспорт в файл (без пуша)

bash

docker buildx build \
  --platform linux/amd64,linux/arm64 \
  -t multiarch-demo:latest \
  -o type=oci,dest=./multiarch-demo.tar \
  .

## Проверка multi-arch образа

bash

# Посмотреть все архитектуры в образе
docker buildx imagetools inspect YOUR_USERNAME/multiarch-demo:latest
# Проверить архитектуру локального образа
docker image inspect myapp:latest --format '{{.Architecture}}'
# Проверить архитектуру внутри контейнера
docker run --rm myapp:latest uname -m

## Как это работает

**QEMU эмуляция:** Buildx использует QEMU для эмуляции других архитектур.

bash

# Установка эмуляторов (если нужно)
docker run --rm --privileged multiarch/qemu-user-static --reset -p yes

**Manifest List:** Multi-arch образ — это специальный список (`manifest list`), содержащий ссылки на образы для разных платформ. Docker при `pull` выбирает подходящий.

## Команды для работы с Buildx

|Команда|Назначение|
|---|---|
|`docker buildx ls`|Список билдеров|
|`docker buildx create --name NAME`|Создать билдер|
|`docker buildx use NAME`|Переключиться на билдер|
|`docker buildx inspect NAME`|Информация о билдере|
|`docker buildx rm NAME`|Удалить билдер|
|`docker buildx prune`|Очистить кэш|
|`docker buildx use default`|Вернуться к стандартному билдеру|

## Оптимизация (кэширование)

bash

docker buildx build \
  --platform linux/amd64,linux/arm64 \
  --cache-from type=registry,ref=myapp:buildcache \
  --cache-to type=registry,ref=myapp:buildcache,mode=max \
  -t myapp:latest \
  --push \
  .

## Практическое задание (из урока)

bash

cd d5
# Собрать локально для своей архитектуры
docker buildx build \
  --platform linux/amd64 \
  -t multiarch-demo:local \
  --load \
  .
# Запустить
docker run -d -p 8080:8080 multiarch-demo:local
# Открыть http://localhost:8080 — должна отображаться текущая архитектура

## Итог

|Ключевой момент|Суть|
|---|---|
|**Multi-arch**|Один образ для всех архитектур|
|**Buildx**|Инструмент для multi-arch сборки|
|**`--push`**|Обязательно для публикации multi-arch образа|
|**QEMU**|Эмуляция других архитектур|
|**Manifest list**|Формат, объединяющий образы для разных платформ|
|**Best practice**|Собирать `linux/amd64` + `linux/arm64` (самые популярные)|
