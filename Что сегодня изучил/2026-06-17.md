## Статья 1: Структура файловой системы Linux

### Всё есть файл

В Linux всё абстрагируется через файлы: обычные файлы, директории, диски, сетевые интерфейсы, процессы, память. Работа с системой сводится к чтению и записи файлов.

### Иерархия директорий

| Директория | Назначение                                   | Примеры                                                                                    |
| ---------- | -------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `/`        | Корень файловой системы                      | —                                                                                          |
| `/etc`     | Конфигурационные файлы системы и сервисов    | `nginx.conf`, `resolv.conf`, `hosts`, `passwd`, `shadow`, `systemd/`                       |
| `/var`     | Переменные данные (часто жрут место)         | `/var/log/` — логи, `/var/lib/docker/` — данные Docker, `/var/lib/postgresql/` — данные БД |
| `/home`    | Домашние директории пользователей            | `/home/devops/.bashrc`, `/home/devops/.ssh/`                                               |
| `/root`    | Домашняя директория root (не в `/home`)      | —                                                                                          |
| `/tmp`     | Временные файлы (удаляются при перезагрузке) | —                                                                                          |
| `/opt`     | Стороннее ПО (не из репозиториев)            | `/opt/grafana/`                                                                            |
| `/usr`     | Пользовательские программы                   | `/usr/bin/` — бинарники, `/usr/local/` — софт из исходников                                |
| `/proc`    | Виртуальная ФС процессов (на лету)           | `/proc/cpuinfo`, `/proc/meminfo`, `/proc/[PID]/`                                           |
| `/sys`     | Виртуальная ФС ядра (железо, драйверы)       | `/sys/block/` — информация о дисках                                                        |

### Переменная PATH

Когда вы вводите команду, система ищет бинарник в директориях из `$PATH`.

Посмотреть PATH:

bash

echo $PATH
# /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

Добавить директорию в PATH (текущая сессия):

bash

export PATH=$PATH:/opt/terraform

Сохранить навсегда: добавить в `~/.bashrc` или `~/.bash_profile`.

Полезные команды:

bash

which nginx     # полный путь до бинарника
whereis nginx   # путь + конфиги + man-страницы

## Статья 2: Типы файловых систем, иноды и монтирование

### Типы файловых систем

| ФС          | Особенности                                                                              | Когда использовать                              |
| ----------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------- |
| **ext4**    | Самая распространённая, стабильная, журналируемая. Макс. файл 16 ТБ, фиксированные иноды | Универсальные серверы, дефолтный выбор          |
| **XFS**     | Лучше для больших файлов, параллельный I/O. Иноды динамические, нельзя уменьшить раздел  | Базы данных, видеохранилища, интенсивная запись |
| **tmpfs**   | Живёт в RAM, очень быстро, данные теряются при перезагрузке                              | `/tmp`, `/dev/shm`, `/run`                      |
| **overlay** | Накладывает read-only слой + read-write слой поверх                                      | Docker (слои образов)                           |

### Inodes

**Inode** — структура данных, хранящая метаинформацию о файле: владелец, права, размер, время, указатели на блоки данных. **Имя файла не хранится в inode.**

Количество инодов ограничено. На ext4 фиксируется при создании ФС. На XFS динамическое.

**Ошибка:** `df -h` показывает свободное место, но `touch test.txt` выдаёт `No space left on device` — кончились иноды.

Диагностика:

bash

df -i        # использование инодов

Типичная причина: миллионы мелких файлов (сессии, кэш, мелкие логи).

### Команда mount

Примонтировать диск:

bash

mount /dev/sdb1 /mnt/data

Посмотреть смонтированные разделы:

bash

mount | grep "^/dev"
lsblk

Размонтировать:

bash

umount /mnt/data          # не "unmount"!

Если `target is busy`:

bash

lsof +D /mnt/data         # найти процессы, использующие директорию
umount -l /mnt/data       # ленивое размонтирование

Опции монтирования:

bash

mount -o ro /dev/sdb1 /mnt/data      # read-only
mount -o rw,noexec /dev/sdb1 /mnt/data   # без права выполнения
mount -t xfs /dev/sdb1 /mnt/data     # явно указать тип

### /etc/fstab — автомонтирование при загрузке

Формат строки:

text

<device> <mountpoint> <type> <options> <dump> <pass>

Пример:

text

UUID=a1b2c3d4... / ext4 defaults 0 1
UUID=f9e8d7c6... /data xfs defaults,nofail 0 2
tmpfs /tmp tmpfs defaults,size=2G 0 0

**Важно:** всегда используйте `UUID` вместо `/dev/sdb1`, потому что имена устройств могут меняться.

Узнать UUID:

bash

blkid /dev/sdb1

Проверить fstab перед перезагрузкой:

bash

mount -a

**Если сервер не загружается из-за ошибки в fstab:**

bash

# В emergency mode
mount -o remount,rw /
vi /etc/fstab   # исправить ошибку
reboot

**`nofail`** — если диск не примонтировался, загрузка продолжается.

### Классический сценарий подключения нового диска

text

lsblk → fdisk (создать раздел) → mkfs (форматировать) → mount → добавить в fstab

## Статья 3: RAID и LVM

### RAID — отказоустойчивость и скорость

|Уровень|Принцип|Минимум дисков|Доступный объём|Скорость|Отказоустойчивость|
|---|---|---|---|---|---|
|**RAID 0**|Чередование (striping)|2|100%|Высокая|❌ Нет|
|**RAID 1**|Зеркалирование|2|50%|Чтение выше, запись как у одного диска|✅ 1 диск|
|**RAID 5**|Чередование + parity|3|(N-1)×размер|Запись медленнее|✅ 1 диск|
|**RAID 10**|RAID 1 + RAID 0|4|50%|Высокая|✅ до 2 дисков (по одному в каждой паре)|

**Для каких задач:**

- **RAID 1** — системный раздел (ОС)
    
- **RAID 5** — файловые хранилища, логи, некритичные данные
    
- **RAID 10** — базы данных (скорость + надёжность)
    

### LVM — Logical Volume Manager

Позволяет управлять дисковым пространством гибко: расширять разделы на лету, добавлять диски без даунтайма.

**Три уровня LVM:**

|Уровень|Аббревиатура|Что это|
|---|---|---|
|Physical Volume|PV|Физический диск или раздел|
|Volume Group|VG|Пул из одного или нескольких PV|
|Logical Volume|LV|Логический раздел (то, что монтируем)|

**Базовые команды:**

bash

pvs           # информация о PV
vgs           # информация о VG
lvs           # информация о LV
pvdisplay     # подробно о PV
vgdisplay     # подробно о VG
lvdisplay     # подробно о LV

**Создание LVM:**

bash

pvcreate /dev/sdb /dev/sdc
vgcreate vg_main /dev/sdb /dev/sdc
lvcreate -L 200G -n lv_data vg_main
mkfs.ext4 /dev/vg_main/lv_data
mount /dev/vg_main/lv_data /data

**Расширение раздела без даунтайма:**

Если в VG есть свободное место:

bash

lvextend -L +50G --resizefs /dev/vg_main/lv_data

Если в VG нет места, но есть новый диск:

bash

pvcreate /dev/sdd
vgextend vg_main /dev/sdd
lvextend -L +100G --resizefs /dev/vg_main/lv_data

**Уменьшение раздела (осторожно, XFS не поддерживает!):**

bash

umount /data
e2fsck -f /dev/vg_main/lv_data          # проверка ФС
resize2fs /dev/vg_main/lv_data 150G     # уменьшаем ФС
lvreduce -L 150G /dev/vg_main/lv_data   # уменьшаем LV
mount /data

Порядок важен: сначала ФС, потом LV. Наоборот — потеря данных.
