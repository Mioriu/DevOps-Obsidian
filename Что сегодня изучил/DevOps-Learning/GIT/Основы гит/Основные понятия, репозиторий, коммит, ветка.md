Три базовых понятия формируют основу работы с Git: репозиторий, коммит и ветка. Понимание этих концепций необходимо для эффективного использования системы контроля версий.

### Репозиторий

Репозиторий — это место, где Git хранит всю информацию о проекте. Физически это обычная папка проекта, в которой создана специальная скрытая директория `.git`.

При инициализации репозитория Git создаёт следующую структуру:

```cmake
project/
├── .git/          # Служебная папка Git
│   ├── objects/   # Хранилище всех версий файлов
│   ├── refs/      # Информация о ветках
│   ├── HEAD       # Указатель текущего положения
│   └── config     # Настройки репозитория
├── src/           # Файлы проекта
├── docs/          # Файлы проекта
└── README.md      # Файлы проекта
```

Папка `.git` содержит всю историю изменений, все версии файлов и метаинформацию. Остальное содержимое папки — это рабочие файлы проекта, которые можно редактировать обычным способом.

Существует два типа репозиториев:

**Обычный репозиторий** содержит и рабочие файлы, и историю изменений. Используется для повседневной работы над проектом.

**Голый репозиторий** содержит только историю без рабочих файлов. Применяется на серверах (GitHub, GitLab) для хранения кода, так как на сервере никто не редактирует файлы напрямую.

### Коммит

Коммит — это зафиксированное состояние проекта в определённый момент времени. Каждый коммит содержит:

- Полный снимок всех файлов проекта на момент создания коммита
- Уникальный идентификатор (хеш) — например, `a5f3b8c`
- Информацию об авторе и времени создания
- Описание изменений (сообщение коммита)
- Ссылку на предыдущий коммит (родителя)

Пример информации о коммите:

```sql
commit a5f3b8c7d9e2f1a4b6c8d0e3f5a7b9c1d3e5f7a9
Author: Anna Petrova <anna@example.com>
Date:   Mon Mar 15 10:30:00 2024 +0300

    Исправлена ошибка валидации в форме регистрации
```

Важная особенность: коммиты в Git неизменяемы. После создания коммит нельзя изменить. Любая попытка изменения (даже исправление опечатки в описании) приведёт к созданию нового коммита с новым идентификатором.

Коммиты связаны между собой в цепочку через ссылки на родителей. Так формируется история проекта:

```css
[Коммит 1] ← [Коммит 2] ← [Коммит 3] ← [Коммит 4]
```

### Ветка

Ветка — это именованный указатель на определённый коммит. Технически ветка представляет собой простой текстовый файл, содержащий идентификатор коммита.

Основные характеристики веток:

- Создание ветки не копирует файлы или историю
- При создании нового коммита ветка автоматически передвигается на него
- Можно создавать неограниченное количество веток
- Переключение между ветками изменяет содержимое рабочей папки

Стандартная ветка в новом репозитории называется `main` или `master`. Дополнительные ветки создаются для разработки новых функций, исправления ошибок или экспериментов.

Специальный указатель **HEAD** показывает текущее положение в репозитории. Обычно HEAD указывает на активную ветку, которая указывает на последний коммит.

```css
HEAD → main → a5f3b8c
```

### Как компоненты работают вместе

Репозиторий предоставляет инфраструктуру для хранения данных. Внутри репозитория создаются коммиты, которые формируют историю изменений. Ветки служат именованными указателями на коммиты и позволяют организовать параллельную разработку.

Типичный процесс работы:

1. В репозитории есть ветка `main`, указывающая на последний коммит
2. Создаётся новая ветка `feature` для разработки новой функции
3. В ветке `feature` создаются новые коммиты
4. Ветка `feature` автоматически передвигается на новые коммиты
5. Ветка `main` остаётся на прежнем месте
6. После завершения работы изменения из `feature` вливаются в `main`

Схема работы с ветками:

```css
       [C3] ← [C4] ← feature
      /
[C1] ← [C2] ← main
```

### Практическое значение

Понимание этих концепций критически важно для работы с Git. Знание структуры репозитория помогает понять, где хранятся данные и почему удаление `.git` приводит к потере истории. Понимание природы коммитов объясняет, почему нельзя изменить прошлое без последствий. Осознание того, что ветки — это просто указатели, снимает опасения при их создании и удалении.

## Итог

Репозиторий, коммит и ветка — фундаментальные концепции Git. Репозиторий хранит все данные проекта в директории `.git`. Коммит фиксирует состояние проекта с полной информацией об изменениях. Ветка предоставляет удобный способ навигации по истории и организации параллельной разработки. Эти простые, но мощные концепции позволяют Git эффективно управлять проектами любой сложности.
