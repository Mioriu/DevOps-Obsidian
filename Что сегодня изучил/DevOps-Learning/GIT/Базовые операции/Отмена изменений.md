В процессе разработки часто возникает необходимость отменить внесённые изменения. Git предоставляет несколько инструментов для возврата файлов к предыдущему состоянию, каждый из которых предназначен для определённого сценария.

### Эволюция команд отмены

Исторически для отмены изменений использовалась команда `git checkout`, которая выполняла множество разных функций. Начиная с версии Git 2.23, функциональность была разделена на более специализированные команды: `git restore` для восстановления файлов и `git switch` для переключения веток. Старые команды продолжают работать для обратной совместимости.

### Восстановление файлов — git restore

Команда `git restore` предназначена для восстановления файлов в рабочей директории или индексе. Это основной современный инструмент для отмены изменений.

#### Отмена изменений в рабочей директории

Для отмены незакоммиченных изменений в файле:

```ruby
# Восстановить файл до состояния последнего коммита
$ git restore README.md

# Восстановить несколько файлов
$ git restore file1.txt file2.txt

# Восстановить все файлы в директории
$ git restore src/

# Восстановить все изменённые файлы
$ git restore .
```

После выполнения команды все изменения в указанных файлах будут потеряны, файлы вернутся к состоянию последнего коммита.

#### Отмена изменений в индексе

Если изменения уже добавлены в индекс командой `git add`, их можно убрать оттуда:

```ruby
# Убрать файл из индекса, сохранив изменения в рабочей директории
$ git restore --staged README.md

# Убрать все файлы из индекса
$ git restore --staged .

# Убрать из индекса и отменить изменения в рабочей директории
$ git restore --staged --worktree README.md
```

#### Восстановление из конкретного коммита

Можно восстановить файлы не из последнего коммита, а из любого другого:

```shell
# Восстановить файл из конкретного коммита
$ git restore --source=HEAD~2 README.md

# Восстановить файл из другой ветки
$ git restore --source=feature-branch config.json

# Восстановить удалённый файл
$ git restore --source=HEAD~1 deleted-file.txt
```

### Классический подход — git checkout

Команда `git checkout` до сих пор широко используется для отмены изменений, особенно в старых проектах и документации.

```ruby
# Отменить изменения в файле (аналог git restore)
$ git checkout -- README.md

# Восстановить файл из конкретного коммита
$ git checkout HEAD~2 -- README.md

# Восстановить все файлы
$ git checkout -- .
```

Двойное тире `--` важно — оно отделяет имена файлов от других параметров команды, предотвращая неоднозначность.

### Удаление неотслеживаемых файлов — git clean

Команда `git clean` удаляет файлы, которые не находятся под контролем версий. Это полезно для очистки рабочей директории от временных файлов, результатов сборки и другого мусора.

```ruby
# Показать, какие файлы будут удалены (безопасный режим)
$ git clean -n
Would remove build/
Would remove temp.log

# Удалить неотслеживаемые файлы
$ git clean -f

# Удалить неотслеживаемые файлы и директории
$ git clean -fd

# Удалить игнорируемые файлы тоже
$ git clean -fx

# Интерактивный режим
$ git clean -i
```

Важно: `git clean` безвозвратно удаляет файлы. Всегда используйте флаг `-n` для предварительного просмотра.

### Сценарии отмены изменений

Рассмотрим типичные ситуации и подходящие команды для их решения.

#### Сценарий 1: Исправление опечатки в неотправленном файле

```shell
# Изменили файл, но ещё не добавили в индекс
$ git status
modified:   src/main.js

# Отменяем изменения
$ git restore src/main.js
```

#### Сценарий 2: Убрать файл из подготовленного коммита

```bash
# Случайно добавили лишний файл
$ git add .
$ git status
Changes to be committed:
    modified:   src/main.js
    modified:   .env  # Этот файл не должен попасть в коммит

# Убираем из индекса
$ git restore --staged .env
```

#### Сценарий 3: Полный сброс к чистому состоянию

```ruby
# Отменить все изменения в отслеживаемых файлах
$ git restore .

# Убрать все из индекса
$ git restore --staged .

# Удалить все неотслеживаемые файлы и папки
$ git clean -fd
```

#### Сценарий 4: Восстановление удалённого файла

```shell
# Файл был удалён в предыдущем коммите
$ git log --oneline -- deleted-file.txt
a5f3b8c Remove obsolete configuration
b7d9e2a Add configuration file

# Восстанавливаем из коммита, где файл ещё существовал
$ git restore --source=b7d9e2a deleted-file.txt
```

### Различия между командами

Важно понимать область действия каждой команды:

- **git restore** — работает с отслеживаемыми файлами, может восстанавливать как в рабочей директории, так и в индексе
- **git checkout -- file** — старый синтаксис для восстановления файлов в рабочей директории
- **git clean** — работает только с неотслеживаемыми файлами, удаляет их безвозвратно

### Меры предосторожности

Отмена изменений может привести к потере работы, поэтому важно соблюдать предосторожности:

**Проверка перед отменой.** Используйте `git status` и `git diff` для просмотра изменений перед их отменой.

**Создание резервной копии.** Если изменения могут понадобиться, сохраните их в отдельную ветку или создайте временный коммит.

**Осторожность с git clean.** Всегда используйте флаг `-n` для предварительного просмотра удаляемых файлов.

```ruby
# Сохранить изменения на всякий случай
$ git stash push -m "Временное сохранение перед отменой"

# Или создать временную ветку
$ git checkout -b temp-backup
$ git add .
$ git commit -m "Backup before reset"
$ git checkout main
```

## Итог

Git предоставляет гибкие инструменты для отмены изменений на разных этапах работы. `git restore` — современный способ восстановления файлов в рабочей директории и индексе. `git checkout` — классический подход, всё ещё широко используемый. `git clean` — специализированный инструмент для удаления неотслеживаемых файлов. Понимание различий между этими командами и их областей применения позволяет уверенно управлять состоянием проекта и исправлять ошибки без риска потери важных данных.
