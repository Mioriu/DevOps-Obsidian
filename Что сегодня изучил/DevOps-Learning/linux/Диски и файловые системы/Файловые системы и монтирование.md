
После создания разделов на диске нужно сделать две вещи: создать файловую систему и примонтировать раздел. В этом уроке подробно разберём оба процесса и научимся настраивать автоматическое монтирование.

### Что делает файловая система?

Файловая система добавляет структуру:

- Где начинается и заканчивается каждый файл
- Имена файлов и папок
- Права доступа и владельцы
- Время создания и изменения
- Как файлы связаны в директории

```yaml
Раздел без ФС:              Раздел с файловой системой ext4:
┌──────────────┐            ┌────────────────────────────┐
│              │            │ Суперблок                  │
│   Просто     │            ├────────────────────────────┤
│   байты      │     →      │ Таблица inodes             │
│   данных     │            ├────────────────────────────┤
│              │            │ Блоки данных с файлами     │
└──────────────┘            └────────────────────────────┘
```

### Создание файловой системы

После создания раздела он пустой — нужно создать файловую систему. Для каждой ФС есть своя команда `mkfs.*` (make filesystem).

Создание `ext4`:

```bash
# Базовая команда
$ sudo mkfs.ext4 /dev/sdb1

mke2fs 1.46.5 (30-Dec-2021)
Creating filesystem with 5242880 4k blocks and 1310720 inodes
Filesystem UUID: abc12345-6789-def0-1234-567890abcdef
Allocating group tables: done
Writing inode tables: done
Creating journal (32768 blocks): done
Writing superblocks and filesystem accounting information: done
```

Создание **других** файловых систем:

```shell
# XFS
$ sudo mkfs.xfs /dev/sdb2

# Btrfs
$ sudo mkfs.btrfs -L "Backup" /dev/sdb3

# NTFS (нужен пакет ntfs-3g)
$ sudo mkfs.ntfs -Q -L "Windows Data" /dev/sdb4

# FAT32
$ sudo mkfs.vfat -F 32 -n "USB" /dev/sdb5
```

**Внимание:** создание файловой системы уничтожает все данные в разделе.

### Монтирование: подключение к системе

Создать файловую систему — это полдела. Чтобы использовать раздел, его нужно примонтировать — подключить к дереву каталогов Linux.

### Команда mount

Основной синтаксис монтирования:

```shell
$ sudo mount [опции] устройство точка_монтирования
```

Простейший пример:

```shell
# Создаём точку монтирования (обычную директорию)
$ sudo mkdir -p /mnt/mydata

# Монтируем раздел
$ sudo mount /dev/sdb1 /mnt/mydata

# Проверяем
$ mount | grep sdb1
/dev/sdb1 on /mnt/mydata type ext4 (rw,relatime)

# Теперь можем работать с файлами
$ ls /mnt/mydata
$ echo "Тест" > /mnt/mydata/test.txt
```

### Опции монтирования

Команда `mount` поддерживает множество опций, которые контролируют поведение файловой системы:

```shell
# Монтирование только для чтения
$ sudo mount -o ro /dev/sdb1 /mnt/readonly

# Запретить выполнение программ
$ sudo mount -o noexec /dev/sdb1 /mnt/data

# Несколько опций через запятую
$ sudo mount -o ro,noexec,nosuid /dev/sdb1 /mnt/secure
```

Основные опции монтирования:

- **ro/rw** — только чтение / чтение-запись
- **noexec** — запретить выполнение программ
- **nosuid** — игнорировать SUID/SGID биты
- **nodev** — игнорировать файлы устройств
- **noatime** — не обновлять время доступа (ускоряет работу)
- **nodiratime** — не обновлять время доступа для директорий
- **sync/async** — синхронная/асинхронная запись
- **user/nouser** — разрешить/запретить монтирование обычным пользователям

Пример безопасного монтирования флешки:

```shell
# Монтируем с ограничениями безопасности
$ sudo mount -o nosuid,nodev,noexec,uid=1000,gid=1000 /dev/sdc1 /mnt/usb

# uid=1000,gid=1000 — установить владельца файлов
```

### Размонтирование

Перед извлечением устройства или отключением раздела его нужно размонтировать:

```shell
# Размонтировать по точке монтирования
$ sudo umount /mnt/mydata

# Или по устройству
$ sudo umount /dev/sdb1

# Принудительное размонтирование (опасно)
$ sudo umount -f /mnt/mydata

# "Ленивое" размонтирование (отключить, когда освободится)
$ sudo umount -l /mnt/mydata
```

Если получаете ошибку "_**target is busy**_", значит раздел используется:

```shell
# Найти процессы, использующие раздел
$ lsof /mnt/mydata

COMMAND  PID USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
bash    2341 user  cwd    DIR   8,17     4096    2 /mnt/mydata

# Или более агрессивный способ
$ fuser -vm /mnt/mydata

# Завершить все процессы, использующие раздел (осторожно!)
$ fuser -km /mnt/mydata
```

### Автоматическое монтирование через /etc/fstab

Файл `/etc/fstab` (file systems table) определяет, какие разделы монтировать **при загрузке** системы. Это текстовый файл, где каждая строка описывает одну файловую систему.

Формат строки в `fstab`:

```lua
устройство  точка_монтирования  тип_ФС  опции  dump  pass
```

Пример файла /etc/fstab:

```bash
#                         
UUID=abc123-...          /              ext4    errors=remount-ro 0      1
UUID=def456-...          /boot          ext4    defaults          0      2
UUID=789ghi-...          /home          ext4    defaults,noatime  0      2
UUID=jkl012-...          none           swap    sw                0      0
/dev/sdb1                /mnt/data      ext4    defaults,nofail   0      2
tmpfs                    /tmp           tmpfs   size=2G,nodev     0      0
```

Разберём параметры:

- **Устройство** — можно указать /dev/sdX, UUID, или LABEL
- **Точка монтирования** — куда монтировать
- **Тип ФС** — ext4, xfs, ntfs-3g и т.д.
- **Опции** — параметры монтирования
- **dump** — использовать ли для резервного копирования (обычно 0)
- **pass** — порядок проверки при загрузке (0 — не проверять, 1 — корень, 2 — остальные)

### Использование UUID вместо имён устройств

Имена устройств (`/dev/sda, /dev/sdb`) могут меняться при перезагрузке. `UUID` (Universally Unique Identifier) — это уникальный идентификатор, который **не меняется**:

```bash
# Узнать UUID всех разделов
$ blkid
/dev/sda1: UUID="1234abcd-5678-90ef-ghij-klmnopqrstuv" TYPE="ext4"
/dev/sda2: UUID="wxyz9876-5432-10ab-cdef-fedcba098765" TYPE="swap"

# Узнать UUID конкретного раздела
$ sudo blkid /dev/sdb1
/dev/sdb1: LABEL="Мои данные" UUID="abc-def-123" TYPE="ext4"

# Другой способ
$ ls -l /dev/disk/by-uuid/
```

Добавление записи в `fstab` с `UUID`:

```shell
# Редактируем fstab
$ sudo nano /etc/fstab

# Добавляем строку
UUID=abc-def-123 /mnt/data ext4 defaults,noatime 0 2

# Проверяем без перезагрузки
$ sudo mount -a   # Монтирует всё из fstab

# Если ошибок нет, всё настроено правильно
```

### Специальные опции для fstab

Некоторые полезные опции для различных сценариев:

```bash
# Для SSD диска - отключаем время доступа
UUID=xxx /home ext4 defaults,noatime,nodiratime 0 2

# Для сетевого диска - не блокировать загрузку, если недоступен
//server/share /mnt/network cifs credentials=/home/user/.smbcreds,nofail,_netdev 0 0

# Для съёмного диска - позволить пользователям монтировать
UUID=yyy /mnt/usb vfat defaults,user,noauto 0 0

# Для раздела с базой данных - синхронная запись
UUID=zzz /var/lib/mysql ext4 defaults,sync 0 2
```

### Монтирование по метке

Вместо `UUID` можно использовать метки (`labels`) — они короче и понятнее:

```shell
# Установить метку на ext4
$ sudo e2label /dev/sdb1 "MyBackup"

# Или при создании ФС
$ sudo mkfs.ext4 -L "MyBackup" /dev/sdb1

# Посмотреть метку
$ sudo e2label /dev/sdb1
MyBackup

# Монтирование по метке
$ sudo mount LABEL=MyBackup /mnt/backup

# В fstab
LABEL=MyBackup /mnt/backup ext4 defaults 0 2
```

### Bind mount — монтирование директории

Linux позволяет монтировать **не только разделы, но и директории** в другое место:

```swift
# Создать "ссылку" на директорию через монтирование
$ sudo mount --bind /home/user/projects /var/www/html

# Теперь содержимое /home/user/projects доступно и в /var/www/html

# В fstab
/home/user/projects /var/www/html none bind 0 0
```

Это полезно, когда нужно сделать директорию доступной в другом месте без символических ссылок.

### Временные файловые системы в памяти

`tmpfs` — это файловая система в оперативной памяти. Очень быстрая, но данные теряются при перезагрузке:

```bash
# Создать tmpfs размером 500MB
$ sudo mount -t tmpfs -o size=500M tmpfs /mnt/ramdisk

# В fstab для /tmp в памяти
tmpfs /tmp tmpfs defaults,noatime,mode=1777,size=2G 0 0

# Посмотреть использование tmpfs
$ df -h -t tmpfs
Filesystem      Size  Used Avail Use% Mounted on
tmpfs           2.0G   12M  2.0G   1% /tmp
tmpfs           3.9G     0  3.9G   0% /dev/shm
```
