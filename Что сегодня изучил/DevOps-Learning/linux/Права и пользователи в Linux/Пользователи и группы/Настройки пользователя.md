В Linux каждая учётная запись пользователя наследует ряд параметров: от системных настроек (например, политика паролей, умолчания при создании нового пользователя) до личной конфигурации окружения (shell, файлы в домашней директории). Для DevOps-инженера умение управлять этими настройками — важная часть обеспечения безопасности и удобства работы команды.

## 1. Файл `/etc/login.defs` и настройки по умолчанию для пользователей

### Назначение

Файл `/etc/login.defs` задаёт глобальные параметры, которые влияют на создание и обслуживание пользователей. В нём можно настроить:

- **Диапазон UID и GID** для новых аккаунтов;
- **Условия хранения паролей** (минимальное количество символов, срок действия и т.д.);
- **Параметры блокировки** учётной записи;
- **Директивы** о том, каким образом система обрабатывает логины по умолчанию.

### Структура `/etc/login.defs`

Этот файл содержит строки вида `ПАРАМЕТР значение`. Например:

```objectivec
PASS_MAX_DAYS   90
PASS_MIN_DAYS   0
PASS_WARN_AGE   7
UID_MIN         1000
UID_MAX         60000
```

- **PASS_MAX_DAYS** определяет максимальное количество дней, в течение которых пароль является действительным;
- **UID_MIN/UID_MAX** задают диапазон UID для обычных пользователей (системные пользователи обычно имеют UID ниже 1000).

### Зачем это нужно?

При добавлении нового пользователя (командой `useradd`) система может брать часть значений из `/etc/login.defs`, чтобы определить, какой UID ему выдавать, сколько дней действует пароль и т. д. Это даёт единообразие и упрощает администрирование при массовом создании учётных записей.

## 2. Использование `chage` для управления политикой паролей

### Назначение

Утилита `chage` (от _change age_) регулирует срок действия пароля, дату последней смены и уведомления пользователя о необходимости сменить пароль. Она взаимодействует с информацией в `/etc/shadow`.

### Синтаксис

```css
chage [опции] <имя_пользователя>
```

- **Опции**:
    - `-l` (list) — показать текущие настройки срока действия пароля.
    - `-d <день>` — задать дату последней смены пароля.
    - `-E <день>` — установить дату, когда учётная запись будет заблокирована (по формату YYYY-MM-DD).
    - `-M <число>` — задать максимальное число дней, через которое пароль устареет.
    - `-W <число>` — за сколько дней до истечения пароля предупреждать пользователя.

### Пример

```nginx
chage -M 90 -W 7 alice
```

- Устанавливает максимальное время действия пароля для пользователя `alice` в 90 дней и начинает предупреждать за 7 дней до истечения.

### Как это помогает?

- **Безопасность**: предотвращает ситуацию, когда у пользователя годами не меняется пароль, что повышает риск взлома.
- **Удобство**: пользователь заранее получает уведомления, успевает сменить пароль до блокировки.

## 3. Конфигурация shell и базовые настройки домашней директории

### 3.1 Конфигурация shell

При входе в систему пользователь получает окружение (environment), в котором работают все команды. Чаще всего это `bash` или `zsh`.

- **Файлы конфигурации**:
    
    - `~/.bashrc`, `~/.bash_profile` (или `~/.profile`) для Bash;
    - `~/.zshrc` для Zsh.
    
    В них задают переменные среды (`PATH`, `PS1`), алиасы, функции оболочки и прочие настройки.
- **Глобальные настройки** расположены в `/etc/bashrc`, `/etc/profile` и т. д. — применяются ко всем пользователям.

### 3.2 Базовые настройки домашней директории

Когда вы создаёте нового пользователя, система обычно копирует шаблонные файлы из `/etc/skel` в домашнюю директорию (например, `~/.bashrc`, `~/.profile`). Таким образом у пользователя появляется базовый набор конфигурационных файлов.

- **Зачем это нужно?**
    - Упростить онбординг новых сотрудников: они получают одинаковую базовую конфигурацию.
    - Раздать важные алиасы, переменные среды, настройки для Git, Docker и т. д.
- **Настройка дополнительных файлов**: иногда администраторы добавляют в `/etc/skel` свои шаблоны, чтобы автоматически выдавать при создании нового пользователя требуемый набор директорий, скриптов и README-файлов.

### Итог

Управление настройками пользователя в Linux включает в себя как глобальные параметры (через `/etc/login.defs` и `chage`), так и личные файлы конфигурации shell в домашней директории. Для DevOps-инженера это дает возможность централизованно контролировать сроки действия паролей, безопасность учётных записей и единообразие окружения для всей команды. Понимая, как устроены эти механизмы, вы сможете гибко адаптировать систему под нужды компании, не теряя при этом в безопасности и удобстве работы.
