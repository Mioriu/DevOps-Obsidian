В Linux каждая учётная запись пользователя связана не только с уникальным идентификатором (UID), но и с одной или несколькими группами (GID). Группы позволяют удобно распределять права и разграничивать доступ, когда над проектами работают несколько человек или сервисов одновременно. 

## 1. Зачем нужны группы

### Упрощённое управление правами

- В многопользовательской системе Linux права задаются для **владельца файла (user)**, **группы (group)** и **остальных (others)**.
- Когда к одному ресурсу (директории, файлу, сервису) нужен доступ сразу нескольким пользователям, проще объединить их в группу и выдать права группе, чем назначать права каждому пользователю по отдельности.
- Это особенно полезно для командной работы: например, разработчикам нужна возможность редактировать код, а тестировщикам — только читать.

### Гибкое разграничение доступа

- Группа может быть «проектной» (например, `devteam`), «функциональной» (например, `ops`) или «сервисной» (например, `jenkins`).
- Вы можете выдать группе лишь необходимые права: чтение логов, запись в каталог, исполнение скриптов и т.д., — а остальные пользователи и группы не смогут ничего менять.
- При расширении команды или запуске новых сервисов достаточно добавить новых пользователей в нужную группу, не меняя каждое право вручную.

## 2. Инструменты работы с группами

![](https://ucarecdn.stepik.net/26c5ee78-f253-4f1d-86d0-741c489d1123/)

### 2.1 `groupadd`

**Назначение**  
Создаёт новую группу в системе. Обычно указывается имя группы; при необходимости можно задать определённый GID (Group ID).

**Синтаксис**

```css
groupadd [опции] <имя_группы>
```

- **Пример**:
    
    ```nginx
    groupadd devteam
    ```
    
    Создаёт группу `devteam` с автоматически сгенерированным GID.

### 2.2 `groupdel`

**Назначение**  
Удаляет группу из системы. Применяется, когда группа больше не используется или когда нужно избежать накопления «мертвых» записей.

**Синтаксис**

```php-template
groupdel <имя_группы>
```

- **Важно**: перед удалением стоит проверить, нет ли пользователей, чьей основной группой является данная. Если она основная, необходимо сначала сменить основную группу пользователей (через `usermod`).

### 2.3 `gpasswd`

**Назначение**  
Управляет паролем группы и её членами. Когда группа защищена паролем, пользователи могут временно присоединяться к ней через команду `newgrp`, введя пароль. Это более старая модель, которая реже используется, но иногда встречается.

**Пример**

```nginx
gpasswd devteam
```

Попросит установить пароль для группы `devteam`.

Кроме того, `gpasswd -a <user> <group>` добавляет пользователя в группу, а `gpasswd -d <user> <group>` удаляет пользователя из группы.

### 2.4 `usermod -aG`

**Назначение**  
Позволяет добавить пользователя в дополнительную (вторичную) группу, не затрагивая его основную группу и прочие настройки.

**Синтаксис**

```php-template
usermod -aG <имя_группы> <имя_пользователя>
```

- **Опция `-a`** (append) означает «добавить пользователя в указанные группы, не убирая его из других». Без `-a` пользователь будет исключён из всех групп, кроме перечисленных.
- **Пример**:
    
    ```nginx
    usermod -aG devteam alice
    ```
    
    Пользователь `alice` получит дополнительный доступ, который есть у группы `devteam`.

## 3. Вторичная (дополнительная) группа

### Основная и дополнительные группы

- У каждого пользователя всегда есть **основная группа** (primary group), которая указана в `/etc/passwd` (поле GID). Чаще всего её имя совпадает с логином пользователя (например, `alice:alice`).
- Однако пользователь может принадлежать к нескольким группам одновременно. В этом случае группы, кроме основной, считаются **дополнительными** (secondary groups).

### Зачем это нужно?

- Разработчику (`devuser`), помимо основной группы `devuser`, может понадобиться доступ к группе `testers`, чтобы просматривать результаты тестов.
- Инженер DevOps может входить в группу `docker` (для управления контейнерами), а также `adm` (для чтения журналов системы).
- Подход «несколько групп» позволяет аккуратно разграничивать доступ, комбинируя роли.

### Как добавить пользователя в несколько групп

- Самый простой способ — использовать команду:
    
    ```php-template
    usermod -aG group1,group2,group3 <пользователь>
    ```
    
    Это сразу добавит пользователя в три дополнительные группы.
- Проверить, в каких группах состоит пользователь, можно командой `groups <имя_пользователя>`.

## Важные моменты для DevOps

1. **Логическое разделение окружений**
    
    - Если у вас несколько окружений (например, `staging`, `production`), вы можете иметь группы вроде `prod-deploy`, доступ к которой имеет только ограниченный круг пользователей.
    - Это снижает риск случайных изменений в продакшене.
2. **Совместная работа**
    
    - DevOps часто выделяет отдельные группы для CI/CD-агентов, мониторинга (Prometheus, Zabbix) и т.д.
    - Любые папки или файлы, к которым нужна совместная работа, можно настроить под нужную группу и выдать группе права на запись.

### Итог

Группы — это удобный механизм, позволяющий не раздавать права «штучно» каждому пользователю, а управлять доступом на уровне команд и подразделений. Зная команды `groupadd`, `groupdel`, `gpasswd` и `usermod -aG`, вы сможете быстро создавать, удалять и модифицировать группы под нужды проекта. А поддержка нескольких групп на одного пользователя даёт гибкость при разграничении ролей и обязанностей в системе.
