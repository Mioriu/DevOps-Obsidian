Одно дело — понимать модель прав `rwx` в теории, и совсем другое — уметь управлять ею на практике. В повседневной работе DevOps-инженера часто приходится мгновенно менять доступ к файлам и директориям, выдавать определённые права новому сервисному аккаунту или ограничивать доступ, чтобы избежать рисков. Для всех этих целей в Linux существуют три ключевые команды: **`chmod`**, **`chown`** и **`chgrp`**.

## 1. Команда `chmod`: управление правами доступа

![](https://ucarecdn.stepik.net/7198a906-736f-47ae-97c6-4e44dcdaa732/)

### Для чего нужна?

Команда `chmod` (от «change mode») меняет права доступа (`r`, `w`, `x`) к файлам и директориям для трёх категорий:

- владельца (**u** — user),
- группы (**g** — group),
- остальных (**o** — others).

`chmod` может работать в двух режимах: **символьном** и **числовом (октальном)**. Ниже рассмотрим, как это устроено на практике и приведём примеры.

### Основной синтаксис

- **Символьный формат**:
    
    ```css
    chmod [u|g|o][+|-|=][r|w|x] файл
    ```
    
    `**u**, **g**, **o**` указывают, к какой категории (владельцу, группе, остальным) мы хотим применить изменение.  
    Знак `**+**` добавляет право, `**-**` убирает, `**=**` устанавливает конкретный набор прав, сбрасывая все остальные.
    
- _Примеры:_
    
    - `chmod u+rwx script.sh` — добавляет **владельцу** все три бита (чтение, запись, исполнение).
    - `chmod g-w config.cfg` — убирает право записи **группе**.
    - `chmod u=rwx,g=rx,o=r somefile` — задаёт полный набор прав владельцу, группе — чтение и исполнение, остальным — только чтение.
- **Числовой формат (октальный)**:
    
    ```bash
    chmod XYZ файл
    ```
    
    где `X`, `Y`, `Z` — числа 0–7, определяющие сумму битов `r=4, w=2, x=1`.  
    _Пример:_
    
    - `chmod 755 script.sh` означает: владельцу — `rwx` (7), группе — `r-x` (5), всем остальным — `r-x` (5)
    - `chmod 600 secret.txt`  только владелец может читать и писать, остальные не имеют доступа
    - `chmod 644 document.txt` владелец может читать, писать; группа может читать; остальные могут только читать

### Важные моменты для DevOps

- В скриптах автоматизации (Ansible, Shell, Terraform) обычно удобнее задавать права в числовом виде (`755`, `640` и т.д.), чтобы сразу видеть итоговые биты.
- Символьная нотация может быть полезна для тонкой корректировки: например, «убрать только запись группе» без изменения других прав.

## 2. Команда `chown`: смена владельца (и группы)

![](https://ucarecdn.stepik.net/d9234dee-9f3d-455b-a461-f24d3479cbe1/)

### Для чего нужна?

`chown` (от «change owner») меняет **владельца** файла или директории. Это актуально, когда файлы были созданы не тем пользователем, который будет их в итоге поддерживать, или когда нужно задать особого «сервисного» владельца.

### Основной синтаксис

```bash
chown [опции] <новый_владелец> файл
```

или сразу для владельца и группы:

```php-template
chown [опции] <новый_владелец>:<новая_группа> файл
```

- _Примеры:_
    - `chown devuser myapp.conf` — передаёт файл `myapp.conf` пользователю `devuser`.
    - `chown devuser:devgroup logs/` — рекурсивно можно менять владельца и группу сразу на директорию `logs` и её содержимое (с флагом `-R`).

### Важные моменты для DevOps

- Для использования `chown` требуется быть суперпользователем (root) или обладать нужными правами через `sudo`.
- При создании сервисных пользователей (например, `nginx`, `postgres`) часто требуется «отдать» им нужные файлы или директории, чтобы сервисы могли работать корректно (читать конфиги, писать логи и т. п.).

## 3. Команда `chgrp`: смена группы

![](https://ucarecdn.stepik.net/c9a26d63-57a4-4234-83f0-0539c872b63c/)

### Для чего нужна?

Иногда достаточно поменять только **группу**, не затрагивая владельца. Допустим, вы хотите, чтобы команда разработчиков (группа `devteam`) имела права на запись в какой-то каталог. Можно оставить владельца root, но изменить группу на `devteam`.

### Основной синтаксис

```bash
chgrp [опции] <новая_группа> файл
```

_Пример:_

- `chgrp devteam docs/` — назначает группе `devteam` папку `docs`. Если права на группу (`g+rw`) уже выставлены, то все участники `devteam` смогут редактировать содержимое.

### Важные моменты для DevOps

- `chown` тоже может менять группу (через двоеточие `:`), но если нужно изменить **только** группу, `chgrp` лаконичнее.
- При работе с CI/CD-системами бывает удобно сгруппировать файлы и дирекции так, чтобы билд-агенты (входящие в определённую группу) имели нужные права на запуск или чтение.

## Применение в реальных задачах DevOps

1. **Настройка окружений**
    
    - Создаёте директорию под деплой, выдаёте ей `chown jenkins:jenkins` и `chmod 750`, чтобы только Jenkins мог писать туда сборочные артефакты, а администратор мог просматривать логи.
2. **Разграничение доступа**
    
    - Если у вас в проекте несколько команд (QA, Dev, Ops), вы можете назначать разные группы и выставлять отдельные права для каждого каталога.
3. **Автоматизация**
    
    - В том же Ansible у вас есть модули `file` или `copy`, где можно сразу задать параметры владельца (`owner`), группы (`group`), и права (`mode` — это аналог `chmod` в числах).
    - При массовом развёртывании (например, Terraform) удобно сразу прописать нужные права и владельцев в конфигурационных файлах, избегая ручной рутины.

### Резюме

- **`chmod`** — регулирует, какие именно права (r, w, x) будут у владельца, группы и остальных. Без него невозможно менять «уровень» доступа.
- **`chown`** — определяет, **кто** будет владельцем ресурса: меняет пользователя (а при необходимости и группу).
- **`chgrp`** — настраивает **только** группу, когда нужно дать общий доступ определённому сообществу пользователей.
