В классической модели Linux прав (r, w, x) на файлы и директории может не хватать гибкости. Когда нужно дать доступ к файлу сразу нескольким пользователям из разных групп, приходится придумывать обходные манёвры или создавать дополнительные группы. Здесь на помощь приходят **ACL (Access Control Lists)**. Они позволяют задавать расширенные права не только для владельца, группы и остальных, но и для конкретных пользователей или групп.

## 1. Понятие ACL и отличие от классической схемы rwx

### 1.1 Зачем нужны ACL

В обычной схеме прав Linux вы можете указать права только для трёх категорий:

- **Владелец (u)**
- **Группа (g)**
- **Остальные (o)**

Но что, если вам нужно, чтобы один конкретный пользователь (из другой команды) имел доступ на чтение, а другой — на запись, причём они не должны оба состоять в одной группе? Для этого используется **ACL** — расширенный список контроля доступа.

**Пример**

- Допустим, владелец файла — `user1`, основной группы — `devgroup`. Но мы хотим дать `user2` право на запись (w), а `user3` — право только чтения (r).
- Без ACL придётся либо добавлять `user2` и `user3` в основную группу, либо создавать новую группу — что может быть неудобно. С ACL мы точно настроим нужные права непосредственно для `user2, user3`.

### 1.2 Как это выглядит

ACL дополняет существующие rwx-права. Вы по-прежнему можете видеть их через `ls -l`, но если у файла или директории включены расширенные ACL, обычно в конце строке появляется символ `+`. Например:

```css
-rw-rw-r--+ 1 user1 devgroup  4096 Sep  1 12:00 report.txt
```

Знак `+` намекает, что у этого файла есть дополнительные записи в списке доступа.

## 2. Инструменты `getfacl` и `setfacl`

### 2.1 Просмотр ACL: `getfacl`

**getfacl** показывает расширенные права, которые применяются к файлу или директории.

```php-template
getfacl <файл_или_каталог>
```

**Пример вывода**:

```makefile
# file: report.txt
# owner: user1
# group: devgroup
user::rw-
user:user2:rw-
group::r--
mask::rw-
other::r--
```

- **user::rw-** — базовые права владельца (user1).
- **user:user2:rw-** — конкретной учётной записи user2 дали чтение и запись (rw-).
- **group::r--** — базовые права группы devgroup.
- **mask::rw-** — максимальный набор прав, который может быть у дополнительных записей ACL (об этом ниже).
- **other::r--** — права для всех прочих пользователей.

### 2.2 Изменение ACL: `setfacl`

**setfacl** позволяет добавлять, менять или удалять записи ACL.

#### Основной синтаксис

```php-template
setfacl -m <ACE> <файл_или_каталог>
```

- `-m` (modify) — модифицирует текущий список ACL.
- `ACE` (Access Control Entry) — запись вида `u:<user>:<rwx>` или `g:<group>:<rwx>`.

**Пример**

```applescript
setfacl -m u:user2:rw file.txt
```

- Это добавляет (или меняет) запись в ACL: **пользователь user2** будет иметь `r` и `w` на `file.txt`.

Если нужно убрать конкретную запись, используют `-x`:

```css
setfacl -x u:user2 file.txt
```

- Это удаляет ACL-запись для user2.

#### Рекурсивное применение

Чтобы рекурсивно задать ACL для каталога (и всего содержимого), добавляют флаг `-R`:

```bash
setfacl -R -m u:user2:rw /shared_dir/
```

## 3. Наследование ACL и маска (mask)

### 3.1 Наследование в директориях

При работе с директориями и ACL можно настроить, чтобы вновь создаваемые файлы и поддиректории **унаследовали** те же расширенные права. Для этого используется специальный «default ACL».

- `setfacl -m d:u:user2:rw /shared_dir/`
- Буква `d` (default) означает «по умолчанию» для новых файлов в этой директории.

Таким образом, любые файлы или поддиректории, созданные внутри `/shared_dir/`, изначально будут иметь ACL-запись, которая разрешает user2 читать и писать.

### 3.2 Маска (mask)

В выводе `getfacl` вы могли заметить строку **mask::**. Маска ограничивает максимальный набор прав, которые могут применяться к «дополнительным» записям (ACL).

- Если в маске стоит `rw-`, то даже если конкретному пользователю назначено `rwx`, **execute** не будет действовать, потому что маска не разрешает `x`.
- Маска не влияет на базовые права владельца (user::) и на «others::», но влияет на group:: и на все дополнительные user: / group: ACL-записи.

**Пример**

- Если mask::r--, то никакие дополнительные пользователи и группы не получат права записи или исполнения — только чтение.

### Итог

- **ACL** (Access Control Lists) — это расширение классических rwx-подходов. Теперь вы можете назначать права конкретным пользователям или группам, независимо от их принадлежности к основной группе файла.
- **getfacl** и **setfacl** — инструменты для просмотра и изменения ACL. С их помощью можно тонко регулировать, кто именно имеет r, w, x к файлам и каталогам.
- **Наследование** (default ACL) упрощает массовое назначение прав при создании новых файлов в определённых директориях.
- **Маска (mask)** ограничивает максимальные права для «дополнительных» записей ACL, чтобы вы не выдали кому-то слишком много привилегий, сами того не заметив.
