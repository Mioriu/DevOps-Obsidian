В Linux при создании новых файлов и директорий им автоматически назначаются права доступа. Однако «по умолчанию» система может не выдавать полный набор прав (rwx). За это отвечает специальный параметр **umask** (user file-creation mode mask). Понимание, как работает umask, и умение его правильно настраивать позволяет DevOps-инженеру контролировать, какие права будут у новых файлов и директорий — и тем самым обеспечивать необходимый уровень безопасности и удобства.

## 1. Понятие umask и его влияние на права создаваемых файлов и директорий

### Что такое umask

`**umask**` — это специальный параметр в Linux, который задаёт, **какие права будут “отняты”** (не выданы) у новых файлов и директорий во время их создания. По умолчанию, когда процесс (программа, команда, shell) создаёт файл, он пытается выдать ему максимально возможные права (часто `666` для файла и `777` для директории). Но затем система применяет `umask`, убирая определённые биты разрешений.

Другими словами, umask работает как противоположные права: если umask содержит бит на запись, это означает, что соответствующий бит на запись **убирается** у конечного результата.

### Как это работает на примере

1. Допустим, программа хочет создать **файл** с правами `rw-rw-rw-`, то есть в октальной записи `666` (6 = r+w).
    
2. Если umask равен `002`, это означает:
    
    - «0» в умаске не убирает никаких прав у владельца (u) и группы (g).
    - «2» убирает **бит записи** (w) у остальных (o).
    
    В двоичной логике `002` означает, что только для «others» (o) мы «снимаем» право записи.
    
3. В итоге результатом применения `666 - 002` будет `664` (октально), то есть `rw-rw-r--`.
    
    - Владельцу: `rw-`
    - Группе: `rw-`
    - Остальным: `r--`

Аналогично, если создаётся **директория** (которая часто запрашивает `777`), то при umask `002` результатом будет `775` (`rwxrwxr-x`).

### Важный момент: чем выше umask, тем **больше** прав отрезается

- Если вы поставите umask `777`, это теоретически «убирает» все права у всех (но это слишком радикально и практически никогда не используется).
- Если вы поставите `022`, то у группы (g) и остальных (o) отнимается возможность записи. Именно так обычно настроено по умолчанию: файлы становятся `644` (rw-r--r--) и директории `755` (rwxr-xr-x).

### Типичные значения umask

1. **`022`**
    
    - При создании **файла** (666) итог: `644`
        - Владельцу: `rw-`
        - Группе: `r--`
        - Остальным: `r--`
    - При создании **директории** (777) итог: `755`
        - Владельцу: `rwx`
        - Группе: `r-x`
        - Остальным: `r-x`
    
    Это настройка по умолчанию во многих системах: владелец может всё, а группа и остальные могут только читать (и «заходить» в директории).
    
2. **`002`**
    
    - При создании **файла** (666) итог: `664`
        - Владельцу: `rw-`
        - Группе: `rw-`
        - Остальным: `r--`
    - При создании **директории** (777) итог: `775`
        - Владельцу: `rwx`
        - Группе: `rwx`
        - Остальным: `r-x`
    
    Это удобно в ситуациях, когда несколько пользователей (принадлежащих к одной группе) должны совместно редактировать файлы. Например, в командах разработчиков: все в группе `dev`, и при umask `002` каждый новый файл будет доступен группе на запись.
    

## 2. Как установить и проверить текущий umask

### Проверка

Чтобы узнать, какой umask активен в текущей сессии, достаточно выполнить команду:

```bash
umask
```

- Обычно покажет результат в виде четырёхзначного (иногда трёхзначного) числа, например `0022` или `002`.

### Установка

- Команда `umask <значение>` меняет umask для текущей shell-сессии.
    
    ```bash
    umask 002
    ```
    
    Теперь все новые файлы и папки будут создаваться с учётом этой маски, **но** только в рамках текущего сеанса.
- Если вы хотите, чтобы umask устанавливался при каждом входе пользователя, нужно прописать команду `umask <значение>` в его файлах инициализации shell (например, `~/.bashrc`, `~/.profile`) или в глобальных скриптах (`/etc/profile`, `/etc/bashrc` и т. д.).

## 3. Практические сценарии изменения umask

### 3.1 Глобальная настройка в `/etc/profile`

Если требуется, чтобы все пользователи на сервере имели единый умаск (например, `022`), это можно прописать в файле `/etc/profile`. Пример:

```bash
# /etc/profile
umask 022
```

После этого, при новой сессии Shell, системные пользователи и обычные (в зависимости от дистрибутива) будут наследовать данную умаску.

### 3.2 Командная работа с файлами

В стартапах или командах разработки часто используют `umask 002`, чтобы **группа** имела право записи (`rw-`) к общим файлам. Это упрощает совместное редактирование без лишних команд `chmod`:

- Файлы получаются `rw-rw-r--` (664),
- Директории — `rwxrwxr-x` (775).

### 3.3 Безопасная среда

Если безопасность — приоритет, и вы хотите минимизировать доступ «остальных» пользователей, может использоваться более строгий umask, например, `027` или `077`. Тогда:

- `027`: новые файлы владелец читает/пишет, группа — читает, остальные — нет прав.
- `077`: все права остаются только владельцу (файлы `rw-------`, каталоги `rwx------`).

### Итог

Параметр umask — невидимый, но ключевой механизм, определяющий, с какими правами появляются новые файлы и директории. Понимание работы umask помогает DevOps-инженеру тонко настроить совместную работу (при сниженной маске) или повысить безопасность (при более жёсткой). Изменять umask можно напрямую в текущей сессии или системно, прописав нужное значение в `/etc/profile` или других скриптах инициализации.
