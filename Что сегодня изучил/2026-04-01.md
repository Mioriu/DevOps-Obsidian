### Саммари 1: Удалённые репозитории (Remote)

**Концепция:**  
Удалённый репозиторий — это версия проекта, размещённая в сети. Технически он не отличается от локального (оба содержат полную историю), но служит точкой синхронизации для команды. Локальный репозиторий может быть связан с несколькими удалёнными.

**Клонирование (`git clone`):**  
Создаёт локальную копию удалённого репозитория. Автоматически:

- Создаёт директорию
    
- Инициализирует Git
    
- Добавляет remote под именем `origin`
    
- Загружает все данные и создаёт рабочую копию
    

Полезные опции:

- `--depth 1` — поверхностное клонирование (только последний коммит)
    
- `--branch develop --single-branch` — только конкретная ветка
    
- `--bare` — без рабочей копии (для серверов)
    

**Протоколы:**

- **HTTPS:** простой, требует ввода логина/пароля или токена. Работает через стандартные порты.
    
- **SSH:** безопаснее, не требует ввода пароля после настройки ключей. Требует генерации пары ключей (`ssh-keygen`) и добавления публичного ключа в аккаунт хостинга.
    

**Управление удалёнными репозиториями:**

- `git remote -v` — просмотр списка remote с URL
    
- `git remote add origin <url>` — добавить удалённый репозиторий
    
- `git remote rename origin github` — переименовать
    
- `git remote set-url origin <new-url>` — изменить URL
    
- `git remote remove upstream` — удалить
    

**Сценарии с несколькими remote:**

- **Fork workflow:** `origin` — ваш форк, `upstream` — оригинальный репозиторий
    
- **Множественные хостинги:** зеркалирование на GitHub и GitLab
    
- **Резервные копии:** push на приватный сервер
    

**Лучшие практики:** использовать SSH для регулярной работы, осмысленные имена для remote, регулярно проверять состояние `git remote show origin`.

### Саммари 2: Синхронизация (Fetch, Pull, Push)

**Три типа веток в локальном репозитории:**

1. **Локальные ветки** — рабочие ветки, в которых ведётся разработка
    
2. **Remote-tracking ветки** — локальные копии веток из удалённого репозитория (`origin/main`). Обновляются при синхронизации, но их нельзя изменить напрямую
    
3. **Удалённые ветки** — физически находятся на сервере
    

**`git fetch` — безопасное получение:**

- Загружает новые коммиты и объекты с сервера
    
- Обновляет remote-tracking ветки (`origin/main`)
    
- **НЕ изменяет** локальные ветки и рабочую директорию
    
- Позволяет изучить изменения перед интеграцией: `git log main..origin/main`
    

**`git pull` — получение + интеграция:**  
`git pull = git fetch + git merge` (или `git rebase`)

Три варианта поведения:

- **Fast-forward:** локальная ветка не имеет уникальных коммитов — просто передвигается указатель
    
- **Merge commit:** есть уникальные коммиты в обеих ветках — создаётся коммит слияния
    
- **Rebase:** `git pull --rebase` — переписывает историю, помещая локальные коммиты поверх полученных
    

Требует чистого рабочего состояния (иначе откажется выполнять).

**`git push` — отправка на сервер:**

- Отправляет локальные коммиты в удалённый репозиторий
    
- Только если push является **fast-forward** операцией (не перезаписывает чужие изменения)
    

**Почему push может быть отклонён:**  
Если кто-то успел отправить коммиты раньше, Git отклоняет push, чтобы предотвратить потерю данных. Нужно сначала сделать `fetch`/`pull` и интегрировать изменения.

**Force push (опасно!):**

- `git push --force` — перезаписывает историю на сервере (может удалить чужие коммиты)
    
- `git push --force-with-lease` — более безопасный вариант: проверяет, что remote-tracking ветка актуальна
    

**Upstream (tracking) связь:**  
Настройка, указывающая, какая удалённая ветка соответствует локальной. Упрощает команды:

- `git push -u origin feature` — установить связь
    
- После этого достаточно `git pull` и `git push` без аргументов
    
- `git status` показывает разницу: "ahead by 2 commits" / "behind by 3 commits"
    

**Итоговая схема:**

- `fetch` → обновляет remote-tracking ветки (безопасно)
    
- `pull` → fetch + merge/rebase в текущую ветку
    
- `push` → отправляет коммиты на сервер (только fast-forward)
