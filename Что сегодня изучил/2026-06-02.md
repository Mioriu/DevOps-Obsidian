# Саммари статей по Docker: Образы, контейнеры и фундаментальные концепции

## Статья 1: Docker Image — неизменяемый фундамент

### Что такое Docker Image

**Docker Image** — это упакованный пакет, содержащий всё необходимое для запуска приложения:

- Код приложения
    
- Среда выполнения (Node.js, Python и т.д.)
    
- Системные библиотеки и инструменты
    
- Настройки (переменные окружения)
    

### Главный принцип: Слои (Layers)

Образ — это **набор слоёв**, наложенных друг на друга (как прозрачные плёнки):

|Слой|Что содержит|Пример|
|---|---|---|
|Слой 1 (Base Image)|Операционная система|`Ubuntu`|
|Слой 2 (Dependencies)|Библиотеки, зависимости|Установка `Python`|
|Слой 3 (App Code)|Код приложения|Копирование `main.py`|

**Кэширование:** При изменении кода пересобирается только верхний слой. Нижние слои берутся из кэша.

**Экономия места:** Если у вас 5 образов на базе `Ubuntu`, слой с Ubuntu хранится один раз.

### Неизменяемость (Immutability)

- Образы — **Read-Only**
    
- Нельзя изменить существующий образ
    
- Любое изменение → сборка **нового** образа с новым тегом
    
- Гарантия: образ `myapp:v1` будет работать одинаково везде и всегда
    

### Dockerfile — инструкция по сборке

dockerfile

FROM python:3.11-slim    # Базовый слой
WORKDIR /app             # Рабочая директория
COPY requirements.txt .  # Копируем зависимости
RUN pip install -r requirements.txt   # Устанавливаем (новый слой)
COPY . .                 # Копируем код
CMD ["python", "main.py"] # Команда запуска

### Теги и версионирование

|Тег|Значение|
|---|---|
|`python:3.11`|Конкретная версия|
|`python:3.11-slim`|Урезанная (облегчённая) сборка|
|`python:latest`|Самая последняя версия|

**⚠️ Важно:** В продакшене **никогда** не используйте `latest` — завтра он может обновиться и сломать ваш код.

### Размер имеет значение: Alpine vs Debian

|Базовый образ|Размер|
|---|---|
|`postgres:latest` (Debian)|~350 МБ|
|`postgres:alpine`|~70 МБ|

**Alpine Linux** — экстремально лёгкий дистрибутив. Меньше размер → быстрее скачивание, меньше места, меньше уязвимостей.

### Итог: 4 главных свойства образа

1. **Слепок** — замороженное состояние файловой системы
    
2. **Слои** — переиспользуемые кирпичики
    
3. **Неизменяемость** — изменения → новый образ
    
4. **Стандарт** — работает одинаково везде

## Статья 2: Базовые команды Docker

### Запуск и управление контейнерами

|Команда|Назначение|Пример|
|---|---|---|
|`docker run`|Создать и запустить контейнер|`docker run -d -p 8080:80 --name web nginx`|
|`docker ps`|Список запущенных контейнеров|`docker ps -a` (включая остановленные)|
|`docker stop`|Штатная остановка (SIGTERM)|`docker stop web`|
|`docker kill`|Мгновенная остановка (SIGKILL)|`docker kill web`|

**Ключевые флаги `docker run`:**

- `-d` (detached) — фон
    
- `-p HOST:CONTAINER` — проброс портов
    
- `--name` — имя контейнера
    
- `-v` — монтирование тома
    
- `--rm` — автоматически удалить при остановке
    

### Диагностика и взаимодействие

|Команда|Назначение|Пример|
|---|---|---|
|`docker logs`|Логи контейнера|`docker logs -f web` (follow)|
|`docker exec`|Выполнить команду внутри контейнера|`docker exec -it web /bin/bash`|
|`docker inspect`|Детальная информация (JSON)|`docker inspect web`|

### Работа с образами

|Команда|Назначение|
|---|---|
|`docker images`|Список локальных образов|
|`docker pull`|Скачать образ (без запуска)|
|`docker build -t name:tag .`|Собрать образ из Dockerfile|

### Очистка ресурсов

|Команда|Что удаляет|
|---|---|
|`docker rm <id>`|Остановленный контейнер|
|`docker rmi <image>`|Образ (если нет контейнеров)|
|`docker system prune`|Всё: остановленные контейнеры, неиспользуемые сети, висячие образы|

### Шпаргалка (Cheatsheet)

bash

docker build -t myapp .           # собрать образ
docker run -dp 80:80 myapp        # запустить в фоне с пробросом порта
docker ps                          # работающие контейнеры
docker logs -f <id>                # логи в реальном времени
docker exec -it <id> bash          # войти внутрь
docker stop <id>                   # остановить
docker rm <id>                     # удалить
docker rmi <image>                 # удалить образ

## Статья 3: PID 1 и логирование

### Модель исполнения: PID 1

В обычном Linux есть процесс с PID 1 (`systemd`), который управляет сервисами.

**В контейнере нет systemd.** Процесс из `CMD`/`ENTRYPOINT` получает **PID 1**.

#### Три ключевых следствия:

1. **Жизнь контейнера = жизнь PID 1.** Как только PID 1 завершается — контейнер останавливается.
    
2. **Приложение должно работать в foreground (на переднем плане).**
    
    - ❌ `service nginx start` (запустит демона в фоне и завершится → контейнер упадёт)
        
    - ✅ `nginx -g 'daemon off;'` (работает на переднем плане)
        
3. **Обработка сигналов.** PID 1 обязан корректно обрабатывать `SIGTERM`. Если приложение игнорирует `SIGTERM`, `docker stop` будет висеть 10 секунд, затем Docker отправит `SIGKILL` (может привести к потере данных).
    

### Архитектура логирования: STDOUT / STDERR

**В Docker логи пишут в консоль, а не в файлы!**

Docker перехватывает:

- **STDOUT** — обычный вывод
    
- **STDERR** — ошибки
    

**Почему файлы логов внутри контейнера — анти-паттерн:**

1. Логи исчезают при удалении контейнера
    
2. Чтобы их прочитать, нужно лезть внутрь (`docker exec`)
    
3. Нет ротации — файл растёт бесконечно
    

### Драйверы логирования (Logging Drivers)

По умолчанию: **`json-file`**

Docker упаковывает вывод в JSON и сохраняет на хосте:

text

/var/lib/docker/containers/<container_id>/<container_id>-json.log

**`docker logs`** читает этот файл:

bash

docker logs my-app                    # все логи
docker logs --tail 100 -f my-app      # последние 100 строк + следить

### Альтернативные драйверы (для продакшена)

|Драйвер|Куда отправляет|
|---|---|
|`syslog`|Системный журнал Linux|
|`gelf`|Graylog|
|`fluentd`|Fluentd / Elasticsearch|
|`awslogs`|Amazon CloudWatch|

### Итог

|Концепция|Суть|
|---|---|
|**PID 1**|Процесс контейнера — главный. Работает в foreground, обрабатывает сигналы|
|**Логи**|Пишут в STDOUT/STDERR, не в файлы|
|**`docker logs`**|Читает логи из драйвера (по умолчанию `json-file`)|
