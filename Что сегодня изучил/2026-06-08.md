## Статья 1: Основы сетей — клиент-сервер, IP, порты, протоколы

### Что такое сеть

**Сеть** — это когда два или более компьютеров могут обмениваться данными.

### Типы сетей по масштабу

|Тип|Расшифровка|Пример|Размер|
|---|---|---|---|
|LAN|Local Area Network|Офис, дата-центр|Одно здание|
|WAN|Wide Area Network|Связь между офисами|Город, страна|
|Internet|Сеть сетей|Весь мир|Глобально|

### Клиент-серверная модель

|Роль|Что делает|Кто инициирует|
|---|---|---|
|**Клиент**|Запрашивает, отправляет запрос, ждёт ответ|Да (активная сторона)|
|**Сервер**|Слушает, принимает запросы, отправляет ответы|Нет (пассивно ждёт)|

**Важно:** Одна машина может одновременно быть и клиентом, и сервером. Например, бэкенд — сервер для фронтенда и клиент для базы данных.

### IP-адрес — уникальный идентификатор устройства в сети

**IPv4:** 4 числа от 0 до 255 (октеты) через точку

text

192.168.1.100
10.0.0.5
8.8.8.8

**IPv6:** 8 групп по 4 hex-символа (пока реже)

### Специальные адреса

|Адрес|Назначение|
|---|---|
|`127.0.0.1`|localhost (сам на себя)|
|`0.0.0.0`|"все интерфейсы" при прослушивании|
|`10.x.x.x`|Приватная сеть (класс A)|
|`172.16-31.x.x`|Приватная сеть (класс B)|
|`192.168.x.x`|Приватная сеть (класс C)|

**Приватные адреса не маршрутизируются в интернете** — используются внутри локальных сетей.

### Порт — номер сервиса на машине (0–65535)

|Порт|Сервис|
|---|---|
|22|SSH|
|80|HTTP|
|443|HTTPS|
|3306|MySQL|
|5432|PostgreSQL|
|6379|Redis|
|8080|HTTP (альтернативный)|
|9090|Prometheus|
|3000|Grafana|

**Сокет = IP + порт**

text

192.168.1.100:5432
10.0.0.5:80

### Протокол — набор правил для общения

**Модель TCP/IP (уровни протоколов):**

|Уровень|Название|Протоколы|Задача|
|---|---|---|---|
|4|Прикладной|HTTP, SSH, DNS, SMTP|Логика приложения|
|3|Транспортный|TCP, UDP|Доставка между процессами|
|2|Сетевой|IP, ICMP|Маршрутизация между сетями|
|1|Канальный|Ethernet, Wi-Fi|Передача по физическому каналу|

### Полезные команды

bash

# Показать все слушающие порты
ss -tlnp
# Показать активные TCP соединения
ss -tnp
# Показать IP-адреса на интерфейсах
ip addr show
# Сделать HTTP-запрос с заголовками
curl -v http://example.com/

## Статья 2: CIDR и подсети

### IP-адрес в двоичном виде

IP-адрес (IPv4) — это 32-битное число. Человек видит `192.168.1.10`, компьютер — `11000000.10101000.00000001.00001010`.

**Любой IP-адрес делится на две части:**

- **Сетевая часть (Network)** — идентификатор сети (как название улицы)
    
- **Хостовая часть (Host)** — идентификатор устройства (как номер дома)
    

### Маска подсети — показывает границу между сетью и хостом

**Правило:** единицы в маске = сетевая часть, нули = хостовая.

text

IP-адрес:  192.168.1.10       11000000.10101000.00000001.00001010
Маска:     255.255.255.0      11111111.11111111.11111111.00000000
           |------сеть--------|   |--хост--|
Сетевая часть: 192.168.1
Хостовая часть: .10

### CIDR-нотация — запись маски через количество единиц

Вместо `255.255.255.0` пишем `/24` (24 единицы, 8 нулей).

text

192.168.1.0/24  → маска 255.255.255.0

### Таблица CIDR

|CIDR|Маска|Бит под хосты|Всего адресов|Доступно хостам|
|---|---|---|---|---|
|/8|255.0.0.0|24|16 777 216|16 777 214|
|/16|255.255.0.0|16|65 536|65 534|
|/24|255.255.255.0|8|256|254|
|/25|255.255.255.128|7|128|126|
|/26|255.255.255.192|6|64|62|
|/27|255.255.255.224|5|32|30|
|/28|255.255.255.240|4|16|14|
|/30|255.255.255.252|2|4|2|
|/32|255.255.255.255|0|1|1|

**Почему "доступно хостам" на 2 меньше?** Зарезервированы:

- Первый адрес — адрес самой сети
    
- Последний адрес — широковещательный (broadcast)
    

### Зачем делить на подсети (Subnetting)

Проблемы одной большой сети (`/8` на 16 млн адресов):

- **Broadcast-шторм** — каждый пакет долетает до всех устройств
    
- **Отсутствие изоляции** — бухгалтерия и продакшен в одном сегменте
    
- **Невозможность тонкого управления доступом**
    

**Решение:** взять большую сеть и нарезать на маленькие подсети.

### Практика деления сетей

**Формула:**

- Количество подсетей = `2^N` (где N — сколько битов добавили к префиксу)
    
- Хостов в каждой = `2^(оставшиеся биты) - 2`
    

**Пример 1:** разделить `/24` на 2 равные подсети

- `/24` → `/25` (добавили 1 бит → 2 подсети)
    
- В каждой: 128 адресов, 126 хостов
    

|Подсеть|Диапазон хостов|Broadcast|
|---|---|---|
|192.168.1.0/25|1 – 126|127|
|192.168.1.128/25|129 – 254|255|

**Пример 2:** разделить `/24` на 4 подсети

- `/24` → `/26` (добавили 2 бита → 4 подсети)
    
- В каждой: 64 адреса, 62 хоста
    

|Подсеть|Диапазон хостов|Broadcast|
|---|---|---|
|192.168.1.0/26|1 – 62|63|
|192.168.1.64/26|65 – 126|127|
|192.168.1.128/26|129 – 190|191|
|192.168.1.192/26|193 – 254|255|

### Быстрый счёт: шаг подсети

**Шаг подсети** = количество адресов в подсети = `2^(32 - префикс)`

Для `/26`: `2^(32-26) = 2^6 = 64`

Подсети начинаются с 0, 64, 128, 192...

**Вопрос:** к какой подсети `/26` принадлежит адрес `192.168.1.200`?

- Шаг 64, подсети: 0, 64, 128, **192**, 256
    
- Ответ: `192.168.1.192/26`
    

### Приватные диапазоны IP (RFC 1918) — не маршрутизируются в Интернете

|Диапазон|CIDR|Количество адресов|
|---|---|---|
|10.0.0.0 – 10.255.255.255|10.0.0.0/8|16 777 216|
|172.16.0.0 – 172.31.255.255|172.16.0.0/12|1 048 576|
|192.168.0.0 – 192.168.255.255|192.168.0.0/16|65 536|

Для выхода в Интернет используется **NAT** (замена приватного адреса на публичный).

### CIDR в реальной жизни

**Docker:**

bash

# По умолчанию: bridge-сеть 172.17.0.0/16
docker network create --subnet=10.10.0.0/24 my-network

**Правила фаервола / Security Groups:**

text

Разрешить SSH (22) с 203.0.113.50/32       # один конкретный IP
Разрешить HTTP (80) с 0.0.0.0/0           # весь Интернет
Разрешить PostgreSQL (5432) с 10.0.2.0/24 # только подсеть app

**Специальные маски:**

- `/32` — один конкретный IP-адрес
    
- `0.0.0.0/0` — все возможные адреса (весь Интернет)
