# Саммари: GitLab CI/CD — ключевые компоненты и практики

---

## Ключевые компоненты GitLab CI/CD

| Компонент            | Описание                                                           |
| -------------------- | ------------------------------------------------------------------ |
| **`.gitlab-ci.yml`** | Файл в корне репозитория, описывающий пайплайн                     |
| **Pipeline**         | Набор джобов, организованных по стейджам (build → test → deploy)   |
| **Jobs**             | Отдельные задачи, выполняются параллельно внутри стейджа           |
| **GitLab Runner**    | Агент, выполняющий джобы (shared / group / specific)               |
| **Artifacts**        | Файлы, передаваемые между джобами (результаты сборки, отчёты)      |
| **Variables**        | Параметризация пайплайнов (UI, `.gitlab-ci.yml`, предопределённые) |

## `before_script` и `after_script`

- **`before_script`** — выполняется **перед** `script` в том же shell-контексте.
    
    - Установка зависимостей, логин в registry, настройка окружения.
        
    - Если упал → джоба фейлится.
        
- **`after_script`** — выполняется **после** `script` в **новом** shell-контексте.
    
    - Очистка, нотификации, сбор логов при падении.
        
    - Выполняется даже при ошибке в `script`.
        

**Важно:** переменные из `before_script` доступны в `script`. В `after_script` — нет.

## Переиспользование конфигурации между проектами

### `include` — подключение внешних файлов

yaml

include:
  - project: 'devops/ci-templates'
    file: '/templates/python.yml'

### `extends` — наследование джобов

yaml

.python_test_template:
  image: python:3.9
  script: pytest
test:
  extends: .python_test_template
  variables:
    EXTRA_ARGS: "--coverage"

### Hidden jobs (с `.`) — шаблоны, которые не запускаются

### YAML anchors — для переиспользования кусков

yaml

.cache_template: &cache_config
  cache:
    key: ${CI_COMMIT_REF_SLUG}
    paths: [node_modules/]

**Лучшая практика:** отдельный репозиторий `ci-templates` с шаблонами для разных языков → подключается через `include`.

## Запуск тестов только при создании MR

yaml

test:
  script: npm test
  rules:
    - if: '$CI_PIPELINE_SOURCE == "merge_request_event"'

**С дополнительными условиями:**

yaml

rules:
  - if: '$CI_MERGE_REQUEST_TARGET_BRANCH_NAME == "main"'
  - if: '$CI_MERGE_REQUEST_LABELS =~ /skip-tests/'
    when: never

## Кэширование в GitLab CI

**Cache** — ускорение повторных запусков (хранит зависимости между пайплайнами). **Не гарантирован** (раннер может потерять).

yaml

cache:
  key: ${CI_COMMIT_REF_SLUG}        # отдельный кэш на ветку
  paths:
    - node_modules/
    - .npm/

**Лучший key — по lock-файлу:**

yaml

cache:
  key:
    files:
      - package-lock.json
  paths:
    - node_modules/

**Policy:**

- `pull-push` (дефолт) — скачать и загрузить
    
- `pull` — только скачать
    
- `push` — только загрузить

## Jenkins — архитектура и ключевые концепции

### Архитектура

|Компонент|Описание|
|---|---|
|**Jenkins Master (Controller)**|Хранит конфигурацию, UI, управляет агентами|
|**Jenkins Agents (Nodes)**|Выполняют билды (на разных машинах, в контейнерах)|
|**Executors**|Слоты для параллельного выполнения (4 executor'а = 4 параллельные джобы)|
|**Jobs/Projects**|Конфигурация задач (Freestyle, Pipeline, Multibranch Pipeline)|
|**Plugins**|Расширения (Git, Docker, Kubernetes, уведомления) — >1500 плагинов|
|**Workspace**|Рабочая директория на агенте|

### Выбор воркера (агента)

**Declarative Pipeline:**

groovy

pipeline {
    agent { label 'linux && docker' }
}

**Для отдельных стейджей:**

groovy

stage('Build') {
    agent { label 'maven' }
    steps { ... }
}

Логические операторы: `linux && docker`, `linux || windows`, `!windows`.

## Shared Library в Jenkins

**Shared Library** — переиспользуемый Groovy-код между пайплайнами.

**Структура:**

text

(root)
├── src/           # Groovy классы
│   └── org/foo/Bar.groovy
├── vars/          # Глобальные функции (вызываются из пайплайна)
│   └── deployToK8s.groovy
└── resources/     # Ресурсные файлы

**`vars/deployToK8s.groovy`:**

groovy

def call(String namespace, String image) {
    sh "kubectl set image deployment/app app=${image} -n ${namespace}"
}

**Использование:**

groovy

@Library('my-shared-library') _
pipeline {
    stages {
        stage('Deploy') {
            steps {
                deployToK8s('production', 'myapp:v1.0')
            }
        }
    }
}

## Jenkinsfile — язык и синтаксис

**Jenkinsfile пишется на Groovy.**

|Синтаксис|Особенности|
|---|---|
|**Declarative Pipeline**|Структурированный, проще, покрывает 95% кейсов. `pipeline { agent, stages, steps }`|
|**Scripted Pipeline**|Более гибкий, чистый Groovy. `node { stage, sh }`|

**Script-блок в Declarative (для Groovy-кода):**

groovy

stage('Complex') {
    steps {
        script {
            if (env.BRANCH_NAME == 'main') {
                deploy()
            }
        }
    }
}
