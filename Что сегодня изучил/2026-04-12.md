### Саммари: Поиск в истории Git (Log, Grep, Blame, Bisect)

**Основная идея:** История Git — это не просто архив, а база знаний о проекте. Умение эффективно искать в ней — ключевой навык опытного разработчика.

---

### 1. Git Log — фильтрация истории

**Поиск по автору и времени:**

bash

git log --author="John" --since="1 month ago"
git log --after="2023-01-01" --before="2023-06-30"

**Поиск по сообщениям коммитов:**

bash

git log --grep="fix"              # искать в сообщениях
git log --grep="bug" --grep="crash" --all-match  # несколько условий

**Поиск по изменениям в коде (мощный инструмент!):**

bash

git log -S"calculateTax"         # изменение количества вхождений строки
git log -G"function.*calculate"  # поиск по регулярному выражению

- `-S` находит коммиты, где строка появилась или исчезла
    
- `-G` находит коммиты с любыми изменениями, соответствующими regex
    

**Поиск по файлам и путям:**

bash

git log -- src/main.js            # история конкретного файла
git log --follow -- src/main.js   # с учётом переименований
git log -- src/                   # все файлы в директории

---

### 2. Git Grep — поиск по содержимому

Git-версия классического `grep`, оптимизированная для репозиториев.

**Преимущества:** автоматически игнорирует `.gitignore` и папку `.git`, работает параллельно, быстрее обычного `grep`.

bash

git grep "TODO"                   # поиск в текущем состоянии
git grep "API_KEY" v2.0.0         # поиск в конкретной версии
git grep "DEBUG" $(git rev-list --all)  # поиск во всех ветках/коммитах

**Полезные опции:**

bash

git grep -n "pattern"             # показать номера строк
git grep -c "pattern"             # только количество совпадений
git grep -p "pattern"             # показать окружающие функции

---

### 3. Git Blame — автор каждой строки

Показывает, кто и когда последним изменял каждую строку файла. Название — не для поиска виноватых, а для понимания контекста.

bash

git blame src/main.js
git blame -L 10,20 src/main.js   # только строки 10-20
git blame -w src/main.js         # игнорировать пробелы

**Игнорирование косметических коммитов:**

bash

# Создать файл .git-blame-ignore-revs с хешами коммитов автоформатирования
git blame --ignore-revs-file .git-blame-ignore-revs src/main.js

**Blame для удалённых строк:**

bash

git blame -c abc123 -- src/deleted-file.js  # на момент коммита abc123

### 4. Git Bisect — бинарный поиск проблемы

Автоматический поиск коммита, который внёс баг. Работает как бинарный поиск по истории.

**Ручной режим:**

bash

git bisect start
git bisect bad HEAD                 # текущая версия с багом
git bisect good v1.0.0              # версия без бага
# Git переключается на средний коммит
# Проверяете и сообщаете:
git bisect good                     # или git bisect bad
# Повторяете, пока не найден проблемный коммит
git bisect reset                    # завершить поиск

**Автоматический режим (с тестом):**

bash

git bisect start HEAD v1.0.0
git bisect run npm test             # Git сам проверит все коммиты
git bisect reset

**Пропуск нетестируемых коммитов:**

bash

git bisect skip                     # если коммит нельзя проверить

### Практические сценарии

|Задача|Инструменты|
|---|---|
|Найти, кто и когда добавил функцию|`git log -S"functionName"`|
|Понять контекст строки кода|`git blame` + `git show <commit>`|
|Найти коммит, сломавший сборку|`git bisect` + автоматический тест|
|Узнать, использовалась ли функция раньше|`git grep "function" $(git rev-list --all)`|
|Что изменилось за последнюю неделю|`git log --since="1 week ago" --oneline`|
|Кто работал над модулем|`git log --format="%an" -- src/module/ \| sort \| uniq -c`|

---

### Полезные алиасы

bash

git config --global alias.whois '!git log --author="$1" --oneline | wc -l'
git config --global alias.find '!git log --oneline -S"$1"'
git config --global alias.history 'log --graph --pretty=format:"%h - %an, %ar : %s"'

---

### Итог

- **Log** — фильтрация истории по любым критериям
    
- **Grep** — поиск паттернов в коде любой версии
    
- **Blame** — контекст каждой строки кода
    
- **Bisect** — автоматический поиск проблемного коммита
    

Комбинируя эти инструменты, можно эффективно расследовать баги, понимать эволюцию кода и принимать обоснованные решения о рефакторинге. История Git — это база знаний, а умение в ней ориентироваться — признак профессионализма.
