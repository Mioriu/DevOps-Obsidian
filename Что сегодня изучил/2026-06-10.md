# Саммари статей по DHCP, NAT и файрволам

## Статья 1: DHCP и NAT — автоматическая настройка сети и трансляция адресов

### DHCP — Dynamic Host Configuration Protocol

**Что делает:** Автоматически выдаёт устройствам IP-адрес, маску, шлюз, DNS и другие сетевые настройки.

**Процесс DORA:**

|Шаг|Название|Кто → Кому|Содержание|
|---|---|---|---|
|1|**DISCOVER**|Клиент → broadcast|"Есть тут DHCP-сервер?"|
|2|**OFFER**|Сервер → broadcast/unicast|"Держи 192.168.1.50"|
|3|**REQUEST**|Клиент → broadcast|"Беру 192.168.1.50"|
|4|**ACK**|Сервер → broadcast/unicast|"Подтверждаю, адрес твой"|

**Аренда (Lease):** IP выдаётся на время (часы/сутки). При достижении 50% времени — попытка продлить.

**DHCP Relay:** Роутер, который пересылает DHCP-запросы из своей сети на DHCP-сервер в другой сети (т.к. broadcast через роутер не проходит).

**Проверка:**

bash

# Посмотреть аренду
cat /var/lib/dhcp/dhclient.leases
# Запросить новый адрес
sudo dhclient eth0

### NAT — Network Address Translation

**Что делает:** Изменяет IP-адреса в пакетах при прохождении через роутер. Позволяет устройствам с приватными IP выходить в интернет через один публичный IP.

**Приватные диапазоны (RFC 1918):**

- `10.0.0.0/8` — 16 млн адресов
    
- `172.16.0.0/12` — 1 млн адресов
    
- `192.168.0.0/16` — 65 тыс. адресов
    

**Типы NAT:**

|Тип|Что делает|Пример|
|---|---|---|
|**SNAT**|Меняет адрес источника (выход в интернет)|`192.168.1.50 → 203.0.113.1`|
|**DNAT**|Меняет адрес назначения (проброс внутрь)|порт 8080 → `192.168.1.10:80`|
|**PAT/Masquerade**|SNAT + трансляция портов (один IP на много устройств)|несколько внутренних IP → один внешний, различаются портами|

**NAT-таблица (conntrack):**

text

192.168.1.50:54321 ↔ 203.0.113.1:40001
192.168.1.51:54321 ↔ 203.0.113.1:40002

**Типичные проблемы:**

- Конфликт IP-адресов (статический IP из DHCP-пула → вынести статику)
    
- Исчерпание портов NAT (уменьшить таймауты conntrack, добавить публичных IP)

## Статья 2: Файрволы и iptables/nftables

### Что такое файрвол

Фильтр сетевого трафика. Три действия:

|Действие|Что происходит|
|---|---|
|**ACCEPT**|Пропустить пакет|
|**DROP**|Молча выбросить (клиент ждёт таймаут)|
|**REJECT**|Отклонить, отправить ошибку|

**Stateful vs Stateless:**

- **Stateful** — отслеживает состояние соединений (ESTABLISHED, RELATED)
    
- **Stateless** — не помнит соединений (каждый пакет изолирован)
    

**Состояния conntrack:**

- `NEW` — первый пакет нового соединения
    
- `ESTABLISHED` — в рамках существующего соединения
    
- `RELATED` — связанный пакет (например, ICMP-ошибка)
    
- `INVALID` — не удалось классифицировать
    

---

### iptables — классический инструмент

**Структура:** Таблицы → Цепочки → Правила

**Основные таблицы:**

|Таблица|Назначение|
|---|---|
|`filter`|Фильтрация (по умолчанию)|
|`nat`|Трансляция адресов (SNAT, DNAT)|
|`mangle`|Модификация пакетов|

**Цепочки в таблице filter:**

|Цепочка|Когда срабатывает|
|---|---|
|`INPUT`|Входящие пакеты для этого хоста|
|`OUTPUT`|Исходящие пакеты от этого хоста|
|`FORWARD`|Транзитные пакеты|

**Базовые команды:**

bash

iptables -L INPUT -n -v           # список правил
iptables -A INPUT -p tcp --dport 22 -j ACCEPT   # добавить правило
iptables -I INPUT 1 -p tcp --dport 80 -j ACCEPT # вставить в начало
iptables -D INPUT 3               # удалить правило по номеру
iptables -P INPUT DROP            # политика по умолчанию

**Порядок правил важен!** Первое совпавшее срабатывает.

**NAT с iptables:**

bash

# Masquerade (выход в интернет)
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
# Port forwarding
iptables -t nat -A PREROUTING -p tcp --dport 8080 -j DNAT --to-destination 10.0.0.10:80
iptables -A FORWARD -p tcp -d 10.0.0.10 --dport 80 -j ACCEPT

---

### nftables — современная замена

**Почему лучше:** единый синтаксис для IPv4/IPv6, атомарные обновления, лучше производительность.

**Структура:** Таблицы → Цепочки (привязаны к hook-точкам) → Правила

**Hook-точки:** `prerouting`, `input`, `forward`, `output`, `postrouting`

**Проверить backend iptables:**

bash

iptables -V   # nf_tables (новый) или legacy (старый)

### Обёртки: firewalld и ufw

**firewalld (CentOS/RHEL/Fedora):**

bash

firewall-cmd --zone=public --add-service=http --permanent
firewall-cmd --reload

**ufw (Ubuntu/Debian):**

bash

ufw allow 22/tcp
ufw enable

⚠️ **Важно:** При включении ufw убедись, что SSH разрешён, иначе потеряешь доступ!

### Файрволы и контейнеры

**Docker:**

- Создаёт правила в `PREROUTING` и `FORWARD` (обходит `INPUT`)
    
- Ограничение доступа к контейнерам:
    

bash

# Через DOCKER-USER
iptables -I DOCKER-USER -i eth0 -s 10.0.0.0/8 -p tcp --dport 80 -j ACCEPT
iptables -I DOCKER-USER -i eth0 -p tcp --dport 80 -j DROP
# Или биндинг на localhost
docker run -p 127.0.0.1:8080:80 nginx

---

### Типичные проблемы

|Проблема|Причина|Решение|
|---|---|---|
|Connection timed out|Политика INPUT DROP, нет правила для порта|Добавить правило, проверить облачный файрвол|
|Потеря SSH после настройки|Закрыли порт 22|Запланировать сброс правил: `echo "iptables -F" \| at now + 5 min`|
|Docker-контейнер доступен извне|Docker обходит INPUT|Использовать DOCKER-USER или биндинг на localhost|
|Сервер не может подключиться к внешним ресурсам|OUTPUT DROP, нет ESTABLISHED|`iptables -A OUTPUT -m state --state ESTABLISHED -j ACCEPT`|
