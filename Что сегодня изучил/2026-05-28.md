[[Локальный registry]]  [[Что такое Docker Registry]]

## Статья 1: Docker Registry — что это и зачем нужен

### Основная идея

**Docker Registry** — это хранилище Docker-образов, аналог GitHub для кода. Позволяет хранить, версионировать и распространять образы между разработчиками и серверами.

### Три ключевые команды для работы с реестром

| Команда       | Назначение                      | Пример                                     |
| ------------- | ------------------------------- | ------------------------------------------ |
| `docker pull` | Загрузить образ из реестра      | `docker pull nginx:latest`                 |
| `docker push` | Отправить образ в реестр        | `docker push myuser/myapp:1.0`             |
| `docker tag`  | Создать тег (обычно перед push) | `docker tag myapp:latest myuser/myapp:1.0` |

### Структура имени образа

text

registry-host:port/username/repository:tag

**Примеры:**

- `docker.io/library/ubuntu:20.04` — официальный образ Ubuntu
    
- `myusername/myapp:latest` — ваш образ в Docker Hub (короткая форма)
    
- `registry.example.com:5000/project/backend:v1.2.3` — частный реестр
    

### Типы реестров

|Тип|Примеры|Особенности|
|---|---|---|
|**Публичные**|Docker Hub, GitHub Container Registry, [Quay.io](https://quay.io/)|Бесплатно для открытых образов|
|**Приватные**|Docker Hub (платный), облачные провайдеры, локальный Registry, Harbor|Контроль доступа, безопасность|

### Docker Hub — основной публичный реестр

- Официальные образы (Ubuntu, Nginx, Python)
    
- Верифицированные образы партнёров
    
- Образы сообщества
    
- Автоматическая сборка (связка с GitHub)
    

### Аутентификация для приватных образов

bash

docker login registry-host:port
# Данные сохраняются в ~/.docker/config.json

### Зачем нужен локальный реестр?

- **Безопасность** — конфиденциальные образы не покидают инфраструктуру
    
- **Скорость** — быстрая загрузка в локальной сети
    
- **Экономия трафика** — образ загружается один раз
    
- **Независимость** — работа без доступа к интернету
    
- **CI/CD интеграция** — полный контроль над пайплайнами
    

### Альтернативы простому Registry

|Решение|Особенности|
|---|---|
|**Harbor**|Роли, сканирование уязвимостей, репликация, веб-интерфейс|
|**Nexus Repository**|Универсальный (Docker, npm, Maven, PyPI)|
|**GitLab Container Registry**|Встроенный, тесная интеграция с CI/CD|

### Итог

Docker Registry — это центральное хранилище образов. Docker Hub — самый популярный публичный реестр. Для работы используются `pull`, `push`, `tag`. Локальные реестры дают контроль, скорость и безопасность.

## Статья 2: Создание собственного Docker Registry

### Зачем нужен собственный реестр?

- **Приватность** — конфиденциальные образы под контролем
    
- **Скорость** — быстрая доставка в локальной сети
    
- **Экономия трафика** — один раз загрузили, много раз распространили
    
- **Отказоустойчивость** — работа без внешних сервисов
    
- **CI/CD интеграция** — полный контроль
    

### Базовый запуск (небезопасный, только для тестов)

bash

docker run -d -p 5000:5000 --name registry registry:2
# Отправка образа
docker tag nginx:latest localhost:5000/my-nginx:latest
docker push localhost:5000/my-nginx:latest
# Проверка через API
curl http://localhost:5000/v2/_catalog

### Постоянное хранение (volume)

bash

docker run -d -p 5000:5000 --name registry \
  -v registry-data:/var/lib/registry \
  registry:2

### Настройка безопасности (TLS + аутентификация)

**1. Генерация самоподписанного сертификата:**

bash

mkdir -p certs && cd certs
openssl genrsa -out domain.key 2048
openssl req -new -x509 -sha256 -key domain.key -out domain.crt -days 365 \
  -subj "/CN=registry.example.com"

**2. Создание пользователя (htpasswd):**

bash

mkdir -p auth
htpasswd -Bc auth/htpasswd username   # запросит пароль

**3. Запуск Registry с TLS и аутентификацией:**

bash

docker run -d -p 5000:5000 --name registry \
  -v registry-data:/var/lib/registry \
  -v $(pwd)/certs:/certs \
  -v $(pwd)/auth:/auth \
  -e REGISTRY_HTTP_TLS_CERTIFICATE=/certs/domain.crt \
  -e REGISTRY_HTTP_TLS_KEY=/certs/domain.key \
  -e REGISTRY_AUTH=htpasswd \
  -e REGISTRY_AUTH_HTPASSWD_REALM="Registry Realm" \
  -e REGISTRY_AUTH_HTPASSWD_PATH=/auth/htpasswd \
  registry:2

**4. Настройка клиента (для самоподписанного сертификата):**

json

// /etc/docker/daemon.json
{
  "insecure-registries": ["registry.example.com:5000"]
}

**5. Аутентификация клиента:**

bash

docker login registry.example.com:5000

### Docker Compose — удобное управление

yaml

version: '3'
services:
  registry:
    image: registry:2
    ports:
      - "5000:5000"
    environment:
      REGISTRY_HTTP_TLS_CERTIFICATE: /certs/domain.crt
      REGISTRY_HTTP_TLS_KEY: /certs/domain.key
      REGISTRY_AUTH: htpasswd
      REGISTRY_AUTH_HTPASSWD_PATH: /auth/htpasswd
      REGISTRY_STORAGE_DELETE_ENABLED: "true"
    volumes:
      - ./data:/var/lib/registry
      - ./certs:/certs
      - ./auth:/auth

### Управление образами через API

| Действие                           | Команда                                                                               |
| ---------------------------------- | ------------------------------------------------------------------------------------- |
| Список репозиториев                | `curl -X GET https://registry:5000/v2/_catalog --user user:pass`                      |
| Список тегов                       | `curl -X GET https://registry:5000/v2/my-nginx/tags/list --user user:pass`            |
| Удаление образа (получить digest)  | `DIGEST=$(curl ... -H "Accept: ..." ... \| grep Docker-Content-Digest)`               |
| Удаление по digest                 | `curl -X DELETE https://registry:5000/v2/my-nginx/manifests/$DIGEST --user user:pass` |
| Сборка мусора (освобождение места) | `docker exec -it registry registry garbage-collect /etc/docker/registry/config.yml`   |

### Расширенные возможности

|Опция|Назначение|
|---|---|
|`REGISTRY_STORAGE=s3`|Хранилище в Amazon S3|
|`REGISTRY_NOTIFICATIONS_ENDPOINTS_0_URL`|Webhook уведомления о событиях|
|`REGISTRY_PROXY_REMOTEURL`|Режим кэширующего прокси для Docker Hub|

### Альтернативы для корпоративного использования

|Решение|Особенности|
|---|---|
|**Harbor**|Веб-интерфейс, сканирование уязвимостей, RBAC, репликация|
|**Nexus Repository OSS**|Мультиформатный (Docker, npm, Maven, PyPI)|
|**GitLab Container Registry**|Встроенный, интеграция с CI/CD|

### Итог

Собственный Docker Registry даёт полный контроль над образами. Для production обязательны **TLS** и **аутентификация**. Для постоянного хранения используйте **volumes** или облачное хранилище (S3). Для корпоративного использования рассмотрите **Harbor** или **Nexus**.
