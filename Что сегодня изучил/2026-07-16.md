## Статья 1: Ansible Galaxy — маркетплейс ролей и коллекций

### Что такое Ansible Galaxy

Ansible Galaxy — это официальный репозиторий (маркетплейс) готовых ролей и коллекций, которые можно использовать в своих проектах. Вместо того чтобы писать роль с нуля, можно взять готовую, протестированную и поддерживаемую сообществом.

**Веб-интерфейс:** [galaxy.ansible.com](https://galaxy.ansible.com/)

### Поиск ролей

bash

ansible-galaxy search nginx
ansible-galaxy search nginx --platforms Ubuntu
ansible-galaxy info geerlingguy.nginx

### Установка ролей

bash

# Установка в глобальную папку (~/.ansible/roles/)
ansible-galaxy install geerlingguy.nginx
# Установка в папку проекта (рядом с плейбуком)
ansible-galaxy install geerlingguy.nginx -p ./roles/

После установки роль подключается как обычная:

yaml

---
- name: Настройка веб-сервера
  hosts: webservers
  become: true
  roles:
    - geerlingguy.nginx

### `requirements.yml` — управление зависимостями

Файл, в котором перечислены все внешние роли и коллекции, используемые в проекте.

**Роли из Galaxy:**

yaml

# requirements.yml
---
roles:
  - name: geerlingguy.nginx
    version: "3.1.0"
  - name: geerlingguy.postgresql
    version: "3.4.0"
  - name: geerlingguy.docker
    version: "7.1.0"

**Роли из Git-репозитория:**

yaml

---
roles:
  - name: nginx
    src: https://github.com/company/ansible-role-nginx.git
    version: v2.0.0
    scm: git
  - name: internal-monitoring
    src: git@gitlab.company.local:devops/ansible-role-monitoring.git
    version: main
    scm: git

**Коллекции:**

yaml

---
roles:
  - name: geerlingguy.nginx
    version: "3.1.0"
collections:
  - name: community.general
    version: "8.0.0"
  - name: community.docker
    version: "3.4.0"
  - name: community.postgresql
    version: "3.2.0"

**Установка всего из `requirements.yml`:**

bash

ansible-galaxy install -r requirements.yml
ansible-galaxy collection install -r requirements.yml

### Когда писать свою роль, а когда брать готовую

|Ситуация|Решение|
|---|---|
|Стандартная задача (nginx, PostgreSQL, Docker)|✅ Использовать роль из Galaxy (geerlingguy, lean_delivery)|
|Специфичная конфигурация вашей компании|🟡 Взять за основу готовую роль и модифицировать (форк)|
|Уникальная задача, которой нет в Galaxy|❌ Писать свою роль с нуля|
|Требования безопасности (не доверяем внешним ролям)|❌ Писать свою роль с нуля|

**Популярные авторы:**

- **geerlingguy** — Jeff Geerling, один из самых популярных авторов (nginx, postgresql, docker, node_exporter)
    
- **lean_delivery** — хорошие роли для управления конфигами
    
- **devsec.hardening** — роли для безопасности (OS hardening, SSH hardening)

## Статья 2: Ansible Vault — управление секретами

### Зачем нужен Vault

Пароли, токены, приватные ключи и другие секреты нельзя хранить в открытом виде в Git. Ansible Vault шифрует файлы и отдельные переменные, позволяя хранить их в репозитории в зашифрованном виде.

### Шифрование файлов

**Создать новый зашифрованный файл:**

bash

ansible-vault create vars/secrets.yml

→ Спросит пароль, откроет редактор.

yaml

db_password: supersecret123
api_token: ghp_xxxxxxxxxxxx
smtp_password: mailpass456

**Зашифровать существующий файл:**

bash

ansible-vault encrypt vars/secrets.yml

**Расшифровать:**

bash

ansible-vault decrypt vars/secrets.yml

**Редактировать зашифрованный файл** (без сохранения расшифрованной версии на диск):

bash

ansible-vault edit vars/secrets.yml

**Посмотреть содержимое (без редактирования):**

bash

ansible-vault view vars/secrets.yml

### Шифрование отдельных переменных

Когда нужно зашифровать только одну переменную, а остальные оставить читаемыми.

bash

ansible-vault encrypt_string 'supersecret123' --name 'db_password'

Выдаст:

yaml

db_password: !vault |
    $ANSIBLE_VAULT;1.1;AES256
    31396637653233303738613064656338...

Вставляете это в обычный YAML-файл:

yaml

# group_vars/production.yml
app_port: 8080
app_env: production
log_level: warn
db_host: db.company.local
db_password: !vault |
    $ANSIBLE_VAULT;1.1;AES256
    31396637653233303738613064656338...

**Преимущество:** `git diff` показывает изменения во всех переменных, кроме зашифрованной.

### Запуск плейбуков с Vault

**Способ 1: Ввести пароль вручную**

bash

ansible-playbook site.yml --ask-vault-pass

**Способ 2: Файл с паролем**

bash

echo 'my_vault_password' > .vault_pass
chmod 600 .vault_pass
ansible-playbook site.yml --vault-password-file .vault_pass

**В `ansible.cfg`:**

ini

[defaults]
vault_password_file = .vault_pass

**⚠️ Важно:** `.vault_pass` добавить в `.gitignore`!

**Способ 3: Скрипт, который отдаёт пароль** (для CI/CD)

**`get_vault_pass.sh`:**

bash

#!/bin/bash
echo "$ANSIBLE_VAULT_PASSWORD"

**Запуск:**

bash

ansible-playbook site.yml --vault-password-file ./get_vault_pass.sh

В CI/CD задаётся переменная окружения `ANSIBLE_VAULT_PASSWORD` через секреты (GitLab CI/CD variables, GitHub Secrets и т.д.).

## Итог

|Инструмент|Назначение|Команды|
|---|---|---|
|**Ansible Galaxy**|Поиск и установка готовых ролей/коллекций|`ansible-galaxy search`, `install`, `info`|
|**requirements.yml**|Список зависимостей проекта|`ansible-galaxy install -r requirements.yml`|
|**Ansible Vault**|Шифрование секретов|`ansible-vault create`, `encrypt`, `decrypt`, `edit`, `view`|
|**Vault переменная**|Шифрование одной переменной|`ansible-vault encrypt_string`|
|**Запуск с Vault**|Передача пароля Ansible|`--ask-vault-pass`, `--vault-password-file`|
