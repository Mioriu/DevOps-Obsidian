# Саммари: Роли в Ansible

## Зачем нужны роли

Роли — способ разбить большой плейбук на логические блоки (nginx, PostgreSQL, мониторинг). Каждая роль — отдельная папка со своей структурой, тасками, шаблонами, хэндлерами, переменными.

**Ключевое преимущество:** роль можно **переиспользовать** в разных проектах или скачать готовую из Ansible Galaxy.

---

## Создание роли через `ansible-galaxy init`

bash

ansible-galaxy init roles/nginx

Создаёт полную структуру роли:

text

roles/nginx/
├── defaults/
│   └── main.yml      # переменные по умолчанию (низкий приоритет)
├── files/            # статические файлы (копируются как есть)
├── handlers/
│   └── main.yml      # хэндлеры роли
├── meta/
│   └── main.yml      # метаданные и зависимости
├── tasks/
│   └── main.yml      # основная логика (точка входа)
├── templates/        # шаблоны Jinja2
├── tests/            # тесты
└── vars/
    └── main.yml      # константы (высокий приоритет)

## Директории роли — что где лежит

### `tasks/main.yml` — основная логика

yaml

---
- name: Установить nginx
  apt:
    name: nginx
    state: present
    update_cache: yes
- name: Сгенерировать основной конфиг
  template:
    src: nginx.conf.j2
    dest: /etc/nginx/nginx.conf
    owner: root
    group: root
    mode: "0644"
  notify: Перезагрузить nginx
- name: Запустить и включить nginx
  service:
    name: nginx
    state: started
    enabled: yes

**Важно:** в тасках роли нет `hosts`, `become`, `vars` — это задаётся на уровне плейбука.

**Разбивка на несколько файлов:**

yaml

---
- name: Установка
  include_tasks: install.yml
- name: Настройка конфигов
  include_tasks: configure.yml
- name: Настройка SSL
  include_tasks: ssl.yml
  when: nginx_ssl_enabled | default(false)

### `handlers/main.yml` — хэндлеры роли

yaml

---
- name: Перезагрузить nginx
  service:
    name: nginx
    state: reloaded
- name: Перезапустить nginx
  service:
    name: nginx
    state: restarted

Таски из `tasks/` могут вызывать их через `notify`.

### `templates/` — шаблоны

Ansible автоматически ищет шаблоны в этой папке. В таске пишем просто `src: nginx.conf.j2`.

### `files/` — статические файлы

Копируются через модуль `copy`. Ansible ищет файлы в `files/` автоматически:

yaml

- name: Скопировать кастомную страницу
  copy:
    src: 50x.html
    dest: /usr/share/nginx/html/50x.html

### `defaults/main.yml` — переменные по умолчанию

**Самый низкий приоритет.** Легко переопределяются из `group_vars`, `host_vars`, плейбука.

yaml

---
nginx_worker_processes: auto
nginx_worker_connections: 1024
nginx_keepalive_timeout: 65
nginx_ssl_enabled: false
nginx_sites: []

**Зачем:** роль работает из коробки даже без задания переменных. Пользователь может переопределить что угодно.

### `vars/main.yml` — константы роли

**Высокий приоритет.** Сложно переопределить. Используется для значений, которые не должны меняться пользователем.

yaml

---
nginx_config_dir: /etc/nginx
nginx_log_dir: /var/log/nginx
nginx_pid_file: /run/nginx.pid

### `meta/main.yml` — информация о роли и зависимости

yaml

---
galaxy_info:
  author: your_name
  description: Роль для установки и настройки nginx
  license: MIT
  min_ansible_version: "2.14"
  platforms:
    - name: Ubuntu
      versions:
        - focal
        - jammy
dependencies:
  - role: common
  - role: firewall
    vars:
      firewall_allowed_ports:
        - 80
        - 443

`dependencies` — Ansible автоматически выполнит зависимые роли перед текущей.

### `tests/` — тесты

Минимальный плейбук для тестирования роли.

## Подключение роли в плейбук

### Способ 1: секция `roles` (классический)

yaml

---
- name: Настройка веб-серверов
  hosts: webservers
  become: true
  roles:
    - nginx
    - postgresql
    - monitoring

**С переменными:**

yaml

roles:
  - role: nginx
    vars:
      nginx_worker_processes: 8
      nginx_sites:
        - domain: app.company.com
          upstream_host: 127.0.0.1
          upstream_port: 8080

**С тегами:**

yaml

roles:
  - role: nginx
    tags: nginx

### Способ 2: `include_role` (динамическое подключение)

yaml

tasks:
  - name: Подготовка
    debug:
      msg: "Подготовка..."
  - name: Подключить роль nginx
    include_role:
      name: nginx
    vars:
      nginx_worker_processes: 4
  - name: После nginx
    debug:
      msg: "Nginx настроен!"

`include_role` позволяет встраивать роль в середину тасков и использовать в циклах.

### Способ 3: `import_role` (статическое подключение)

yaml

tasks:
  - name: Подключить роль nginx
    import_role:
      name: nginx

Разница:

- `import_role` — статически, на этапе парсинга (теги видны, нельзя в циклах)
    
- `include_role` — динамически, на этапе выполнения (можно в циклах, с динамическим `when`)

## Порядок выполнения: `pre_tasks` → `roles` → `tasks` → `post_tasks`

yaml

- name: Настройка серверов
  hosts: all
  become: true
  pre_tasks:
    - name: Обновить кэш пакетов
      apt:
        update_cache: yes
  roles:
    - nginx
    - postgresql
  tasks:
    - name: Финальная проверка
      debug:
        msg: "Всё настроено!"
  post_tasks:
    - name: Отправить уведомление
      debug:
        msg: "Деплой завершён"

**Порядок:**

1. `pre_tasks` → до ролей
    
2. `roles`
    
3. `tasks` → после ролей
    
4. `post_tasks` → в самом конце
    

Хэндлеры вызываются после каждого блока.

---

## Где Ansible ищет роли

1. `roles/` рядом с плейбуком
    
2. Путь из `roles_path` в `ansible.cfg`
    
3. `~/.ansible/roles/`
    
4. `/etc/ansible/roles/`
    

**Настройка в `ansible.cfg`:**

ini

[defaults]
roles_path = ./roles:/opt/shared-roles

## Полный пример проекта

text

my-project/
├── ansible.cfg
├── inventory.ini
├── site.yml
├── group_vars/
│   ├── all.yml
│   ├── webservers.yml
│   └── databases.yml
├── host_vars/
│   └── server1.yml
└── roles/
    ├── common/
    ├── nginx/
    ├── postgresql/
    └── monitoring/

**`site.yml`:**

yaml

---
- name: Общая настройка всех серверов
  hosts: all
  become: true
  roles:
    - common
- name: Настройка веб-серверов
  hosts: webservers
  become: true
  roles:
    - role: nginx
      tags: nginx
- name: Настройка баз данных
  hosts: databases
  become: true
  roles:
    - role: postgresql
      tags: database
- name: Настройка мониторинга
  hosts: monitoring
  become: true
  roles:
    - role: monitoring
      tags: monitoring

## Итог

| Компонент    | Назначение                                 |
| ------------ | ------------------------------------------ |
| `tasks/`     | Основная логика роли                       |
| `handlers/`  | Хэндлеры (перезагрузка сервисов)           |
| `templates/` | Шаблоны Jinja2                             |
| `files/`     | Статические файлы                          |
| `defaults/`  | Переменные по умолчанию (низкий приоритет) |
| `vars/`      | Константы (высокий приоритет)              |
| `meta/`      | Метаданные и зависимости                   |
| `tests/`     | Тесты                                      |

**Правила:**

- Роль — независимый блок, не знает на каких серверах работает
    
- Используй `defaults/` для настраиваемых переменных
    
- Используй `vars/` для констант
    
- Секция `roles` в плейбуке — классический способ подключения
    
- `include_role` — когда нужна гибкость (циклы, динамические условия)
    
- Хэндлеры роли автоматически доступны в тасках роли
