### Саммари 1: Создание репозитория и базовая архитектура

**Два способа начать работу:**

1. **Инициализация (`git init`):** Создает новый пустой репозиторий. Появляется скрытая папка `.git`, содержащая всю внутреннюю инфраструктуру (объекты, ссылки, конфиги). Файлы проекта еще не отслеживаются — их нужно добавить явно.
    
2. **Клонирование (`git clone`):** Создает копию существующего репозитория (например, с GitHub), загружая полную историю и создавая рабочую копию последней версии.
    

**Базовая настройка:** Перед работой необходимо задать имя и email пользователя (`git config --global user.name/email`), которые будут записаны в каждый коммит.

**Три состояния и жизненный цикл файлов:**

- **Рабочая директория:** Файлы, с которыми идет работа (могут быть _измененными_ или _неотслеживаемыми_).
    
- **Область подготовки (индекс):** Промежуточная зона. Файлы попадают сюда через `git add` (становятся _подготовленными_).
    
- **Репозиторий:** Место постоянного хранения зафиксированных изменений (коммитов). Файл считается _неизмененным_, если его состояние совпадает с последним коммитом.
    

**Типичный цикл:** Изменяем файлы → Добавляем в индекс (`git add`) → Фиксируем коммит (`git commit`).

### Саммари 2: Управление изменениями (Status, Diff, Add, Commit)

Четыре основные команды формируют повседневный рабочий процесс.

**1. `git status` (обзор состояния):**  
Показывает текущую ветку и разделяет изменения на категории:

- _Changes not staged:_ файлы изменены, но не добавлены в индекс.
    
- _Untracked files:_ новые файлы, которые Git не отслеживает.
    
- _Changes to be committed:_ файлы, уже добавленные в индекс и готовые к коммиту.
    

**2. `git diff` (детали изменений):**  
Показывает _содержательные_ различия в строках кода.

- `git diff`: изменения в рабочей директории (еще не в индексе).
    
- `git diff --staged`: изменения, которые уже подготовлены и попадут в следующий коммит.
    

**3. `git add` (подготовка):**  
Перемещает изменения из рабочей директории в индекс. Ключевые флаги:

- `git add .` или `-A`: добавить все изменения.
    
- `git add -p`: интерактивный режим для частичного добавления (позволяет взять в коммит только часть изменений из файла).
    

**4. `git commit` (фиксация):**  
Создает снимок состояния индекса.

- `git commit -m "Сообщение"`: стандартный коммит.
    
- `git commit -am "..."`: объединяет `add` и `commit` для уже отслеживаемых файлов.
    
- `git commit --amend`: изменяет последний коммит (исправление сообщения или добавление забытых файлов).

### Саммари 3: История и навигация (Log, Show, Diff)

**Просмотр истории (`git log`):**  
Показывает список коммитов (от новых к старым) с хешем, автором, датой и сообщением.

- `--oneline`: компактный вид (короткий хеш + сообщение).
    
- `--graph`: визуализирует ветвление и слияния.
    
- `--stat`: показывает статистику изменений (добавлено/удалено строк).
    
- `-p`: показывает полный diff для каждого коммита.
    
- Фильтры: `--author`, `--since`, `--grep`, а также просмотр истории конкретного файла (`git log -- filename`).
    

**Навигация по ссылкам:**

- **HEAD:** указатель на текущий коммит.
    
- **Относительные ссылки:** `~` (родитель по прямой) и `^` (родитель при слиянии). Пример: `HEAD~2` (два коммита назад), `HEAD^2` (второй родитель в merge-коммите).
    

**Просмотр коммита (`git show`):**  
Показывает подробную информацию о конкретном коммите (автор, дату, изменения). Использование: `git show HEAD~1` или `git show a5f3b8c`.

**Поиск и сравнение:**

- `git log -S "текст"`: найти коммиты, в которых менялось количество вхождений строки.
    
- `git blame`: показывает, кто и когда изменял каждую строку файла.
    
- `git diff HEAD~2 HEAD`: сравнить состояния между двумя коммитами.

### Саммари 4: Отмена изменений (Restore, Checkout, Clean)

Современные команды (Git 2.23+) разделили функции `checkout`. Для отмены изменений теперь используется `git restore`.

**1. Отмена в рабочей директории (не добавлены в индекс):**  
Вернуть файл к состоянию последнего коммита, отбросив правки:

- `git restore README.md`
    
- _Классический способ:_ `git checkout -- README.md`
    

**2. Отмена в индексе (уже сделали `git add`):**  
Убрать файл из индекса, но оставить изменения в файлах:

- `git restore --staged README.md`
    
- _Классический способ:_ `git reset HEAD README.md`
    

**3. Удаление неотслеживаемых файлов (`git clean`):**  
Удаляет файлы, которые не находятся под версионным контролем (логи, временные файлы).

- `git clean -n`: показать, что будет удалено (безопасный режим).
    
- `git clean -fd`: удалить файлы и директории.
    

**4. Восстановление из других коммитов:**  
Можно восстановить файл из любого места (даже удаленный):

- `git restore --source=HEAD~2 README.md` (взять версию из коммита, отстоящего на 2 шага назад).
    

**Меры предосторожности:** Отмена изменений может привести к потере данных. Рекомендуется перед массовым сбросом использовать `git stash` для временного сохранения или делать резервные ветки.
