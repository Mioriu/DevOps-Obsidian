## Статья 1: Управление Docker Registry через API и интеграция с CI/CD

### Основная идея

Docker Registry предоставляет **RESTful API** для программного управления репозиториями и образами. Это позволяет автоматизировать работу с реестром и интегрировать его в CI/CD пайплайны.

### Базовые эндпоинты API

|Эндпоинт|Назначение|Пример|
|---|---|---|
|`GET /v2/`|Проверка доступности API|`curl https://registry:5000/v2/`|
|`GET /v2/_catalog`|Список репозиториев|`curl https://registry:5000/v2/_catalog`|
|`GET /v2/<repo>/tags/list`|Список тегов репозитория|`curl https://registry:5000/v2/nginx/tags/list`|

### Аутентификация в API

**Basic Auth:**

bash

curl -X GET https://registry:5000/v2/_catalog --user username:password

**Bearer Token:**

bash

TOKEN=$(curl -s -H "Authorization: Basic $(echo -n 'user:pass' | base64)" \
  "https://registry:5000/v2/token?service=registry&scope=repository:nginx:pull" \
  | jq -r '.token')
curl -H "Authorization: Bearer $TOKEN" https://registry:5000/v2/nginx/tags/list

### Управление образами

**Получение digest (хеша) образа:**

bash

DIGEST=$(curl -v -H "Accept: application/vnd.docker.distribution.manifest.v2+json" \
  -X GET https://registry:5000/v2/nginx/manifests/latest \
  --user user:pass 2>&1 | grep Docker-Content-Digest | awk '{print $3}')

**Удаление образа по digest:**

bash

curl -X DELETE https://registry:5000/v2/nginx/manifests/$DIGEST --user user:pass

**Очистка дискового пространства (сборщик мусора):**

bash

docker exec -it registry registry garbage-collect /etc/docker/registry/config.yml

### Интеграция с GitLab CI/CD

yaml

stages:
  - build
  - test
  - deploy
variables:
  REGISTRY_URL: registry.example.com:5000
  IMAGE_NAME: $REGISTRY_URL/myapp
  IMAGE_TAG: $CI_COMMIT_SHORT_SHA
build:
  stage: build
  image: docker:20.10
  services:
    - docker:20.10-dind
  before_script:
    - echo $REGISTRY_PASSWORD | docker login $REGISTRY_URL -u $REGISTRY_USERNAME --password-stdin
  script:
    - docker build -t $IMAGE_NAME:$IMAGE_TAG .
    - docker push $IMAGE_NAME:$IMAGE_TAG
  after_script:
    - docker logout $REGISTRY_URL

### Интеграция с GitHub Actions

yaml

name: Build and Push Docker Image
on:
  push:
    branches: [ main ]
jobs:
  build-and-push:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - uses: docker/login-action@v1
        with:
          registry: registry.example.com:5000
          username: ${{ secrets.REGISTRY_USERNAME }}
          password: ${{ secrets.REGISTRY_PASSWORD }}
      - uses: docker/build-push-action@v2
        with:
          push: true
          tags: registry.example.com:5000/myapp:${{ github.sha }}

### Автоматическая очистка старых образов

bash

#!/bin/bash
REGISTRY_URL="https://registry.example.com:5000"
REPO="myapp"
KEEP_LAST=5
# Получение старых тегов (последние KEEP_LAST не трогаем)
TAGS=$(curl -s --user $USER:$PASS $REGISTRY_URL/v2/$REPO/tags/list \
  | jq -r '.tags[]' | sort -r | tail -n +$((KEEP_LAST+1)))
for TAG in $TAGS; do
  DIGEST=$(curl -s -H "Accept: application/vnd.docker.distribution.manifest.v2+json" \
    --user $USER:$PASS $REGISTRY_URL/v2/$REPO/manifests/$TAG | jq -r '.config.digest')
  curl -X DELETE --user $USER:$PASS $REGISTRY_URL/v2/$REPO/manifests/$DIGEST
done
docker exec -it registry registry garbage-collect /etc/docker/registry/config.yml

### Webhook для автоматического деплоя

**Настройка Registry:**

yaml

environment:
  REGISTRY_NOTIFICATIONS_ENDPOINTS_0_NAME: webhook
  REGISTRY_NOTIFICATIONS_ENDPOINTS_0_URL: https://deployment.example.com/hooks/registry
  REGISTRY_NOTIFICATIONS_ENDPOINTS_0_HEADERS_Authorization: "Bearer token"

**Обработчик webhook (Node.js/Express):**

javascript

app.post('/hooks/registry', (req, res) => {
  if (req.headers.authorization !== 'Bearer token') return res.status(401).send('Unauthorized');
  
  for (const event of req.body.events) {
    if (event.action === 'push') {
      exec('./deploy.sh');  // запуск деплоя
    }
  }
  res.status(200).send('OK');
});

### Стратегии тегирования образов

bash

VERSION=$(cat VERSION)
GIT_COMMIT=$(git rev-parse --short HEAD)
docker build -t $REGISTRY_URL/myapp:latest .
docker tag $REGISTRY_URL/myapp:latest $REGISTRY_URL/myapp:$VERSION
docker tag $REGISTRY_URL/myapp:latest $REGISTRY_URL/myapp:$GIT_COMMIT
docker push $REGISTRY_URL/myapp:latest
docker push $REGISTRY_URL/myapp:$VERSION
docker push $REGISTRY_URL/myapp:$GIT_COMMIT

### Итог

- Docker Registry API позволяет автоматизировать управление образами
    
- CI/CD интеграция (GitLab, GitHub Actions) — стандартная практика
    
- Автоматическая очистка старых образов экономит место
    
- Webhook'и позволяют автоматически деплоить при появлении новых образов

## Статья 2: Ограничение ресурсов и настройка cgroups

### Основная идея

**cgroups** (control groups) — технология ядра Linux для ограничения, учёта и изоляции ресурсов (CPU, память, I/O, сеть). Docker использует cgroups, чтобы контейнеры не "съедали" все ресурсы хоста.

### Ограничение CPU

|Параметр|Назначение|Пример|
|---|---|---|
|`--cpus`|Количество ядер CPU|`--cpus=2` (максимум 2 ядра)|
|`--cpu-shares`|Относительный вес (1024 по умолчанию)|`--cpu-shares=512` (половина веса)|
|`--cpu-period` + `--cpu-quota`|Тонкая настройка квоты|`--cpu-period=100000 --cpu-quota=50000` (50% ядра)|
|`--cpuset-cpus`|Привязка к конкретным ядрам|`--cpuset-cpus="0,3"` (только ядра 0 и 3)|

**Пример с --cpus:**

bash

docker run --cpus=1.5 nginx   # ограничение 1.5 ядрами CPU

**Как работает --cpu-shares:**

- При конкуренции за CPU, время распределяется пропорционально весам
    
- Если контейнер один — может использовать 100% CPU независимо от shares
    

### Ограничение памяти

|Параметр|Назначение|Пример|
|---|---|---|
|`--memory`|Жёсткий лимит памяти|`--memory=1g` (максимум 1 ГБ)|
|`--memory-swap`|Общий лимит память + своп|`--memory=1g --memory-swap=2g`|
|`--memory-reservation`|Мягкий лимит (при нехватке)|`--memory-reservation=800m`|
|`--memory-swappiness`|Склонность к использованию свопа (0-100)|`--memory-swappiness=0`|
|`--oom-kill-disable`|Отключить OOM-киллер|`--oom-kill-disable` (только с `--memory`)|

**Примеры:**

bash

docker run --memory=1g nginx                    # жёсткий лимит 1 ГБ
docker run --memory=1g --memory-swap=2g nginx   # 1 ГБ RAM + 1 ГБ свопа
docker run --memory-swap=-1 nginx               # неограниченный своп

### Ограничение I/O операций

|Параметр|Назначение|Пример|
|---|---|---|
|`--device-read-bps`|Лимит чтения (байт/сек)|`--device-read-bps /dev/sda:10mb`|
|`--device-write-bps`|Лимит записи (байт/сек)|`--device-write-bps /dev/sda:5mb`|
|`--device-read-iops`|Лимит операций чтения/сек|`--device-read-iops /dev/sda:1000`|
|`--device-write-iops`|Лимит операций записи/сек|`--device-write-iops /dev/sda:500`|

### Ulimits (ограничения процессов)

bash

docker run --ulimit nofile=1024:2048 --ulimit nproc=100:200 nginx

**Основные типы ulimits:**

|Тип|Назначение|
|---|---|
|`nofile`|Максимальное количество открытых файлов|
|`nproc`|Максимальное количество процессов|
|`core`|Размер core-файлов|
|`cpu`|Максимальное время CPU (сек)|
|`stack`|Максимальный размер стека|
|`rss`|Максимальный размер резидентной памяти|

### Пример полного ограничения контейнера

bash

docker run \
  --name limited-container \
  --cpus=1.5 \
  --cpu-shares=512 \
  --memory=1g \
  --memory-swap=1.5g \
  --memory-reservation=800m \
  --device-read-bps /dev/sda:10mb \
  --device-write-bps /dev/sda:8mb \
  --ulimit nofile=1024:4096 \
  --ulimit nproc=50:100 \
  nginx

### Проверка ограничений

**Через docker stats:**

bash

docker stats limited-container

**Через docker inspect:**

bash

docker inspect limited-container | grep -A 15 "HostConfig"

**Через cgroups напрямую:**

bash

cat /sys/fs/cgroup/cpu/docker/<container_id>/cpu.cfs_quota_us
cat /sys/fs/cgroup/memory/docker/<container_id>/memory.limit_in_bytes

### Ограничения в Docker Compose

yaml

version: '3'
services:
  webapp:
    image: nginx
    deploy:
      resources:
        limits:
          cpus: '0.5'
          memory: 512M
        reservations:
          cpus: '0.25'
          memory: 256M
    ulimits:
      nofile:
        soft: 1024
        hard: 4096

### Итог

|Ресурс|Основные параметры|
|---|---|
|**CPU**|`--cpus`, `--cpu-shares`, `--cpuset-cpus`|
|**Память**|`--memory`, `--memory-swap`, `--memory-reservation`|
|**I/O**|`--device-read-bps`, `--device-write-bps`, `--device-*-iops`|
|**Процессы/файлы**|`--ulimit nofile`, `--ulimit nproc`|

Правильное ограничение ресурсов — обязательная практика для production-сред, предотвращающая ситуацию, когда один контейнер "съедает" все ресурсы хоста и нарушает работу других сервисов.
