[[Продвинутые инструкции]]

# Саммари: Продвинутые инструкции Dockerfile

## Основная идея

Базовых инструкций (`FROM`, `RUN`, `COPY`, `CMD`, `ENTRYPOINT`) часто достаточно, но для реальных проектов требуются более тонкие настройки. Продвинутые инструкции позволяют управлять безопасностью, метаданными, проверкой здоровья и поведением при сборке.

---

## Таблица всех продвинутых инструкций

|Инструкция|Назначение|Время действия|Пример|
|---|---|---|---|
|`ARG`|Переменные только на этапе сборки|build time|`ARG VERSION=1.0`|
|`LABEL`|Метаданные образа (автор, версия)|build time (сохраняется)|`LABEL maintainer="dev@example.com"`|
|`USER`|Запуск от непривилегированного пользователя|runtime|`USER appuser`|
|`VOLUME`|Объявление точки монтирования для данных|runtime|`VOLUME /data`|
|`ONBUILD`|Триггер для дочерних образов|build time (отложенный)|`ONBUILD COPY . /app`|
|`STOPSIGNAL`|Сигнал при остановке контейнера|runtime|`STOPSIGNAL SIGQUIT`|
|`HEALTHCHECK`|Проверка "живости" контейнера|runtime (периодически)|`HEALTHCHECK CMD curl -f http://localhost/health`|
|`SHELL`|Смена shell для выполнения команд|build time|`SHELL ["/bin/bash", "-c"]`|

---

## 1. ARG — переменные сборки

**Зачем:** Передать параметр только на этапе сборки (не сохраняется в образе). Например, версию пакета или временный секрет для скачивания зависимостей.

dockerfile

FROM python:3.9
ARG MY_PACKAGE_VERSION=1.2.3
RUN pip install my_package==$MY_PACKAGE_VERSION

**Сборка с переопределением:**

bash

docker build --build-arg MY_PACKAGE_VERSION=2.0.0 -t my-image .

**Отличие от `ENV`:** `ARG` не видна в работающем контейнере, только во время `docker build`.

---

## 2. LABEL — метаданные образа

**Зачем:** Добавить информацию об образе — автор, версию, описание, ссылку на репозиторий. Просматривается через `docker image inspect`.

dockerfile

FROM node:16
LABEL maintainer="prosto@devops.com" \
      version="1.0.0" \
      description="My Node.js Service"

---

## 3. USER — запуск от непривилегированного пользователя

**Зачем:** Безопасность. По умолчанию контейнеры часто запускаются от `root`. Лучше создать отдельного пользователя.

dockerfile

FROM alpine:3.17
RUN adduser -D myuser          # -D = без пароля
USER myuser
WORKDIR /home/myuser
COPY app ./
CMD ["./app"]

Если процесс скомпрометируют, он не получит root-доступ к хосту.

---

## 4. VOLUME — точка монтирования для данных

**Зачем:** Объявить директорию, которая должна храниться вне контейнера (чтобы данные не терялись при пересоздании).

dockerfile

FROM postgres:15
VOLUME /var/lib/postgresql/data

При запуске Docker создаёт анонимный том. В production обычно управляют томами через `docker-compose.yml`, а не только через `VOLUME` в Dockerfile.

---

## 5. ONBUILD — отложенные инструкции для дочерних образов

**Зачем:** Создать "шаблонный" базовый образ, который при наследовании автоматически выполняет дополнительные действия.

**Родительский образ (`my-base`):**

dockerfile

FROM node:16
ONBUILD COPY package*.json /app/
ONBUILD RUN npm install

**Дочерний образ (пользовательский):**

dockerfile

FROM my-base:latest
COPY . /app
CMD ["npm", "start"]

→ При сборке дочернего образа автоматически сработают `ONBUILD COPY` и `ONBUILD RUN` из родителя.

**Предупреждение:** Создаёт неявную логику, используйте осторожно.

---

## 6. STOPSIGNAL — смена сигнала остановки

**Зачем:** По умолчанию `docker stop` посылает `SIGTERM`. Некоторые приложения ожидают другой сигнал (например, `SIGQUIT`).

dockerfile

FROM ubuntu:22.04
STOPSIGNAL SIGQUIT
CMD ["/usr/bin/my-daemon"]

---

## 7. HEALTHCHECK — проверка "живости" контейнера

**Зачем:** Docker может периодически проверять, работает ли приложение корректно (не только запущено ли). Статус: `healthy` / `unhealthy`.

dockerfile

FROM nginx:alpine
HEALTHCHECK --interval=30s --timeout=5s --retries=3 \
  CMD curl -f http://localhost/health || exit 1
CMD ["nginx", "-g", "daemon off;"]

**Проверка статуса:** `docker ps` — в колонке `STATUS` видно `healthy` / `unhealthy`.

**Параметры:**

- `--interval` — как часто проверять (по умолч. 30s)
    
- `--timeout` — таймаут на проверку
    
- `--retries` — сколько неудачных попыток до `unhealthy`
    
- `--start-period` — время на инициализацию (проверки не считаются ошибками)
    

---

## 8. SHELL — смена shell для выполнения команд

**Зачем:** По умолчанию в Linux используется `sh -c`, в Windows — `cmd /S /C`. Можно переключить на `bash` или `powershell`.

dockerfile

FROM ubuntu:22.04
SHELL ["/bin/bash", "-c"]
RUN echo "Now we use bash" && set -eux

Особенно полезно в Windows-образах для перехода на PowerShell.

---

## Итог: когда что использовать

|Ситуация|Инструкция|
|---|---|
|Передать версию пакета при сборке|`ARG`|
|Добавить информацию об образе (автор, версия)|`LABEL`|
|Запустить процесс не от root (безопасность)|`USER`|
|Сохранить данные базы/логов между перезапусками|`VOLUME`|
|Создать шаблонный образ для наследования|`ONBUILD`|
|Изменить сигнал при `docker stop`|`STOPSIGNAL`|
|Проверять, жив ли контейнер (не только запущен)|`HEALTHCHECK`|
|Использовать bash вместо sh в `RUN`|`SHELL`|
