# Саммари статей по Docker: Сети и Docker Compose

## Статья 1: Сетевая подсистема Docker (Docker Networking)

### Основная идея

Docker Networking управляет связью контейнеров между собой, с хост-машиной и с внешним миром. По умолчанию контейнер запускается в изолированном сетевом пространстве (Network Namespace).

### Концепция: CNM (Container Network Model)

- У каждого контейнера свой **виртуальный IP-адрес**
    
- Контейнеры могут подключаться к одной или нескольким **сетям**
    
- Драйвер сети определяет правила маршрутизации и изоляции
    

### Основные сетевые драйверы

|Драйвер|Как работает|DNS по имени|Сценарий|
|---|---|---|---|
|**Bridge (default)**|Виртуальный мост `docker0`, внутренние IP (172.17.x.x), NAT для выхода в интернет|❌ Нет|Быстрые тесты|
|**User-defined Bridge**|Своя сеть, контейнеры видят друг друга по IP|✅ **Да**|Стандарт для приложений|
|**Host**|Контейнер использует сетевой стек хоста напрямую|N/A|High-load, max производительность|
|**None**|Только `lo` (localhost), полная изоляция|Нет|Безопасные задачи|

### Важный нюанс про DNS

**В стандартной сети `bridge` (дефолтной) контейнеры не видят друг друга по именам, только по IP!**

Чтобы работало обращение по имени (`ping database`), нужно создать **свою** сеть (User-defined bridge):

bash

docker network create my-app-net
docker run -d --name db --network my-app-net postgres
docker run -d --name app --network my-app-net myapp
# app может обращаться к db по имени "db"

### Публикация портов (Port Mapping)

Контейнеры в режиме `bridge` имеют внутренние IP, недоступные извне. Чтобы достучаться до контейнера, нужно пробросить порт:

bash

docker run -d -p 8080:80 nginx

- `8080` — порт на хост-машине
    
- `80` — порт внутри контейнера
    

### DNS и Service Discovery

Docker имеет встроенный DNS-сервер (адрес `127.0.0.11` внутри контейнера).

**Как работает:**

1. Создаёте свою сеть: `docker network create my-net`
    
2. Запускаете контейнер с именем: `docker run -d --name db --network my-net postgres`
    
3. Другие контейнеры в этой сети обращаются к нему по имени `db`
    

### Команды для работы с сетями

|Команда|Назначение|
|---|---|
|`docker network ls`|Список сетей|
|`docker network create --driver bridge my-net`|Создать сеть|
|`docker network connect my-net my-container`|Подключить контейнер к сети (на лету)|
|`docker network inspect my-net`|Детали сети (IP, подключённые контейнеры)|
|`docker network disconnect my-net my-container`|Отключить контейнер|

### Итог по сетевым драйверам

- **Bridge (default)** — только для быстрых тестов, нет DNS по именам
    
- **User-defined Bridge** — стандарт для приложений, есть DNS
    
- **Host** — максимальная производительность, нет изоляции
    
- **None** — полная изоляция

## Статья 2: Docker Compose — управление мульти-контейнерной средой

### Основная идея

**Docker Compose** — инструмент для определения и запуска многоконтейнерных приложений. Вместо множества `docker run` с кучей флагов — один файл `docker-compose.yml` и одна команда.

### Структура `docker-compose.yml`

yaml

version: '3.8'           # версия схемы (необязательна в новых версиях)
services:                # сервисы (контейнеры)
  webapp:
    build: .             # собрать из Dockerfile
    ports:
      - "8000:8000"
    environment:
      - DB_HOST=postgres_db   # обращение по имени сервиса!
    depends_on:
      - postgres_db
    networks:
      - backend-net
  postgres_db:
    image: postgres:14-alpine
    restart: always
    environment:
      POSTGRES_USER: admin
      POSTGRES_PASSWORD: secret
    volumes:
      - db_data:/var/lib/postgresql/data
    networks:
      - backend-net
volumes:
  db_data:               # именованный том
networks:
  backend-net:           # пользовательская сеть
    driver: bridge

### Ключевые директивы

|Директива|Назначение|
|---|---|
|`build: .`|Собрать образ из Dockerfile в текущей папке|
|`image: postgres`|Использовать готовый образ из реестра|
|`ports`|Проброс портов (`"хост:контейнер"`)|
|`environment`|Переменные окружения|
|`depends_on`|Порядок запуска (но не проверяет готовность!)|
|`volumes`|Монтирование томов|
|`restart: always`|Политика перезапуска|

### Магия DNS в Compose

Внутри сети Compose создаёт DNS-записи по **именам сервисов**. Если сервис называется `postgres_db`, приложение подключается к `postgres_db`.

### Основные команды (Docker Compose v2)

|Команда|Назначение|
|---|---|
|`docker compose up`|Запустить (логи в консоль)|
|`docker compose up -d`|Запустить в фоне (detached)|
|`docker compose down`|Остановить и удалить контейнеры, сети|
|`docker compose down -v`|Удалить **и тома** (осторожно!)|
|`docker compose ps`|Статус контейнеров|
|`docker compose logs -f`|Логи всех сервисов|
|`docker compose logs -f webapp`|Логи конкретного сервиса|
|`docker compose exec webapp bash`|Зайти внутрь контейнера|
|`docker compose build`|Пересобрать образы|

### Переменные окружения и `.env`

**Плохая практика:** хардкодить пароли в `docker-compose.yml`

**Хорошая практика:** использовать `.env` файл

**`.env`:**

ini

POSTGRES_USER=admin
POSTGRES_PASSWORD=super_secret
APP_PORT=8080

**`docker-compose.yml`:**

yaml

services:
  db:
    image: postgres
    environment:
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
  webapp:
    ports:
      - "${APP_PORT}:80"

### Именование проектов

Docker Compose группирует ресурсы по **имени проекта** (по умолчанию — название папки).

Если папка называется `my_project`, то:

- Контейнеры: `my_project-webapp-1`, `my_project-db-1`
    
- Сеть: `my_project_default`
    

Это позволяет запускать несколько копий окружения без конфликтов.

### Итог

|Если нужно|Используйте|
|---|---|
|Запустить 2+ связанных контейнера|Docker Compose|
|Обращение контейнеров по имени|User-defined сеть в Compose|
|Хранение паролей вне конфига|`.env` файл|
|Пересобрать образ после изменения кода|`docker compose build && docker compose up`|
