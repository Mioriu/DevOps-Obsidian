### Тезисно: LVM (Logical Volume Manager) — гибкое управление дисками

**1. Зачем нужен LVM (Проблемы обычных разделов)**

- С обычными разделами:
    
    - Нельзя легко увеличить размер, если закончилось место.
        
    - Нельзя объединить несколько дисков в один том.
        
    - Сложно сделать моментальный снимок (снапшот).
        
    - Сложно перенести данные между дисками без остановки.
        
- **LVM добавляет слой абстракции**, решая эти проблемы.
    

**2. Архитектура LVM (Три уровня)**

- **PV (Physical Volume):** Физический том. Обычный диск или раздел, подготовленный для LVM (`pvcreate /dev/sdb`).
    
- **VG (Volume Group):** Группа томов. Пул хранилища, объединяющий несколько PV в единое пространство (`vgcreate storage /dev/sdb /dev/sdc`).
    
- **LV (Logical Volume):** Логический том. "Виртуальный раздел", который создается из свободного места VG. Именно его форматируют (`mkfs.ext4`) и монтируют (`mount`).
    

**3. Создание LVM (Пошагово)**

- **Шаг 1 — PV:** `sudo pvcreate /dev/sdb /dev/sdc`
    
- **Шаг 2 — VG:** `sudo vgcreate storage /dev/sdb /dev/sdc`
    
- **Шаг 3 — LV:**
    
    - `sudo lvcreate -n home -L 150G storage` (том на 150 ГБ).
        
    - `sudo lvcreate -n projects -l 50%FREE storage` (том на 50% от оставшегося места).
        
- **Шаг 4 — Форматирование и монтирование:** `mkfs.ext4 /dev/storage/home`, затем `mount /dev/storage/home /mnt/home`.
    
- **Просмотр состояния:**
    
    - `pvs` / `pvdisplay` — физические тома.
        
    - `vgs` / `vgdisplay` — группы томов.
        
    - `lvs` / `lvdisplay` — логические тома.
        

**4. Главное преимущество: Изменение размера на лету**

- **Увеличение (расширение):**
    
    1. Расширить LV: `lvextend -L +50G /dev/storage/home` (добавить 50 ГБ).
        
    2. Расширить файловую систему: `resize2fs /dev/storage/home` (для ext4) или `xfs_growfs /mnt/projects` (для XFS).
        
- **Уменьшение (только для ext4 и с осторожностью!):**
    
    1. Уменьшить ФС: `resize2fs /dev/storage/backup 80G`.
        
    2. Уменьшить LV: `lvreduce -L 80G /dev/storage/backup`.
        

**5. Продвинутые возможности**

- **Добавление нового диска в VG:**
    
    - `pvcreate /dev/sdd`
        
    - `vgextend storage /dev/sdd`
        
- **Снимки (Snapshots):** Моментальный слепок тома для бэкапов или тестирования.
    
    - Создание: `lvcreate -L 10G -s -n home_snapshot /dev/storage/home`.
        
    - Восстановление: `lvconvert --merge /dev/storage/home_snapshot`.
        
- **Перемещение данных между дисками (pvmove):** Позволяет перенести данные с одного физического диска на другой без остановки системы (`pvmove /dev/sdb`), чтобы затем удалить старый диск из VG (`vgreduce storage /dev/sdb`).
    
- **Thin Provisioning (Тонкое выделение):** Создание томов, которые "резервируют" место виртуально, но физически занимают его только по мере записи данных. Позволяет создавать больше суммарных LV, чем физический размер VG.
    
- **RAID через LVM:** Возможность создавать зеркала (RAID1) и массивы с четностью (RAID5) средствами LVM.
    

**6. Практические аспекты**

- **Миграция с обычных разделов на LVM:** Создать новый VG на новом диске, скопировать данные (`rsync`), перемонтировать, обновить `/etc/fstab`, затем добавить старый раздел в VG.
    
- **Резервное копирование метаданных:** `vgcfgbackup storage` (сохраняет конфигурацию VG в `/etc/lvm/backup/`). Восстановление: `vgcfgrestore storage`.
    
- **Решение типичных проблем:**
    
    - "Device is busy" — найти процессы (`lsof` / `fuser`) и отмонтировать.
        
    - Сбой диска — использовать `vgreduce --removemissing` для удаления недоступного PV из VG (с потерей данных на нем).
