# Саммари статей по пакетным менеджерам и SSH

## Статья 1: Пакетные менеджеры — apt, yum, dnf

### Основные команды

| Действие                | Debian/Ubuntu (apt)    | CentOS/RHEL (yum/dnf) |
| ----------------------- | ---------------------- | --------------------- |
| Установка               | `apt install nginx`    | `yum install nginx`   |
| Удаление (без конфигов) | `apt remove nginx`     | `yum remove nginx`    |
| Удаление (с конфигами)  | `apt purge nginx`      | —                     |
| Обновление индекса      | `apt update`           | —                     |
| Обновление пакетов      | `apt upgrade`          | `yum update`          |
| Поиск                   | `apt search nginx`     | `yum search nginx`    |
| Информация              | `apt show nginx`       | `yum info nginx`      |
| Установленные пакеты    | `apt list --installed` | `yum list installed`  |

**Важно:** `apt update` — обновляет индекс (список доступных пакетов), `apt upgrade` — обновляет сами пакеты. Сначала всегда `update`, потом `upgrade`.

### Репозитории

**Debian/Ubuntu — `/etc/apt/sources.list` и `/etc/apt/sources.list.d/`**

Добавление репозитория Docker (пример):

bash

curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /usr/share/keyrings/docker.gpg
echo "deb [signed-by=/usr/share/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" > /etc/apt/sources.list.d/docker.list
apt update
apt install docker-ce

**CentOS/RHEL — `/etc/yum.repos.d/`**

bash

yum install epel-release
# или
rpm -ivh https://example.com/some-repo.rpm

### dpkg и rpm — низкоуровневые инструменты

| Действие                       | dpkg (Debian/Ubuntu)     | rpm (CentOS/RHEL)        |
| ------------------------------ | ------------------------ | ------------------------ |
| Установить .deb/.rpm           | `dpkg -i package.deb`    | `rpm -ivh package.rpm`   |
| Удалить                        | `dpkg -r package`        | `rpm -e package`         |
| Список установленных           | `dpkg -l`                | `rpm -qa`                |
| Какому пакету принадлежит файл | `dpkg -S /usr/bin/nginx` | `rpm -qf /usr/bin/nginx` |
| Содержимое пакета (файлы)      | `dpkg -L nginx`          | `rpm -ql nginx`          |

**Если `dpkg -i` ругается на зависимости:**

bash

apt install -f    # "почини мне зависимости"

### Зависимости и конфликты

bash

# Посмотреть зависимости пакета
apt depends nginx
apt rdepends nginx      # обратные зависимости
yum deplist nginx
# Установить конкретную версию
apt install nginx=1.18.0
yum install nginx-1.18.0
# Зафиксировать версию (запретить обновление)
apt-mark hold nginx
apt-mark unhold nginx   # разфиксировать

### Чистка кэша

bash

apt clean               # удалить весь кэш
apt autoclean           # удалить только устаревшие
apt autoremove          # удалить "осиротевшие" зависимости
yum clean all

## Статья 2: SSH — подключение, ключи, конфиг, туннели

### Базовое подключение

bash

ssh user@192.168.1.100
ssh -p 2222 user@host

При первом подключении fingerprint сохраняется в `~/.ssh/known_hosts`.

### SSH-ключи

bash

# Генерация (ed25519 — современный, безопасный)
ssh-keygen -t ed25519 -C "devops@mycompany"
# Копирование ключа на сервер
ssh-copy-id user@host
# Или вручную
cat ~/.ssh/id_ed25519.pub | ssh user@host "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"

**Права на файлы критичны:** `.ssh` — 700, `authorized_keys` — 600, приватный ключ — 600.

### ~/.ssh/config — упрощение подключений

bash

Host prod-web
    HostName 10.0.1.10
    User devops
    IdentityFile ~/.ssh/id_ed25519
Host prod-db
    HostName 10.0.1.20
    User postgres
    Port 2222
Host *
    ServerAliveInterval 60          # keep-alive каждые 60 сек
    ServerAliveCountMax 3           # после 3 неудачных — отключиться
    AddKeysToAgent yes

После настройки:

bash

ssh prod-web   # вместо длинной команды

### Безопасность SSH-сервера (`/etc/ssh/sshd_config`)

text

PasswordAuthentication no       # отключить вход по паролю
PermitRootLogin no              # запретить вход под root

**Перед применением:** убедитесь, что вход по ключам работает!

Проверка конфига и перезапуск:

bash

sshd -t                         # проверить синтаксис
systemctl restart sshd          # применить

### fail2ban — защита от брутфорса

bash

apt install fail2ban
systemctl enable --now fail2ban

Блокирует IP после нескольких неудачных попыток входа.

### SSH-туннели

**-L (Local) — прокинуть удалённый порт к себе:**

bash

# PostgreSQL на сервере → локально на порт 5432
ssh -L 5432:localhost:5432 user@server
# На сервере доступна db.internal:5432 → локально
ssh -L 5432:db.internal:5432 user@server

**-R (Remote) — прокинуть свой порт на сервер:**

bash

# Локальный порт 3000 → сервер на порт 8080
ssh -R 8080:localhost:3000 user@server

**Флаги для туннелей:**

- `-N` — не открывать shell, только туннель
    
- `-f` — уйти в фон
    

### Jump-хост (ProxyJump)

bash

# Через bastion на внутренний сервер
ssh -J user@bastion.example.com user@10.0.1.15

**В ~/.ssh/config:**

text

Host bastion
    HostName bastion.example.com
    User devops
Host internal-*
    User devops
    ProxyJump bastion
    Host internal-web
    HostName 10.0.1.15

Теперь `ssh internal-web` автоматически идёт через bastion.

Туннель через jump:

bash

ssh -J bastion -L 5432:localhost:5432 internal-db

### scp и rsync — копирование файлов

**scp (простое копирование):**

bash

scp file.txt user@host:/tmp/
scp user@host:/var/log/nginx/error.log ./
scp -r ./configs/ user@host:/opt/app/

**rsync (умное копирование — только изменения, сжатие, права):**

bash

# Копирование директории
rsync -avz ./project/ user@host:/opt/project/
# С прогрессом
rsync -avzP ./project/ user@host:/opt/project/
# Синхронизация (удалить на сервере то, чего нет локально)
rsync -avz --delete ./project/ user@host:/opt/project/

Флаги rsync:

- `-a` — archive mode (рекурсивно, сохраняет права, временные метки)
    
- `-v` — verbose
    
- `-z` — сжатие
    
- `-P` — прогресс + докачка при обрыве
    
- `--delete` — удалить лишнее на приёмной стороне
    

**Разница со слэшем:**

- `./project/` → копирует содержимое в `/opt/project/`
    
- `./project` (без слэша) → создаст `/opt/project/project/`
    

rsync понимает SSH-конфиг и jump-хосты.
