## Статья 1: Docker DNS — встроенное разрешение имён

### Основная идея

Docker имеет **встроенный DNS-сервер**, который позволяет контейнерам обращаться друг к другу **по имени** (например, `db` или `redis`) вместо IP-адресов. Это работает **только в user-defined сетях** (не в дефолтной bridge).

### Default bridge vs User-defined bridge — ключевое различие

|Тип сети|DNS по именам|Когда использовать|
|---|---|---|
|**Default bridge** (docker0)|❌ НЕТ (только по IP)|Простые случаи, не нужна связь между контейнерами|
|**User-defined bridge**|✅ ДА (контейнеры видят друг друга по `--name`)|Микросервисы, связка контейнеров|

### Как это работает

1. Docker создаёт **внутренний DNS-сервер** для каждой user-defined сети
    
2. Контейнер получает `/etc/resolv.conf` с `nameserver 127.0.0.11` (адрес Docker DNS)
    
3. При запросе `ping db` → Docker DNS возвращает IP контейнера с именем `db`
    
4. Docker демон следит за состоянием контейнеров и обновляет DNS-записи
    

### Практический пример

bash

# Создаём user-defined сеть
docker network create mynet
# Запускаем БД
docker run -d --network mynet --name db postgres
# Запускаем приложение — может обращаться к "db" по имени!
docker run -it --network mynet --name app alpine sh
/app # ping db
PING db (172.18.0.2): 56 data bytes

### Дополнительные возможности

| Функция                              | Пример                                                                    |
| ------------------------------------ | ------------------------------------------------------------------------- |
| **Network aliases** (несколько имён) | `docker run --network mynet --network-alias db2 --network-alias database` |
| **Overlay network (Swarm)**          | Аналогичный DNS для контейнеров на разных хостах                          |
| **docker-compose**                   | Сервисы автоматически видят друг друга по имени сервиса                   |

### Важные замечания

- **Не монтируйте вручную `/etc/resolv.conf`** — сломаете Docker DNS
    
- DNS работает **только внутри одной сети**
    
- Имена контейнеров должны быть **уникальными в пределах сети**
    
- По умолчанию контейнеры в разных user-defined сетях **не видят друг друга**
    

### Проверка DNS внутри контейнера

bash

# Зайти в контейнер
docker exec -it app sh
# Посмотреть DNS-настройки
cat /etc/resolv.conf
# nameserver 127.0.0.11
# Проверить разрешение имени
nslookup db
# или ping db

### Итог

Для удобной связки контейнеров всегда создавайте **user-defined сети**. Docker DNS автоматически разрешает имена, избавляя от ручного прописывания IP. Это стандарт для микросервисной архитектуры.

## Статья 2: Диагностика сети — ping, nslookup, docker network inspect

### Три основных инструмента диагностики

| Инструмент               | Что проверяет                                                  | Команда                        |
| ------------------------ | -------------------------------------------------------------- | ------------------------------ |
| `ping`                   | Доступен ли контейнер по сети (маршрут + отклик)               | `docker exec app ping db`      |
| `nslookup` / `dig`       | Как Docker DNS резолвит имя в IP                               | `docker exec app nslookup db`  |
| `docker network inspect` | Полная информация о сети (IP, подключённые контейнеры, subnet) | `docker network inspect mynet` |

### Пошаговая диагностика сетевой проблемы

**Шаг 1 — Проверить сеть:**

bash

docker network ls
docker network inspect mynet

→ Убедиться, что оба контейнера подключены к одной сети и имеют IP-адреса

**Шаг 2 — Проверить DNS внутри контейнера:**

bash

docker exec -it app sh
nslookup db

→ Если `server can't find db` — DNS не знает контейнер, возможно:

- Контейнеры в разных сетях
    
- Контейнер `db` не запущен или не имеет имени
    
- Используется default bridge (там DNS не работает)
    

**Шаг 3 — Проверить связность:**

bash

docker exec app ping db

→ Если пинг идёт — сеть работает, проблема в приложении/портах

### Установка недостающих утилит в контейнере

|Образ|Установка ping|Установка nslookup/dig|
|---|---|---|
|**Alpine**|`apk add iputils`|`apk add bind-tools`|
|**Debian/Ubuntu**|`apt-get update && apt-get install -y iputils-ping`|`apt-get install -y dnsutils`|

### Дополнительные инструменты

| Инструмент   | Назначение                                             |
| ------------ | ------------------------------------------------------ |
| `curl`       | Проверить доступность HTTP-порта (`curl db:5432`)      |
| `telnet`     | Проверить открыт ли конкретный порт (`telnet db 5432`) |
| `traceroute` | Трассировка маршрута пакетов (реже нужно)              |

### Типичные проблемы и их диагностика

| Проблема                             | Признак                                | Решение                                                            |
| ------------------------------------ | -------------------------------------- | ------------------------------------------------------------------ |
| Контейнеры не видят друг друга       | `ping db` → `bad address 'db'`         | Контейнеры в разных сетях или используется default bridge          |
| DNS не резолвит                      | `nslookup db` → `server can't find db` | Проверить `docker network inspect` — контейнер `db` точно в сети?  |
| Пинг идёт, но приложение не работает | `ping db` OK                           | Проблема с портом или самим приложением — проверить `curl db:порт` |

### Пример полной диагностики

bash

# 1. Список сетей
docker network ls
# 2. Детали сети
docker network inspect mynet
# → смотрим, есть ли db и app в "Containers"
# 3. Заходим в app
docker exec -it app sh
# 4. Проверяем DNS
cat /etc/resolv.conf          # должен быть nameserver 127.0.0.11
nslookup db                   # должен вернуть IP
# 5. Проверяем связность
ping db                       # должен отвечать
# 6. Проверяем порт (если приложение)
curl db:5432                  # или telnet db 5432

### Итог

- `docker network inspect` → видим **структуру сети** (IP, подключённые контейнеры)
    
- `nslookup` / `ping` изнутри контейнера → проверяем **DNS и связность**
    
- Сочетание этих инструментов позволяет быстро локализовать проблему: сеть, DNS, порт или само приложение
