### Саммари: Удалённые ветки (Remote Branches)

**Трёхуровневая система веток:**

1. **Локальные ветки** — рабочие ветки, где происходит разработка
    
2. **Remote-tracking ветки** — локальные копии состояния веток на сервере (`origin/main`). Обновляются автоматически при `fetch`/`pull`/`push`, но их нельзя изменить напрямую
    
3. **Удалённые ветки** — физически находятся на сервере
    

**Публикация новой ветки:**

bash

git push -u origin feature/new-branch

- `-u` (или `--set-upstream`) создаёт ветку на сервере и устанавливает **upstream связь**
    
- После этого работают короткие команды `git push`/`git pull`
    
- `git branch -vv` показывает все upstream связи
    

**Получение чужих веток:**

bash

git fetch origin                    # загружает информацию о всех ветках
git branch -r                       # просмотр remote-tracking веток
git checkout feature/colleague      # автоматически создаёт локальную ветку, отслеживающую origin/feature/colleague

**Удаление веток:**

- Локальная: `git branch -d feature/done` (только если слита) или `-D` (принудительно)
    
- Удалённая: `git push origin --delete feature/old`
    
- Remote-tracking («мёртвые»): `git remote prune origin` (или `git fetch --prune origin`)
    

**Работа с несколькими remote (форки):**

bash

git fetch upstream                   # получить изменения из оригинального репо
git checkout main
git merge upstream/main              # слить изменения
git push origin main                 # отправить в свой форк

**Пространства имён:** каждый remote имеет своё пространство — `origin/main`, `upstream/main`, `backup/main` — что позволяет отслеживать одну логическую ветку в разных репозиториях.

**Защита веток (настройки хостинга):**

- Запрет удаления и force push для критических веток
    
- Требование pull request перед слиянием
    
- Автоматические CI/CD проверки
    

**Ключевые принципы:** явно публикуйте новые ветки, устанавливайте upstream связи, регулярно очищайте мёртвые remote-tracking ветки, используйте осмысленные имена с префиксами (`feature/`, `bugfix/`, `hotfix/`).
