### Саммари 1: Игнорирование файлов (.gitignore)

**Зачем игнорировать:**  
В репозиторий не должны попадать временные файлы, результаты сборки, зависимости (node_modules), локальные настройки и секретные данные (пароли, ключи API). Это предотвращает раздувание репозитория, конфликты при слиянии и утечки конфиденциальной информации.

**Файл .gitignore:**  
Размещается в корне репозитория (или в поддиректориях) и содержит glob-шаблоны для исключения файлов.

- `*.log` — игнорировать все .log файлы.
    
- `build/` — игнорировать всю директорию.
    
- `/TODO` — игнорировать только в корне.
    
- `**/temp` — игнорировать директорию temp на любом уровне вложенности.
    
- `!important.log` — отмена игнорирования (исключение из правила).
    

**Важное ограничение:**  
`.gitignore` действует **только на неотслеживаемые файлы**. Если файл уже добавлен в репозиторий, его нужно сначала удалить из индекса:

bash

git rm --cached filename.log

**Множественные и глобальные правила:**

- Можно создавать отдельные `.gitignore` в поддиректориях — они имеют приоритет над общими.
    
- Глобальный `.gitignore` (`git config --global core.excludesfile ~/.gitignore_global`) применяется ко всем проектам пользователя (например, для `.DS_Store`).
    

**Сохранение пустых директорий (.gitkeep):**  
Git не отслеживает пустые папки. Соглашение — создавать внутри пустой файл `.gitkeep` (или любое другое имя), чтобы структура директорий сохранялась в репозитории.

**Лучшие практики:**

- Добавлять `.gitignore` в начале проекта.
    
- Использовать готовые шаблоны ([gitignore.io](https://gitignore.io/)).
    
- Регулярно проверять игнорируемые файлы через `git status --ignored`.

### Саммари 2: Ветвление (Branching)

**Концепция:**  
Ветка в Git — это не копия файлов, а **подвижный указатель на коммит** (файл размером 41 байт). Это делает операции с ветками (создание, переключение, удаление) мгновенными независимо от размера проекта.

**Создание и переключение:**

- Создать ветку (оставаясь на текущей): `git branch feature-login`
    
- Создать и переключиться (современный способ): `git switch -c feature-login`
    
- Классический способ: `git checkout -b feature-login`
    
- Переключиться на существующую ветку: `git switch main` (или `git checkout main`)
    
- Вернуться на предыдущую ветку: `git switch -`
    

**Безопасность:**  
Git не позволяет переключить ветку, если есть незафиксированные изменения, конфликтующие с целевой веткой. Это предотвращает потерю работы.

**Просмотр информации:**

- `git branch` — список локальных веток (* — текущая).
    
- `git branch -v` — с последним коммитом каждой ветки.
    
- `git branch --merged` / `--no-merged` — показывает слитые/неслитые ветки относительно текущей.
    
- `git branch -a` — все ветки (включая удалённые).
    

**Удаление веток:**

- Безопасное удаление (только если слита): `git branch -d feature-login`
    
- Принудительное удаление (без проверки): `git branch -D feature-login`
    

**Практические принципы:**

- Ветки именуются с префиксами: `feature/`, `bugfix/`, `hotfix/`, `release/`.
    
- Долгоживущие ветки следует регулярно синхронизировать с основной веткой (merge/rebase), чтобы избежать накопления конфликтов.
    
- После слияния отработавшие ветки удаляются для поддержания чистоты репозитория.
    
- Визуализация структуры: `git log --graph --oneline --all`
