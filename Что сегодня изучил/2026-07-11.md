# Саммари: Установка Ansible и первое подключение

## Что нам нужно

|Компонент|Описание|
|---|---|
|**Control node**|Машина, с которой запускается Ansible. Linux или macOS (на Windows — через WSL)|
|**Managed node**|Сервер, которым управляем. Должен быть доступен по SSH|

---

## Установка Ansible

### Способ 1: через пакетный менеджер (apt) — Ubuntu/Debian

bash

sudo apt update
sudo apt install ansible -y
ansible --version

**Нюанс:** в репозиториях Ubuntu часто лежит не самая свежая версия.

### Способ 2: через pip (рекомендуемый)

bash

sudo apt install python3 python3-pip -y
pip3 install ansible

Если pip ругается на `externally-managed-environment`:

bash

pip3 install ansible --break-system-packages

Или через виртуальное окружение (более правильно):

bash

python3 -m venv ~/ansible-venv
source ~/ansible-venv/bin/activate
pip install ansible

**Проверка:**

bash

ansible --version

## Настройка SSH-ключей

Ansible подключается к серверам по SSH, поэтому ключи обязательны.

**Генерация ключа (если нет):**

bash

ssh-keygen -t ed25519

**Копирование ключа на сервер:**

bash

ssh-copy-id user@IP_ВАШЕГО_СЕРВЕРА

**Проверка подключения без пароля:**

bash

ssh user@IP_ВАШЕГО_СЕРВЕРА

**Если не работает:** проверьте права на сервере — `.ssh` должен быть `700`, `authorized_keys` — `600`.

## Первый inventory

Файл со списком серверов. Создаём рабочую директорию:

bash

mkdir ~/ansible-practice
cd ~/ansible-practice

**`inventory.ini`:**

ini

[servers]
server1 ansible_host=IP_ВАШЕГО_СЕРВЕРА ansible_user=root

- `[servers]` — группа хостов
    
- `server1` — имя хоста в Ansible
    
- `ansible_host` — IP или домен
    
- `ansible_user` — пользователь для подключения
    

---

## Первый запуск — `ansible ping`

bash

ansible all -i inventory.ini -m ping

**Разбор:**

- `ansible` — запуск ad-hoc команды
    
- `all` — все хосты из inventory (можно `servers` или конкретный хост)
    
- `-i inventory.ini` — путь к inventory
    
- `-m ping` — модуль ping (проверяет, что Ansible может подключиться и выполнить Python-код)
    

**Успешный ответ:**

text

server1 | SUCCESS => {
    "changed": false,
    "ping": "pong"
}

### Частые ошибки и решения

|Ошибка|Причина|Решение|
|---|---|---|
|`Permission denied`|SSH-ключ не закинут или неправильный пользователь|`ssh-copy-id user@IP`|
|`Host key verification failed`|Ни разу не подключались к серверу|Подключиться вручную: `ssh user@IP` и подтвердить отпечаток|
|`No module named ansible`|Ansible не установлен или не в PATH|Проверить установку|

## Конфиг `ansible.cfg` — что настроить сразу

Создаём в рабочей директории:

ini

[defaults]
inventory = inventory.ini
host_key_checking = False
remote_user = root
[privilege_escalation]
become = True
become_method = sudo

**Разбор:**

|Параметр|Значение|
|---|---|
|`inventory`|Путь к inventory по умолчанию (теперь не нужно писать `-i` каждый раз)|
|`host_key_checking = False`|Отключает проверку SSH-отпечатков (удобно для обучения и динамической инфраструктуры)|
|`remote_user = root`|Пользователь по умолчанию для подключения|
|`become = True`|Повышать привилегии (через sudo)|
|`become_method = sudo`|Метод повышения привилегий|

**Где Ansible ищет конфиг (порядок):**

1. Переменная окружения `ANSIBLE_CONFIG`
    
2. `ansible.cfg` в текущей директории
    
3. `~/.ansible.cfg`
    
4. `/etc/ansible/ansible.cfg`
    

**Проверка, что конфиг подхватился:**

bash

ansible --version
# config file = /home/ваш_юзер/ansible-practice/ansible.cfg

## Теперь команды короче

Без `-i`, без указания пользователя:

bash

ansible all -m ping

---

## Пара ad-hoc команд для проверки

bash

ansible all -m command -a "uptime"
ansible all -m command -a "df -h"
ansible all -m command -a "free -m"

**Разбор:**

- `-m command` — модуль, выполняющий произвольную команду на сервере
    
- `-a "команда"` — аргументы для модуля (сама команда)
