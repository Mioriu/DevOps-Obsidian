# Вопросы для собеседования Middle DevOps

## Linux (10)

1. **В чём разница между hard link и symlink?**
Hard link — второй указатель на тот же inode, живёт даже если удалить оригинальный файл, не работает между файловыми системами. Symlink — отдельный файл-ссылка с путём на другой файл, ломается при удалении/переносе оригинала, работает между ФС.
ОК
2. **Что делает `chmod 755 file`?**
Устанавливает права: владелец — rwx (7), группа — r-x (5), остальные — r-x (5).
ОК
3. **Как посмотреть, какие процессы больше всего грузят CPU/память?**
`top` или `htop` (интерактивно), `ps aux --sort=-%cpu` / `--sort=-%mem`.
ОК
4. **Что такое load average?**
Среднее число процессов в состоянии выполнения/ожидания CPU за 1, 5, 15 минут. Нужно сравнивать с числом ядер CPU.
ОК
5. **Разница между SIGTERM и SIGKILL?**
SIGTERM (15) — просит процесс завершиться корректно, можно перехватить. SIGKILL (9) — принудительное завершение ядром, перехватить нельзя.
ОК
6. **Как посмотреть открытые порты и что их слушает?**
`ss -tulnp` (современный аналог `netstat -tulnp`).
ОК
7. **Что такое inode?**
Структура файловой системы, хранящая метаданные файла (права, владелец, размер, ссылки на блоки данных), но не само имя файла.
ОК
8. **В чём разница между `/` и `/home`?**
`/` — корень файловой системы со всей системой (бинарники, конфиги, ядро). `/home` — домашние директории пользователей.
ОК
9. **Как посмотреть логи systemd-сервиса?**
`journalctl -u <service_name>` (можно с `-f` для слежения в реальном времени).
ОК
10. **Что такое swap и когда он используется?**
Область на диске, используемая как «расширение» RAM, когда физической памяти не хватает. Используется ОС для выгрузки редко используемых страниц памяти.
ОК

## Kubernetes (10)

1. **Что такое Pod?**
Минимальная разворачиваемая единица в Kubernetes — один или несколько контейнеров, разделяющих сеть и хранилище.
ОК
2. **Разница между Deployment и StatefulSet?**
Deployment — для stateless-приложений, поды взаимозаменяемы, имена случайные. StatefulSet — для stateful-приложений (БД), поды имеют стабильные имена/сетевые идентификаторы и порядок создания/удаления.
ОК
3. **Что такое Service и какие типы бывают?**
Абстракция для стабильного доступа к подам. Типы: ClusterIP (внутри кластера), NodePort (порт на каждой ноде), LoadBalancer (внешний балансировщик облака), ExternalName.
ОК
4. **Что такое Ingress?**
Объект, управляющий HTTP/HTTPS-доступом извне к сервисам внутри кластера (роутинг по домену/пути), требует Ingress-контроллер.
ОК
5. **ConfigMap vs Secret — в чём разница?**
Оба хранят конфигурацию отдельно от образа. ConfigMap — для не секретных данных (обычный текст). Secret — для чувствительных данных, хранится в base64 (не шифрование само по себе, нужны доп. меры для реальной защиты).
ОК
6. **Что такое readiness и liveness probe?**
Liveness — проверяет, жив ли контейнер; при провале Kubernetes перезапускает под. Readiness — проверяет, готов ли под принимать трафик; при провале под убирается из Service, но не перезапускается.
ОК
7. **Что такое namespace?**
Логическое разделение ресурсов внутри одного кластера (изоляция, ограничение ресурсов, разделение по командам/окружениям).
ОК
8. **Как происходит rolling update?**
Deployment постепенно заменяет старые поды новыми: создаёт новые, ждёт readiness, потом убирает старые, контролируется параметрами maxSurge/maxUnavailable.
ОК
9. **Что такое HPA?**
Horizontal Pod Autoscaler — автоматически масштабирует число подов на основе метрик (CPU, память, кастомные метрики).
ОК
10. **Что такое PersistentVolume и PersistentVolumeClaim?**
PV — ресурс хранилища в кластере (физический или облачный диск). PVC — запрос пода на выделение хранилища из доступных PV.
ОК

## CI/CD (10)

1. **Что такое CI/CD?**
CI (Continuous Integration) — частая автоматическая сборка и тестирование кода при каждом изменении. CD — автоматическая доставка (Delivery) или развёртывание (Deployment) готового артефакта.
ОК
2. **Разница между Continuous Delivery и Continuous Deployment?**
Delivery — код всегда готов к релизу, но выкладка в прод требует ручного подтверждения. Deployment — выкладка в прод происходит автоматически без ручного шага.
ОК
3. **Что такое pipeline as code?**
Описание CI/CD-пайплайна в виде файла в репозитории (например, `.gitlab-ci.yml`, `Jenkinsfile`), а не через настройку в UI — версионируется вместе с кодом.
ОК
4. **Что такое artifact repository?**
Хранилище собранных артефактов (jar, docker-образы, npm-пакеты), например Nexus, Artifactory, Docker Registry.
ОК
5. **Что такое blue-green deployment?**
Развёртывание новой версии рядом со старой (два одинаковых окружения), после проверки трафик переключается на новую версию целиком, старая остаётся как резерв для отката.
ОК
6. **Что такое canary deployment?**
Постепенный вывод новой версии на небольшую часть трафика/пользователей с последующим увеличением доли, если всё стабильно.
ОК
7. **Что такое rollback и как его реализовать?**
Откат к предыдущей рабочей версии при проблемах. Реализуется через хранение предыдущих артефактов/образов и возможность быстро их передеплоить (например, `kubectl rollout undo`).
ОК
8. **Зачем нужны стадии (stages) в pipeline?**
Для логического разделения процесса (build, test, deploy) и контроля порядка выполнения — каждая следующая стадия запускается только при успехе предыдущей.
ОК
9. **Что такое feature flag?**
Механизм включения/выключения функциональности без передеплоя, позволяет разделить деплой кода и релиз фичи.
ОК
10. **Разница между build и release?**
Build — компиляция/сборка кода в артефакт. Release — версия, готовая к развёртыванию в конкретное окружение (может включать конфигурацию под это окружение).
ОК

## Docker (5)

1. **Разница между образом (image) и контейнером?**
Образ — неизменяемый шаблон (файловая система + метаданные). Контейнер — запущенный экземпляр образа с изменяемым слоем поверх.
ОК
2. **Что такое Dockerfile и основные инструкции?**
Текстовый файл с инструкциями для сборки образа. Основные: `FROM` (базовый образ), `RUN` (выполнить команду при сборке), `COPY`/`ADD` (скопировать файлы), `CMD`/`ENTRYPOINT` (команда запуска), `EXPOSE` (порт).
ОК
3. **Что такое multi-stage build?**
Сборка образа в несколько этапов (`FROM ... AS builder`), где финальный образ берёт только нужные артефакты из промежуточных этапов — уменьшает размер итогового образа.
ОК
4. **Разница между CMD и ENTRYPOINT?**
CMD задаёт команду по умолчанию, которую легко переопределить при запуске контейнера. ENTRYPOINT задаёт основную команду, которую сложнее переопределить; часто используются вместе (ENTRYPOINT + CMD как аргументы по умолчанию).
ОК
5. **Что такое volume в Docker и зачем нужен?**
Механизм хранения данных вне изменяемого слоя контейнера — данные сохраняются после удаления контейнера, могут разделяться между контейнерами.
ОК

## Сети (5)

1. **В чём разница между TCP и UDP?**
TCP — с установлением соединения, гарантирует доставку и порядок пакетов (надёжный, медленнее). UDP — без установления соединения, доставка не гарантирована (быстрее, для видео/игр/DNS-запросов).
ОК
2. **Что такое DNS и как работает резолвинг?**
Система преобразования доменных имён в IP-адреса. Клиент спрашивает у резолвера, тот идёт к корневым → TLD → авторитативным серверам, пока не найдёт нужную запись (или отдаёт из кэша).
ОК
3. **Что такое NAT?**
Network Address Translation — механизм преобразования приватных IP-адресов во внешний публичный IP (и обратно), позволяет нескольким устройствам локальной сети выходить в интернет через один внешний адрес.
ОК
4. **Разница между HTTP и HTTPS?**
HTTPS — это HTTP поверх TLS/SSL, обеспечивает шифрование трафика, проверку подлинности сервера и целостность данных. HTTP передаёт данные в открытом виде.
ОК
5. **Что такое VPN?**
Технология создания защищённого зашифрованного туннеля между устройством и удалённой сетью через публичный интернет, обеспечивает конфиденциальность и доступ к внутренним ресурсам как будто из локальной сети.
ОК

## Ansible (5)

1. **Что такое playbook?**
YAML-файл, описывающий набор задач (tasks), которые нужно выполнить на целевых хостах.
ОК
2. **Что такое идемпотентность в Ansible?**
Свойство модулей приводить систему в заданное состояние независимо от того, сколько раз выполняется playbook — повторный запуск не меняет результат, если состояние уже достигнуто.
ОК
3. **Разница между ролью (role) и playbook?**
Playbook — конкретный сценарий выполнения на хостах. Роль — переиспользуемая структурированная единица (tasks, handlers, vars, templates), которую можно подключать в разные playbook'и.
ОК
4. **Что такое inventory?**
Файл/источник, описывающий список хостов и их группировку, на которых Ansible будет выполнять задачи.
ОК
5. **Что такое handler?**
Задача, которая выполняется только по триггеру (`notify`) от другой задачи, и только один раз в конце плейбука, даже если её вызывали несколько раз (например, перезапуск сервиса после изменения конфига).
ОК

## Terraform (5)

1. **Что такое state file и зачем он нужен?**
Файл (`terraform.tfstate`), в котором Terraform хранит текущее состояние управляемой инфраструктуры — сопоставление ресурсов из кода с реальными объектами в облаке.
ОК
2. **Разница между `terraform plan` и `terraform apply`?**
`plan` показывает, какие изменения будут внесены (без применения). `apply` реально применяет эти изменения к инфраструктуре.
ОК
3. **Что такое provider?**
Плагин, через который Terraform взаимодействует с конкретным API (AWS, Azure, GCP, Kubernetes и т.д.), переводя код в вызовы этого API.
ОК
4. **Что такое module в Terraform?**
Переиспользуемый набор ресурсов, оформленный как отдельный блок конфигурации, который можно подключать с разными входными параметрами в разных проектах.
ОК
5. **Зачем нужен remote backend (например, S3)?**
Для хранения state-файла централизованно и совместной работы команды: обеспечивает блокировку state (locking) от одновременных изменений и не хранит state локально/в git.
ОК
