Так, тема достаточно продвинутая, но разобрать её нужно, потому что рано могут спросить на собесе

## Когда нужен свой модуль

**Интеграция с внутренним API.** У вас в компании есть, допустим, своя система управления конфигурацией, CMDB, или внутренний сервис, у которого есть API. Вам нужно из Ansible дёргать это API, создавать записи, обновлять статусы. Готового модуля нет и быть не может — это ваша внутренняя система.

**Сложная логика с идемпотентностью.** Вы раз за разом пишете одну и ту же связку `shell` + `register` + `when`, чтобы проверить состояние и применить изменения. Модуль спрячет всю эту логику внутрь и даст чистый, идемпотентный интерфейс.

**Повторяющийся шаблон на shell.** Если вы копипастите один и тот же блок из `shell` + `changed_when` + `failed_when` в пять плейбуков — это сигнал, что пора завернуть это в модуль.

## Минимальный модуль на Python

Модули Ansible пишутся на Python. Вот самый простой рабочий модуль:

pythoncopy

```python
#!/usr/bin/python# library/hello.py from ansible.module_utils.basic import AnsibleModule  def main():    module = AnsibleModule(        argument_spec=dict(            name=dict(type='str', required=True),        ),    )     name = module.params['name']    module.exit_json(changed=False, msg=f"Привет, {name}!")  if __name__ == '__main__':    main()
```

Вот и всё. Это полноценный модуль. Давайте разберём по кусочкам.

### AnsibleModule — сердце модуля

`AnsibleModule` — это класс, который делает всю рутину: парсит аргументы, валидирует типы, обрабатывает ошибки, форматирует вывод. Вы просто описываете, какие параметры принимает модуль, и работаете с ними.

pythoncopy

```python
module = AnsibleModule(    argument_spec=dict(        name=dict(type='str', required=True),        state=dict(type='str', default='present', choices=['present', 'absent']),        count=dict(type='int', default=1),        force=dict(type='bool', default=False),    ),    supports_check_mode=True,)
```

`argument_spec` — словарь параметров. Для каждого параметра можно указать тип (`str`, `int`, `bool`, `list`, `dict`), обязательность (`required`), значение по умолчанию (`default`), допустимые значения (`choices`).

`supports_check_mode=True` — модуль поддерживает `--check`. Если это указано, то при запуске с `--check` модуль получит `module.check_mode == True`, и вы можете пропустить реальные действия.

### Обработка результатов

У модуля два способа завершиться:

**Успех:**

pythoncopy

```python
module.exit_json(    changed=True,        # менялось ли что-то    msg="Всё готово",    # сообщение    result=some_data,    # любые дополнительные данные)
```

**Ошибка:**

pythoncopy

```python
module.fail_json(    msg="Что-то пошло не так: файл не найден",)
```

`changed=True` или `changed=False` — вот это ключевой момент. Именно через это поле модуль сообщает Ansible, изменилось ли что-то на сервере. От этого зависит, сработают ли хэндлеры, и что покажет PLAY RECAP. Если ваш модуль всегда возвращает `changed=True` — вы теряете идемпотентность.

## Реалистичный пример

Допустим, нам нужен модуль, который управляет записями в каком-то внутреннем сервисе через файл:

pythoncopy

```python
#!/usr/bin/python# library/app_config.py from ansible.module_utils.basic import AnsibleModuleimport jsonimport os  def main():    module = AnsibleModule(        argument_spec=dict(            key=dict(type='str', required=True),            value=dict(type='str', required=True),            config_path=dict(type='str', default='/etc/myapp/config.json'),            state=dict(type='str', default='present', choices=['present', 'absent']),        ),        supports_check_mode=True,    )     key = module.params['key']    value = module.params['value']    config_path = module.params['config_path']    state = module.params['state']     # Прочитать текущий конфиг    config = {}    if os.path.exists(config_path):        try:            with open(config_path, 'r') as f:                config = json.load(f)        except (json.JSONDecodeError, IOError) as e:            module.fail_json(msg=f"Не удалось прочитать конфиг: {e}")     changed = False     if state == 'present':        if config.get(key) != value:            config[key] = value            changed = True    elif state == 'absent':        if key in config:            del config[key]            changed = True     # В check-режиме ничего не пишем    if changed and not module.check_mode:        try:            os.makedirs(os.path.dirname(config_path), exist_ok=True)            with open(config_path, 'w') as f:                json.dump(config, f, indent=2)        except IOError as e:            module.fail_json(msg=f"Не удалось записать конфиг: {e}")     module.exit_json(        changed=changed,        key=key,        value=value if state == 'present' else None,        config=config,    )  if __name__ == '__main__':    main()
```

Обратите внимание на паттерн:

1. Прочитали текущее состояние.
2. Сравнили с желаемым.
3. Если отличается — поменяли, `changed=True`.
4. Если совпадает — ничего не делаем, `changed=False`.
5. В чек-моде — только определяем, нужно ли менять, но не меняем.

Вот это и есть идемпотентный модуль. Запускай хоть сто раз — `changed` будет только когда реально что-то поменялось.

## Размещение в library/

Самый простой способ подключить модуль — положить его в папку `library/` рядом с плейбуком:

![Ansible library/ — кастомные модули рядом с playbook](https://offers.prostodevops.ru/diagrams/ansible/ansible-library-flat.png)Ansible library/ — кастомные модули рядом с playbook

Ansible автоматически подхватит все модули из `library/`. Никаких дополнительных настроек. Используете в плейбуке как обычный модуль:

yamlcopy

```yaml
---- name: Пример с кастомным модулем  hosts: all   tasks:    - name: Поприветствовать      hello:        name: "Ansible"      register: result     - name: Показать результат      debug:        var: result.msg     - name: Настроить параметр приложения      app_config:        key: database_url        value: "postgresql://db.local:5432/myapp"        state: present      become: true
```

Имя модуля = имя файла без `.py`. Файл `library/hello.py` → модуль `hello`.

Если модуль нужен в роли — кладите в `library/` внутри роли:

![Ansible library внутри роли — модули доступны только этой роли](https://offers.prostodevops.ru/diagrams/ansible/ansible-role-library.png)Ansible library внутри роли — модули доступны только этой роли

Или укажите путь глобально в `ansible.cfg`:

inicopy

```ini
[defaults]library = ./library:/opt/shared-modules
```

## Отладка модуля

Если модуль не работает, первым делом — добавьте verbose:

ansible-playbook playbook.yml -vvv

Ansible покажет, какой именно JSON модуль вернул. Если модуль падает с ошибкой Python — в `-vvv` будет полный трейсбек.

Можно тестировать модуль и отдельно от Ansible, просто передав ему JSON с аргументами:

echo '{"ANSIBLE_MODULE_ARGS": {"name": "test"}}' | python library/hello.py

Выдаст JSON-ответ модуля. Удобно для быстрой проверки без запуска всего плейбука.
