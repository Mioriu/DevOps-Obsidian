**AWX** — это open-source веб-интерфейс для управления Ansible.

### Простыми словами:

Ansible — это CLI инструмент. Запускаешь `ansible-playbook` из терминала.

AWX — это графический интерфейс + API + планировщик + контроль доступа для Ansible.

## Зачем это нужно?

**Без AWX (просто Ansible):**

- Запускаешь playbook руками из терминала
- Нет истории запусков
- Нет контроля кто что запустил
- Credentials хранятся в файлах
- Нельзя дать доступ другим без SSH

**С AWX:**

- Веб-интерфейс — запускаешь playbook кнопкой
- История всех запусков с логами
- RBAC (Role-Based Access Control) — контроль кто что может запускать
- Централизованное хранение credentials (vault, пароли, SSH ключи)
- Расписание запусков (cron для playbooks)
- REST API для интеграции с другими системами
- Workflows — цепочки playbooks

## AWX vs Ansible Tower

**Ansible Tower** — коммерческий продукт от Red Hat (платный, с поддержкой)

**AWX** — open-source версия Tower (бесплатный, community-поддержка)

Tower основан на AWX, но:

- Tower стабильнее (проверенные релизы)
- Tower с поддержкой от Red Hat
- AWX обновляется чаще (новые фичи быстрее)

Аналогия: Fedora (AWX) vs RHEL (Tower)

## Основные возможности:

1. **Inventory management** — хранение списка серверов
2. **Credentials management** — безопасное хранение паролей/ключей
3. **Job Templates** — шаблоны запуска playbooks с параметрами
4. **Scheduling** — запуск по расписанию
5. **Workflows** — последовательность playbooks (если успешно → следующий)
6. **RBAC** — права доступа для пользователей и команд
7. **REST API** — автоматизация через API
8. **Notifications** — уведомления в Slack/Email при успехе/провале
9. **Audit trail** — кто что когда запускал

- Из защищенного окружения
- С логированием
- С контролем доступа
- По расписанию или по API

## Когда использовать AWX?

**Используй AWX если:**

- Много людей запускают playbooks (нужен контроль доступа)
- Нужна история запусков и логи
- Нужно запускать по расписанию
- Нужно дать доступ не-DevOps людям (через веб)
- Интеграция с CI/CD через API

**Не нужен AWX если:**

- Только ты один запускаешь playbooks
- Простые задачи
- Не хочешь поднимать еще один сервис

## Установка

AWX ставится как:

- **Docker Compose** (для теста)
- **Kubernetes** (для прода через AWX Operator)

Требования: довольно тяжелый (PostgreSQL, Redis, несколько контейнеров)

## На собеседовании:

**"Что такое AWX?"**

AWX — это open-source веб-интерфейс для Ansible с RBAC, планировщиком, хранением credentials и REST API. Позволяет централизованно управлять запуском playbooks, контролировать доступ и вести аудит.

**"Чем отличается от Ansible Tower?"**

AWX — open-source upstream для Ansible Tower. Tower — коммерческий продукт с поддержкой Red Hat, более стабильный. AWX обновляется чаще и бесплатный.
