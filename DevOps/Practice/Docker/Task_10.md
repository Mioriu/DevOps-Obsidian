# app1

## Проблема

- Крашится по причине попытки монтирования несуществующего файла и при этом создает директорию ./config/app1.conf

## Решение

- Удалим директорию `rm -rf ./config/app1.conf`

- Либо переименовываем конфиг `mv ./config/app1.conf.example ./config/app1.conf` либо меняем его название в файле docker-compose.yml

# app3

## Проблема

- app3  | sh: can't create /data/test.txt: Read-only file system

- Контейнер пытается писать в read only смонтированную директорию

## Решение

- Убираем параметр ro при монтировании тома

- Проверим работу, т.к. в docker ps его нет по причине того что это просто одна команда, а не фоновый процесс

```
docker compose logs app3
app3 | test
```

# app4

## Проблема

- Контейнер видит 0й код возврата и при любой ошибке думает что процесс завершился корректно

## Решение

- Убираем `|| exit 0`

- Можем указать `set -e`, но это нужно было бы в случае, если было бы несколько команд и мы бы хотели остановиться на первой же ошибке

# app5

## Проблема

- Контейнер бесконечно рестартует из-за политики restart: always, т.к. сам контейнер просто возвращает exit 1

## Решение

- Либо полностью стираем restart из compose файла либо ставим restart: no

# app6

## Проблема

- Для запуска контейнера postgres есть минимальный необходимый набор переменных окружения(базовый минимум), а именно переменная POSTGRES_PASSWROD, которая не задана в compose файле.

## Решение

- Добавляем в compose файл переменную

```
environment:
-POSTGTRES_PASSWORD=test
```
