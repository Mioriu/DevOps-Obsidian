Сетевая подсистема Docker (Docker Networking) — это механизм, который управляет связью контейнеров между собой, с хост-машиной и с внешним миром.

По умолчанию контейнер запускается в изолированном сетевом пространстве (Network Namespace). Без настройки сети он не может видеть другие контейнеры и не доступен извне.

## 1. Концепция: CNM (Container Network Model)

Docker использует подключаемую архитектуру. Основная идея:

- У каждого контейнера есть свой **виртуальный IP-адрес**.
- Контейнеры могут подключаться к одной или нескольким **сетям**.
- Драйвер сети определяет правила маршрутизации и изоляции.

## 2. Основные сетевые драйверы

При установке Docker автоматически создает три стандартные сети. Посмотреть их можно командой `docker network ls`.

### A. Bridge (Мост) — Режим по умолчанию

Это самый распространенный тип сети. Если вы не указываете сеть при старте, контейнер попадает сюда.

- **Как это работает:** Docker создает на хосте виртуальный мост (виртуальный коммутатор) под названием `docker0`. Все контейнеры в этой сети получают внутренние IP-адреса из частной подсети (например, `172.17.0.2`, `172.17.0.3`).
- **Изоляция:** Контейнеры могут общаться друг с другом по IP.
- **Связь с миром:** Docker использует **NAT** (Network Address Translation) и правила IP-tables на хосте, чтобы выпустить трафик контейнера в интернет.

**Важный нюанс (DNS):** В стандартной сети `bridge` (дефолтной) контейнеры **не видят** друг друга по именам, только по IP. Чтобы работало обращение по имени (например, `ping database`), нужно создать _свою_ сеть (User-defined bridge).

### B. Host (Хост) — Максимальная производительность

В этом режиме изоляция сети отключается полностью.

- **Как это работает:** Контейнер использует сетевой стек хоста напрямую. Он не получает свой IP-адрес.
- **Порты:** Если приложение внутри контейнера слушает порт 80, оно займет порт 80 на **реальном** сетевом интерфейсе вашего сервера.
- **Плюс:** Нет оверхеда на NAT и маршрутизацию. Скорость равна скорости железа.
- **Минус:** Нельзя запустить два контейнера, слушающих один и тот же порт (возникнет конфликт портов).

### C. None (Отсутствует)

Режим полной изоляции.

- **Как это работает:** У контейнера есть только локальный интерфейс `lo` (localhost). Никаких внешних подключений.
- **Зачем нужно:** Для задач с высокой безопасностью, где приложению не нужен интернет (например, генерация ключей шифрования или пакетная обработка файлов).

## 3. Публикация портов (Port Mapping)

Поскольку контейнеры в режиме `bridge` имеют свои внутренние IP (недоступные извне), чтобы попасть в веб-сервер внутри контейнера, нужно пробросить порт.

Синтаксис: `-p HOST_PORT:CONTAINER_PORT`

docker run -d -p 8080:80 nginx

1. Docker слушает порт **8080** на хост-машине (все интерфейсы 0.0.0.0).
2. Весь трафик, пришедший на 8080, перенаправляется через NAT внутрь контейнера на порт **80**.

Если не сделать проброс, приложение будет доступно только другим контейнерам в той же сети, но не пользователям из интернета.

## 4. DNS и Service Discovery (Магия имен)

В современной архитектуре IP-адреса контейнеров **эфемерны**. При перезапуске контейнер может получить новый IP. Поэтому прописывать IP в конфигах (`DB_HOST=172.17.0.5`) нельзя.

Docker имеет встроенный **DNS-сервер** (работает по адресу `127.0.0.11` внутри каждого контейнера).

**Как это работает:**

1. Вы создаете свою сеть:

docker network create my-app-net

1. Запускаете в ней базу данных с именем `db-prod`:

docker run -d --name db-prod --network my-app-net postgres

1. Запускаете бэкенд в той же сети. Теперь бэкенд может обратиться к базе просто по имени хоста `db-prod`. Docker DNS автоматически подставит актуальный IP-адрес.

## 5. Основные команды для работы с сетями

### Создание сети

docker network create --driver bridge my-net

_Рекомендуется всегда создавать отдельные сети для разных проектов (изоляция проектов друг от друга)._

### Подключение контейнера

Можно подключить контейнер к сети при старте:

docker run --network my-net ...

Или подключить уже работающий контейнер к новой сети (на лету):

docker network connect my-net my-container

### Просмотр деталей

Чтобы узнать, какой IP получил контейнер и в каких сетях он состоит:

docker network inspect my-net

Эта команда вернет JSON со списком всех подключенных контейнеров и их адресами.

## Сводная таблица режимов

| Драйвер                 | Изоляция | Скорость      | DNS по имени | Сценарий                         |
| ----------------------- | -------- | ------------- | ------------ | -------------------------------- |
| **Bridge (default)**    | Есть     | Обычная (NAT) | **Нет**      | Быстрые тесты                    |
| **User-defined Bridge** | Есть     | Обычная (NAT) | **Да**       | Стандарт для приложений          |
| **Host**                | Нет      | Нативная      | N/A          | High-load, специфичные протоколы |
| **None**                | Полная   | N/A           | Нет          | Безопасные задачи                |
