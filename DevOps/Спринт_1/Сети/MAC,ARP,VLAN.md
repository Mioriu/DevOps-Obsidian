# MAC, ARP, VLAN

## Зачем это знать?

MAC, ARP и VLAN — это канальный уровень (L2). Тут происходит реальная передача данных между устройствами в локальной сети. Если L2 не работает, ничего выше работать не будет. (MAC на границе L2/L3)

## 1. MAC-адреса

### Что это

MAC (Media Access Control) — уникальный идентификатор сетевого интерфейса. Записан в железо (хотя можно изменить программно).

Формат: 6 байт, обычно пишут в hex через двоеточие или дефис:

codecopy

```
00:1A:2B:3C:4D:5E00-1A-2B-3C-4D-5E001A.2B3C.4D5E     (Cisco-стиль)
```

Первые 3 байта — OUI (Organizationally Unique Identifier), идентификатор производителя. Последние 3 байта — уникальный номер устройства.

![Анатомия MAC-адреса: OUI · Serial](https://offers.prostodevops.ru/diagrams/network/mac-anatomy.png)Анатомия MAC-адреса: OUI · Serial

## 2. ARP: связь IP и MAC

### Зачем нужен

IP-адрес — логический, для маршрутизации между сетями. MAC-адрес — физический, для передачи внутри одной сети.

Когда хост хочет отправить пакет соседу в той же подсети, ему нужно знать MAC этого соседа. IP-адрес он знает (например, из DNS), а MAC — нет. ARP (Address Resolution Protocol) решает эту задачу.

### Как работает

![Схема в материале «Фундамент 8 (Дополнительно): MAC, ARP, VLAN»: Хост A (192.168.1.10)                    Хост B (192.168.1.20)](https://offers.prostodevops.ru/diagrams/extras/seti/fundament-8-dopolnitel-no-mac-arp-vlan-1.png)Схема в материале «Фундамент 8 (Дополнительно): MAC, ARP, VLAN»: Хост A (192.168.1.10) Хост B (192.168.1.20)

ARP Request — broadcast, его видят все в сегменте. ARP Reply — unicast, только отправителю запроса.

### ARP-кэш

Чтобы не слать ARP-запросы на каждый пакет, хосты кэшируют соответствия IP→MAC.

Состояния:

- **REACHABLE** — недавно подтверждён, используется
- **STALE** — давно не проверялся, при следующем использовании будет проверка
- **DELAY** — ждём подтверждения
- **PROBE** — активно проверяем
- **FAILED** — не удалось получить MAC
- **PERMANENT** — статическая запись

### ARP и шлюз

Когда хост отправляет пакет в другую сеть (например, в интернет), он не делает ARP для конечного адреса. Он делает ARP для шлюза (default gateway) и отправляет пакет ему. Шлюз уже разбирается дальше.

codecopy

```
Хост 192.168.1.10 хочет достучаться до 8.8.8.8 1. 8.8.8.8 не в моей подсети (192.168.1.0/24)2. Значит, отправляю через шлюз 192.168.1.13. ARP: "Какой MAC у 192.168.1.1?"4. Получаю MAC шлюза5. Отправляю Ethernet-фрейм:   - src MAC: мой   - dst MAC: MAC шлюза   - src IP: 192.168.1.10   - dst IP: 8.8.8.8
```

IP-адреса не меняются, а MAC меняется на каждом хопе.

### Gratuitous ARP

"Незапрошенный" ARP — хост сам объявляет свой IP→MAC, не дожидаясь запроса.

Используется:

- При загрузке — "Привет, я 192.168.1.10, вот мой MAC"
- При смене IP — обновить кэши соседей
- Для обнаружения конфликтов — если кто-то ответит, значит IP занят
- При failover (VRRP/HSRP) — виртуальный IP переехал на другой роутер

## 4. VLAN: виртуальные сети

### Что это

VLAN (Virtual LAN) — логическое разделение одной физической сети на несколько изолированных сегментов.

Без VLAN: все устройства, подключённые к свитчу, в одном broadcast-домене. Broadcast от одного видят все.

С VLAN: устройства в разных VLAN изолированы. Broadcast из VLAN 10 не попадёт в VLAN 20, даже если они на одном свитче.

codecopy

```
        [Свитч]       /   |   \| --- | --- |     PC1   PC2   PC3  VLAN10 VLAN20 VLAN10 PC1 и PC3 видят друг друга (VLAN 10)PC2 изолирован (VLAN 20)PC1 и PC2 не могут общаться напрямую
```

### Зачем нужны VLAN

**Безопасность.** Изоляция отделов: бухгалтерия не видит трафик разработки. Гостевой Wi-Fi отделён от корпоративной сети.

**Производительность.** Меньше broadcast-домен — меньше мусорного трафика. ARP-запросы не flood'ят всю сеть.

**Гибкость.** Логическая структура не зависит от физической. Можно переместить сотрудника в другой офис, а он останется в своём VLAN.

**Упрощение управления.** Политики применяются к VLAN, а не к отдельным портам.

### Как работает

Свитч помечает каждый порт номером VLAN (1-4094). Фреймы передаются только между портами одного VLAN.

**Access port** — порт принадлежит одному VLAN. Подключённое устройство не знает про VLAN, свитч сам добавляет/убирает метку.

**Trunk port** — порт передаёт трафик нескольких VLAN. Используется между свитчами и к серверам, которым нужен доступ к нескольким VLAN.

### 802.1Q — стандарт VLAN-тегирования

На trunk-портах в Ethernet-фрейм добавляется 4-байтовый тег:

![Структура 802.1Q Ethernet-кадра](https://offers.prostodevops.ru/diagrams/network/ethernet-frame.png)Структура 802.1Q Ethernet-кадра

VLAN ID — 12 бит, значения 1-4094 (0 и 4095 зарезервированы).

## Что запомнить

1. **MAC — физический адрес интерфейса.** 6 байт, первые 3 — производитель. Broadcast: FF:FF:FF:FF:FF:FF
    
2. **ARP связывает IP и MAC.** Request — broadcast, Reply — unicast. Кэш хранит соответствия
    
3. **ARP только для локальной сети.** Для внешних адресов ARP делается на шлюз
    
4. **VLAN изолирует трафик логически.** Access port — один VLAN, Trunk — несколько с тегами 802.1Q
    
5. **Между VLAN нужен роутер.** Router-on-a-stick или L3 switch
