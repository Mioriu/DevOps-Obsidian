# Маршрутизация

Маршрутизация — это правила, по которым система решает, куда отправить пакет. Без понимания маршрутизации ты не разберёшься, почему трафик идёт не туда.

## 1. Как работает маршрутизация

Когда приложение отправляет пакет, ядро смотрит в таблицу маршрутизации и решает: через какой интерфейс и на какой следующий узел (gateway) отправить пакет.

Таблица маршрутизации — это список правил вида:

Чтобы попасть в сеть X, отправляй пакеты через интерфейс Y на gateway Z

Посмотреть таблицу:

ip route

Вывод:

codecopy

```
default via 192.168.1.1 dev eth010.0.0.0/8 via 10.255.0.1 dev eth1172.16.0.0/16 dev eth1 scope link192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.100
```

Разберём каждую строку:

**`default via 192.168.1.1 dev eth0`** Маршрут по умолчанию. Если пакет не подходит ни под один другой маршрут — отправляй на 192.168.1.1 через eth0. Это выход в интернет.

**`10.0.0.0/8 via 10.255.0.1 dev eth1`** Всё, что идёт в сеть 10.0.0.0/8, отправляй на gateway 10.255.0.1 через eth1.

**`172.16.0.0/16 dev eth1 scope link`** Сеть 172.16.0.0/16 доступна напрямую через eth1, без gateway. `scope link` означает, что адреса в этой сети находятся в том же L2-сегменте.

**`192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.100`** Автоматически созданный маршрут для локальной сети интерфейса eth0. `proto kernel` — создан ядром при настройке интерфейса. `src 192.168.1.100` — какой IP использовать как source.

## 2. Gateway и default route

Gateway (шлюз) — это маршрутизатор, который знает, как добраться до других сетей. Когда твой сервер не знает, куда отправить пакет напрямую, он отправляет его на gateway.

Default route (маршрут по умолчанию) — куда отправлять пакеты, если не нашлось более специфичного маршрута. Обычно это путь в интернет.

default via 192.168.1.1 dev eth0

Это значит: "всё, что не знаю куда отправить — отправляй на 192.168.1.1".

### Несколько default routes

Может быть только один активный default route. Если добавишь второй, получишь ошибку или он заменит первый (в зависимости от команды).

Для более сложных сценариев (два провайдера, failover) используются policy-based routing и метрики маршрутов.

Метрика — приоритет маршрута. Меньше = приоритетнее:

bashcopy

```bash
ip route add default via 192.168.1.1 metric 100ip route add default via 192.168.2.1 metric 200
```

Будет использоваться первый. Если 192.168.1.1 станет недоступен — второй.

## 3. Маршрутизация между подсетями

Типичная задача: сервер с двумя интерфейсами должен маршрутизировать трафик между сетями.

Сеть A (10.0.1.0/24) --- [eth0: 10.0.1.1 | Сервер | eth1: 10.0.2.1] --- Сеть B (10.0.2.0/24)

Чтобы это работало, нужно:

1. **Включить IP forwarding**
    
2. **Убедиться, что файрвол разрешает FORWARD**
    
3. **На клиентах в обеих сетях должен быть маршрут через этот сервер**
    

Или этот сервер должен быть default gateway для обеих сетей.
