## Зачем это знать?

Ты подключаешься к сети — и он сразу получаешь IP, маску, шлюз, DNS. Кто их выдал? DHCP-сервер. Если DHCP не работает, устройства не получат настройки и не смогут работать в сети.

Другая ситуация: есть десять устройств, а провайдер выдал один IP-адрес. Как все устройства выходят в интернет? NAT на роутере транслирует внутренние адреса во внешний.

DHCP и NAT — базовые механизмы, без которых не работают ни домашние сети, ни корпоративные, ни облачные инфраструктуры.

## 1. DHCP: автоматическая настройка сети

### Что это

DHCP (Dynamic Host Configuration Protocol) — протокол, который **автоматически** выдаёт устройствам сетевые настройки:

- IP-адрес
- Маску подсети
- Адрес шлюза (default gateway)
- DNS-серверы
- И другие параметры (NTP, TFTP для PXE boot и т.д.)

### Как работает: DORA

Процесс получения адреса называется **DORA** — по первым буквам четырёх сообщений:

diagramcopy

```
Клиент                                    DHCP-сервер
(нет IP, только MAC)                      (например, 192.168.1.1)
        |                                        |
        |  1. DISCOVER (broadcast)               |
        |  "Есть тут DHCP-сервер?"               |
        |--------------------------------------->|
        |                                        |
        |  2. OFFER (broadcast или unicast)      |
        |  "Да, держи 192.168.1.50"              |
        |<---------------------------------------|
        |                                        |
        |  3. REQUEST (broadcast)                |
        |  "Беру 192.168.1.50"                   |
        |--------------------------------------->|
        |                                        |
        |  4. ACK (broadcast или unicast)        |
        |  "Подтверждаю, он твой на 24 часа"     |
        |<---------------------------------------|
        |                                        |

   Клиент настраивает интерфейс
```

**DISCOVER** — клиент шлёт broadcast (255.255.255.255), потому что ещё не знает ни своего IP, ни IP сервера. Источник: 0.0.0.0.

**OFFER** — сервер предлагает адрес из своего пула. Может быть несколько серверов, каждый пришлёт свой OFFER.

**REQUEST** — клиент выбирает одно предложение и запрашивает именно его. Broadcast, чтобы остальные серверы знали, что их предложение отклонено.

**ACK** — сервер подтверждает. Клиент получает адрес и время аренды (lease time).

### Аренда (Lease)

IP выдаётся не навсегда, а на время — lease time. Типичные значения: 1 час, 8 часов, 24 часа.

Когда проходит половина lease time, клиент пытается продлить аренду (DHCP Request напрямую серверу). Если сервер подтвердит — аренда продлена. Если сервер недоступен, клиент попробует ещё раз на 87.5% времени. Если не получилось — при истечении аренды клиент должен освободить IP и начать DORA заново.

### DHCP Relay

DHCP использует broadcast, а broadcast не проходит через роутеры. Как быть, если DHCP-сервер в другой подсети?

DHCP Relay (или IP Helper) — роутер ловит DHCP broadcast в своей сети и пересылает unicast'ом на DHCP-сервер в другой сети. Ответ идёт обратно тем же путём.

### Где живёт DHCP-сервер

- Домашняя сеть — на роутере
- Офис — на выделенном сервере или контроллере домена (Windows DHCP, ISC DHCP, dnsmasq)
- Облако — управляемый сервис (AWS DHCP options set, и т.д.)
- Kubernetes — обычно не DHCP, а статическое назначение через CNI

## 2. NAT: трансляция адресов

### Что это

NAT (Network Address Translation) — механизм изменения IP-адресов в пакетах при прохождении через роутер.

Главная задача: позволить устройствам с приватными IP (192.168.x.x, 10.x.x.x) выходить в интернет через один или несколько публичных IP.

### Почему NAT нужен

IPv4-адресов всего ~4.3 миллиарда. На планете больше устройств. Без NAT адресов не хватило бы уже в 90-х.

Приватные диапазоны (RFC 1918):

- 10.0.0.0/8 — 16 млн адресов
- 172.16.0.0/12 — 1 млн адресов
- 192.168.0.0/16 — 65 тысяч адресов

Эти адреса не маршрутизируются в интернете. Каждая организация может использовать их внутри своей сети, и они не конфликтуют.

### Типы NAT

**SNAT (Source NAT)** — меняет адрес источника. Используется для выхода из приватной сети в интернет.

diagramcopy

```
Внутренний хост              NAT-роутер                  Интернет
192.168.1.50:54321  →   подменяет на    →    203.0.113.1:32456  →  example.com:443
                        публичный IP
```

**DNAT (Destination NAT)** — меняет адрес назначения. Используется для проброса портов внутрь сети.

diagramcopy

```
Интернет                    NAT-роутер                  Внутренний сервер
client:* → 203.0.113.1:80   подменяет на   →    192.168.1.10:80
                            внутренний IP
```

**PAT (Port Address Translation) / NAPT / Masquerade** — SNAT с трансляцией портов. Много внутренних адресов транслируются в один внешний, различаются по портам. Это то, что делает твой домашний роутер.

### Как работает PAT (Masquerade)

diagramcopy

```
Хост A: 192.168.1.50:54321 → example.com:443
Хост B: 192.168.1.51:54321 → example.com:443

NAT-таблица на роутере:
192.168.1.50:54321 ↔ 203.0.113.1:40001
192.168.1.51:54321 ↔ 203.0.113.1:40002

Исходящие пакеты:
A: src 203.0.113.1:40001 → dst example.com:443
B: src 203.0.113.1:40002 → dst example.com:443

Входящие пакеты (ответы):
example.com:443 → 203.0.113.1:40001 → роутер смотрит в таблицу → 192.168.1.50:54321
example.com:443 → 203.0.113.1:40002 → роутер смотрит в таблицу → 192.168.1.51:54321
```

Роутер запоминает соответствие (внутренний IP:порт ↔ внешний IP:порт) и использует его для обратной трансляции.

### NAT и входящие соединения

NAT ломает модель "любой хост может подключиться к любому". Если хост за NAT, к нему нельзя подключиться снаружи напрямую — у него нет публичного адреса.

Решения:

**Port Forwarding (DNAT)** — настроить на роутере: "всё, что приходит на порт 8080, отправляй на 192.168.1.10:80".

**UPnP/NAT-PMP** — приложение автоматически просит роутер пробросить порт. Работает для игр, торрентов. Небезопасно, часто отключают.

**NAT Traversal (STUN/TURN/ICE)** — техники для установления соединений между двумя хостами за NAT. Используются в WebRTC, VoIP.

### NAT в Linux (iptables/nftables)

bashcopy

```bash
# Включить IP forwardingecho 1 > /proc/sys/net/ipv4/ip_forward # SNAT/Masquerade — выход в интернет через eth0iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE # DNAT — проброс порта 8080 внутрь на 192.168.1.10:80iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 8080 -j DNAT --to-destination 192.168.1.10:80 # Посмотреть NAT-таблицу (активные соединения)cat /proc/net/nf_conntrack# илиconntrack -L
```

Типичная архитектура: веб-серверы в публичной подсети (с публичными IP), базы данных и бэкенды в приватной подсети (выходят через NAT Gateway).

## 3. Проблемы и решения

### Проблема 1: Устройство не получает IP

Симптомы:

- IP-адрес 169.254.x.x (link-local, самоназначенный)
- Или 0.0.0.0
- Сеть недоступна

Причины:

- DHCP-сервер не работает → проверить сервер
- Нет сетевого подключения (кабель, Wi-Fi) → физический уровень
- DHCP-пул исчерпан → расширить пул или уменьшить lease time
- Файрвол блокирует DHCP → проверить правила
- VLAN mismatch → проверить настройки VLAN

### Проблема 2: Конфликт IP-адресов

Симптомы:

- Периодические потери связи
- "IP address conflict detected"
- ARP показывает разные MAC для одного IP

Причины:

- Кто-то настроил статический IP из DHCP-пула → зарезервировать адрес или вынести статику за пределы пула
- Два DHCP-сервера в сети → найти и отключить лишний

### Проблема 3: NAT — кончились порты

Симптомы:

- Новые соединения не устанавливаются
- Ошибки "cannot assign requested address" или таймауты
- В conntrack много записей

Решения:

- Уменьшить таймауты в conntrack
- Добавить больше публичных IP для NAT
- Использовать connection pooling в приложениях

## 4. DHCP и NAT вместе

Типичная сеть:

diagramcopy

```
Интернет (публичные IP)
        |
   [Роутер]
   - WAN: 203.0.113.1 (от провайдера, часто тоже через DHCP)
   - LAN: 192.168.1.1
   - DHCP-сервер: выдаёт 192.168.1.50-192.168.1.200
   - NAT: транслирует 192.168.1.0/24 → 203.0.113.1
        |
   [Свитч]
    /   |   \
| --- | --- |

  PC1  PC2  PC3
  .50  .51  .52
```

1. PC1 включается, шлёт DHCP Discover
2. Роутер отвечает: "Твой IP 192.168.1.50, шлюз 192.168.1.1, DNS 8.8.8.8"
3. PC1 открывает google.com
4. Пакет идёт на 192.168.1.1 (шлюз)
5. Роутер делает NAT: src 192.168.1.50:54321 → src 203.0.113.1:40001
6. Пакет уходит в интернет
7. Ответ приходит на 203.0.113.1:40001
8. Роутер делает обратный NAT: dst 203.0.113.1:40001 → dst 192.168.1.50:54321
9. PC1 получает ответ

## Что запомнить

1. **DHCP выдаёт IP автоматически.** Процесс DORA: Discover → Offer → Request → Ack
    
2. **DHCP использует broadcast** — не проходит через роутеры без Relay
    
3. **NAT транслирует адреса.** SNAT — для выхода наружу, DNAT — для проброса внутрь
    
4. **PAT/Masquerade** — много внутренних IP через один внешний, различаются портами
    
5. **За NAT нельзя подключиться снаружи** без проброса портов или NAT traversal
    
6. **conntrack хранит NAT-соединения** — может кончиться при высокой нагрузке
